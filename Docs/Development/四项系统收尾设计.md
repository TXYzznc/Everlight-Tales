# 四项系统收尾设计（待确认）

> 范围：界面清单数据缺口 + 系统缺口中剩余的四项。本文是**设计方案**，待用户确认后再逐项实现。
> 顺序：① 多存档位 → ② 升级弹窗 → ③ 形态切换（D-060）→ ④ 来客区/服务区。

## 0. 总原则

1. 遵循已确认的设计决定，**不新增经营数值/好感/等级/货币**（D-323、07-家园、00-系统清单、24-材料、02-修复展一致）。
2. 分层按 b01 D-089 五层布局：逻辑落 Meta/Board/Data（零引擎可探针），UI 表现落 Everlight.Tales.UI。
3. 每项实现后走无头编译验证（RebuildAllContracts，exit 0 + 无 `error CS`），并更新界面清单状态列。

## 1. 多存档位

### 现状
- `WorldSession` 用 PlayerPrefs 单存档：16 个 `et.world.*` 键（day/period/repairFee/batch/tutorial/owned/known/materials/blueprints/forms/currentForms/tasks/display/jobs/tutorialStage），`Save()`/`Restore()`/`HasSave()` 直接读写全局键，无 slot 概念。
- 无标题页：`MainPageShell` 打开即 `LoadOrNew(seed)` 自动读（有档继续、无档新档）。
- `Meta/SaveService` + `Meta/WorldSaveService`（world.json 文件）是 b22/b24 验证过的完整 DTO 往返，但**实际运行链是 PlayerPrefs 最简存档**（b43），两条链并存未统一。

### 目标
支持 N 个存档位，玩家可在进入游戏前选择「继续 / 新建 / 删除」某个存档位。

### 方案
1. **载体沿用 PlayerPrefs**（实际运行链），键加 slot 后缀：`et.world.{slot}.day` 等 16 键。新增 `et.world.{slot}.meta` 存摘要（保存时间戳 + 显示用昵称）。
2. **WorldSession 加 `Slot` 字段**（当前槽位），`Save()/Restore()/HasSave()` 全部带 slot；`LoadOrNew(seed, slot)` 增加重载（缺省 slot=1 兼容现有调用）。
3. **新增存档服务** `Meta/SaveSlotService`（仅引 Data + UnityEngine 的 PlayerPrefs，或按 Meta 约定只引 Data 时把 PlayerPrefs 封装进 UI 层调用——见待确认 D3）：
   - `ListSlots()` → 每个 slot 的摘要（第 N 天 · 时段 · 维修费 · 保存时间戳）。
   - `HasSlot(slot)` / `DeleteSlot(slot)`。
4. **标题页 UIForm**：`SaveSlotPage`（新建，契约驱动 + UITable 登记 `UIViews.SaveSlotPage`），列出各 slot 卡片（空位显示「新档」，有档显示摘要），点击 = 继续/新建，卡片角标 = 删除。
5. **启动链调整**：`MainPageShell` 不再直接 `LoadOrNew`，改在标题页选档后 `LoadOrNew(seed, slot)`。

### 验收
- 3 个 slot 可分别新建/继续/删除，互不串档。
- 删除后该 slot 回到空位，其他 slot 不受影响。
- 老档（slot=1 缺省）无需迁移即可继续。

### 待确认决策
| # | 决策 | 选项（推荐置前） |
|---|---|---|
| D1 | 选档入口 | ① 独立标题页 `SaveSlotPage`（进游戏前，**推荐**）；② MainPageShell 内「存档管理」面板（进游戏后切换） |
| D2 | 存档位数量 | ① 3 个（**推荐**）；② 其他数量 |
| D3 | 存档载体 | ① PlayerPrefs 加 slot 后缀（最小改动，**推荐**）；② 迁到 `SaveService` 文件完整 DTO（更规范，但要把运行链从 PlayerPrefs 切到文件） |

## 2. 升级弹窗

### 现状
- 解锁链路分散，均静默（或与领取弹窗混在一起）：
  - 教学：`TutorialService.CompleteStage` 解锁 P-001~P-003。
  - 回访：`RevisitService.Deliver` 发图样 + 材料。
  - 领奖：`TaskService.Claim` 发图样（`JournalPanel.ClaimTask` 已弹「领取成功」含图样明细）。
  - 形态：`FormService.Unlock` 解锁形态（`WorkbenchPanel` 已弹加工成功）。
- 无统一的「解锁投放」反馈。设计文档明确「同阶段列表是可陆续遇到的内容，不是升级弹窗里一次发完的礼包」（03-解锁投放），即**单件解锁反馈，非批量礼包**。

### 目标
玩家首次获得新零件/图样/形态时，有明确、不重复的解锁反馈。

### 方案
1. **定义「解锁事件」**（UI 层统一入口）：`GlobalUI.ShowUnlock(title, content)`，复用 `GlobalUI.ShowDialog` 包装，样式区分（标题带「解锁」前缀）。
2. **触发点接线**（各解锁操作成功后）：
   - 教学段完成 → `ShowUnlock("解锁新零件", "惯性撞锤")`（`TutorialService.StagePart(stageIndex)` 取件名）。
   - 回访交付 → `ShowUnlock("获得图样", "M-012 借力改道夹")`（在 `RevisitCase` 成功分支）。
   - 领奖 → 现有「领取成功」弹窗内容追加一行「已获得图样：xxx」，**不再单独弹解锁**（避免双弹窗）。
   - 形态加工 → 现有「加工成功」弹窗追加「形态：xxx 已解锁」。
3. **边界**：只对「首次获得」触发（图样幂等 `GrantBlueprint` 已保证不重复入库，弹窗跟随首次成功）；重复领奖/重复加工走 `AlreadyUnlocked` 不弹。

### 验收
- 教学解锁零件、回访发图样时各弹一次「解锁」反馈。
- 领奖/加工的解锁信息合并进现有弹窗，不出现连续两次弹窗。

### 待确认决策

| D4 | 触发点范围 | ① 教学零件 + 回访图样 + 领奖图样 + 形态加工 全接（**推荐**）；② 仅回访/领奖（教学段已有引导弹窗，可跳过） |
| D5 | 与「领取成功」弹窗关系 | ① 合并：领奖/加工信息追加进现有弹窗，教学/回访单独弹（**推荐**）；② 全部单独弹「解锁」弹窗 |

## 3. 形态切换（D-060）

### 现状
- `Meta/FormService` 已做：解锁/切换/`ResolveForm(tempOverride)`（临时切换只影响本关、不改 CurrentForms）。
- `UI/WorkbenchPanel` 已做永久切换 UI（形态卡 解锁/切换）。
- **D-060 形态行为（Board 层）未实现**：试机以基础形态可玩（b29）。
- 盘面零件卡（`BoardPage.BuildPartDetail`）**无临时切换 UI**。

### 目标
实现四种形态的 Board 层行为 + 盘面零件卡临时切换，让「形态」真正影响盘面演算。

### 方案（分 A 行为 + B 切换 UI 两部分）

#### A. Board 层形态行为（规则已确认 D-060）
新增 Board 层 `FormAbility`（按 `FormConfig.Id` 分派），在 `PartAbility` 触发链路里按当前形态走不同行为。四种规则：

| 形态 | 触发条件 | 行为 | 能量/计分 |
|---|---|---|---|
| P-001-F01 贯通撞锤 | 被实体撞击（入射方向 d） | 推移 d 方向相邻格的输出侧对象 1 格；来撞件留在停止格；只推移选中对象、不隐式推进整排 | 2/2 费 1；触发 4 + 每格 8 |
| P-001-F02 横推撞锤 | 被实体撞击（入射方向 d） | 推移 (d+1)、(d−1) 两相邻对象各 1 格（模 6）；缺一路照常；两路按 d+1→d−1 顺序入 FIFO，目标已离开/不存在则取消 | 2/2 两路合计费 1；触发 4 + 每路每格 8 |
| P-003-F01 轴向线圈 | 受触发（碰撞/冲击） | 沿 D0、D3 各发最长 2 格射线，命中首个实体即停（拒收也遮挡）；发强度 1 冲击；随后移除本体 | 1/1 费 1；触发 6 + 每命中 6 |
| P-003-F02 定时线圈 | 受触发 | 首次有效触发支付 1 → 待爆（到期拍=当前拍+1）；待爆再触发只加触发分；到期拍在扣额度后、基础下落前于实时位置六邻格爆破（发冲击），爆破后移除本体；换轮不重置到期拍（连续拍序号） | 1/1 费 1；触发 6 + 爆破每命中 6；启动时 0 效果分 |

**关键实现点：**
- 撞锤两形态沿用现有「碰撞带入射方向」链路（`PartTriggerEvent` 已带入射方向，b08），贯通/横推改写 `PartAbility` 撞锤分支的推移目标选择。
- 轴向线圈复用现有冲击射线能力（P-011 飞轮已有射线参考）；定时线圈新增 `BoardEntity` 待爆状态字段（`FuseDueTap`）+ 到期结算在 `TapSettlement` 扣额度后、基础下落前插入「到期爆破」队列（b06 结算顺序已有 `dueEffects`/`tapEndEffects` 扩展点）。
- 待爆状态随轮存档（`RepairAttemptSave`）持久化：记录实体 ID、形态、能量、待爆状态、到期拍、当前拍序号。

#### B. 盘面零件卡临时切换 UI
- `BoardPage.BuildPartDetail`（零件种类卡）为「已拥有且有形态宿主」的零件加「形态」行 + 切换按钮。
- 点击切换 → 弹形态选择（基础形态 + 该宿主已解锁形态），选中后写入本关 `tempOverride`（`ResolveForm` 已支持，只影响本关、不改 CurrentForms）。
- 形态在准备页/盘面固定后，本关结算用 `ResolveForm` 取实际形态。

### 验收
- 四形态行为无头探针：贯通（输出侧推移、来撞件不动）、横推（两路推移、缺一路）、轴向（D0/D3 射线越过空格命中、命中首实体即停）、定时（本拍启动下拍爆破、待爆可搬位、末拍不追加）各通过。
- 盘面零件卡可临时切换形态，切换后本关演算按该形态执行，退出本关不影响 CurrentForms。

### 待确认决策
| # | 决策 | 选项（推荐置前） |
|---|---|---|
| D6 | 实现顺序 | ① 四形态一次做完（行为 + 切换 UI 一票，**推荐**）；② 先撞锤两形态（贯通/横推）再线圈两形态 |
| D7 | 临时切换交互 | ① 零件卡内「形态」行 + 切换按钮 + 弹形态选择（**推荐**）；② 单独形态切换面板 |

## 4. 来客区/服务区

### 现状
- `HomePanel` 五区中的「来客」「服务」是只读占位文本（b28）。
- 设计文档**多处明确首版不经营客流、不新增经营数值**（07-家园「第一版只保留加工台/资料台/陈列档案区，不经营客流、不计算好感」；00-系统清单「不新增等级、好感度或经营数值」；24-材料「首版不能买材料」；D-323）。
- 但 15-地图供给明确「上午接待到店来客、领取怪谈感谢、接收当天普通委托」「修理铺含到店普通单与感谢」。

### 目标
把来客/服务两区从「占位」升级为「轻量入口」，承载**委托接收 + 感谢领取**，但**不做客流/好感/经营数值系统**。

### 方案
1. **来客区（zone 0）** = 当天到店内容清单（只读 + 领取）：
   - 「沈遥感谢」卡片：上午可领（`RevisitCase` 入口），已领/非上午显示状态。
   - 「当天普通委托」卡片：列出 `WorldSession.Supply` 中 `PlaceId=="home"` 的普通供给，点击跳地图或就地开始（见 D9）。
   - 改装支线（TASK-MOD）入口卡片：`JournalPanel` 任务页已有，这里放快捷入口。
2. **服务区（zone 4）** = 服务/快捷入口（非经营）：
   - 选项 A：合并到加工区（加工/配装/资料/收藏已在其他区，服务区仅保留「配装 + 恢复面板」快捷入口）。
   - 选项 B：独立展示「配装（携带选择）+ 恢复面板（继续/放弃尝试）+ 设置」入口。
3. **逻辑落 Meta**：新增 `Meta/GuestBoardService`（或复用现有 `SupplyService`/`TaskService`）产出「来客清单」视图模型；感谢领取复用 `RevisitService.Deliver`；委托接收复用现有任务/供给链路。
4. **UI 落 UI**：`HomePanel` 把两个占位文本替换为程序化面板（`GuestPanel`/`ServicePanel`，或复用 `JournalPanel` 事件页/任务页）。

### 验收
- 来客区显示当天到店内容（感谢 + 普通委托 + 支线入口），感谢可领取，委托可开始/跳转。
- 服务区显示配装/恢复/设置入口，可正常跳转。
- 全程无客流/好感/经营数值。

### 待确认决策
| # | 决策 | 选项（推荐置前） |
|---|---|---|
| D8 | 首版范围 | ① 轻量入口（委托接收 + 感谢领取，不做经营数值，**推荐**）；② 保持只读占位（彻底留内容批）；③ 完整经营系统（与 D-323 冲突，不建议） |
| D9 | 来客区委托交互 | ① 来客区卡片只展示 + 点「去处理」跳到地图对应地点（复用地图事件卡，**推荐**）；② 来客区就地直接开始事件（跳过地图） |
| D10 | 服务区内容 | ① 快捷入口集（配装 + 恢复 + 设置，**推荐**）；② 合并进加工区，服务区移除或改用途 |
