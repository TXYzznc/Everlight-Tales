# GF 表单与 UI 代码规范

## GF UIForm

- 页面通过 GF UIComponent/UI 服务打开与关闭，资源路径、UIGroup、优先级、Pause Covered Form 和 Allow Escape 由项目 UI 配置定义。
- 新独立页面可使用 GF 工具生成脚手架，但生成后必须替换为项目约定的 Form 基类、命名空间和生命周期实现，再注册配置。
- 已有页面不得因重新生成脚手架而创建同名脚本、重复 UIForm 或重复配置。
- Overlay 是所属页面的子节点时，不新增独立 UIForm、UIViews 枚举或重复资源注册。

## 脚本职责

- Form 负责生命周期、控件绑定、显示映射、局部导航和向业务提交意图。
- Presenter/Controller/ViewModel（按项目模式选择）负责把领域状态转换为 UI 可读数据；Form 不承担业务结算。
- 业务服务不得直接查找、修改或创建具体 UI 节点；通过 UI 事件、数据快照或明确定义的显示接口通信。
- SerializeField 使用 camelCase 且与节点语义对应；避免字符串查找，旧页面过渡时才允许受控兜底。

## 生命周期与数据

- `OnInit`：缓存静态控件与注册本地事件。
- `OnOpen`：读取参数、订阅本页面所需数据、初始化焦点与显示。
- `OnCover/OnPause`：停止可见交互与页面专属表现，不丢失可恢复状态。
- `OnResume`：刷新可能已失效的数据和焦点。
- `OnClose/OnRecycle`：取消订阅、取消请求、归还 Item、清空临时引用；不得留下回调。
- 所有异步回调在写 UI 前校验 Form 仍打开、请求版本仍匹配、对象未销毁。

## 参数与事件

- 开页参数必须有明确类型、默认值和缺失处理；不通过全局静态变量偷传页面状态。
- UI 事件只表达用户意图，不直接修改跨模块业务数据。
- 列表刷新优先增量更新和对象池；禁止每次数据变化整页 Destroy/Instantiate。
- 禁止在 `Update` 轮询数据或分配 GC；需要刷新时由事件、定时器或显式生命周期触发。
