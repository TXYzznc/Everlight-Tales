# GF UI 设计与制作全流程规范

> 适用范围：以 Game Framework / GF_X 为 UI 框架基础、采用 Unity UGUI 与 TextMeshPro 的项目。
>
> 不适用：UI Toolkit、IMGUI、网页 UI、非 GF 的页面管理框架。项目策划、品牌、美术风格和具体数值不属于本规范。

## 使用顺序

1. 先读 [01-界面设计与交互规范.md](./01-界面设计与交互规范.md)，确认信息、状态和可访问性。
2. 美术按 [02-UI美术资源与交付规范.md](./02-UI美术资源与交付规范.md) 输出可导入资源。
3. 先写 `prefab-layout.md`，并按 [03-Prefab与RectTransform规范.md](./03-Prefab与RectTransform规范.md) 建立结构。
4. 再依 [04-GF表单与UI代码规范.md](./04-GF表单与UI代码规范.md) 接入 GF UIForm 和业务脚本。
5. 使用 [05-输入与界面生命周期规范.md](./05-输入与界面生命周期规范.md) 处理输入、打开、关闭和异步时序。
6. 按 [06-适配可访问性与性能规范.md](./06-适配可访问性与性能规范.md) 做适配、可读性与性能检查。
7. 交付前执行 [07-测试与验收清单.md](./07-测试与验收清单.md)。新项目先复制 [08-项目接入模板.md](./08-项目接入模板.md) 并填写项目差异。

## 当前项目阶段性覆盖（AutoEra）

- 当前第一版 UI 的 AI 制作与验收只以 `1920×1080` 为强制分辨率基准。
- `16:10`、`21:9` 及其他比例的最终适配、截图和验收暂由用户手动处理，不作为 AI 任务、OpenSpec 或交付完成门；除非用户后续明确重新启用。
- AI 仍应使用合理锚点、CanvasScaler、Layout Group 和安全边距，不得主动写死会妨碍后续适配的屏幕坐标；这属于结构卫生要求，不要求额外比例取证。
- 本节作为当前产品约束，优先于下列通用规范及既有页面文档中的多比例验收表述。

## 强制原则

- 策划需求、视觉设计、Prefab 结构、代码绑定和验收证据是不同层，不得互相取代。
- 页面结构先于美术拼装，素材切分先于 Prefab 绑定，Prefab 完成先于业务绑定。
- 一个独立 GF 页面对应一个 UIForm Prefab；不以无实际复用价值的“专属组件子 Prefab”包装整页内容。
- 所有输入通过项目 InputModule；UI 业务不得直接轮询 `Input` 或设备。
- 运行时不得动态拼装正式页面层级；仅允许实例化预制好的列表 Item。
- UI 在任何分辨率、语言、交互状态下都不能依赖“恰好是当前设计稿尺寸”才能正确显示。

## 规范优先级

1. 项目当前的策划与产品约束。
2. 本规范。
3. 项目接入模板中经过明确确认的差异。
4. 某个页面的 `prefab-layout.md`、视觉稿和实现任务。

任何下层文件与上层冲突时，先修正文档或申请明确决策，不以代码现状默默覆盖规范。
