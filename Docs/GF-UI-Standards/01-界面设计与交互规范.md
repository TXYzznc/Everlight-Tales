# 界面设计与交互规范

## 设计输入与输出

每个页面开始前必须具备：目标用户、使用场景、页面入口/出口、信息字段、操作、异常状态、权限或阶段限制。输出至少包括信息架构、状态表、`prefab-layout.md` 和美术需求。

## 信息层级

- 0.5 秒内可读：当前目标、危险、主操作、不可逆操作。
- 短暂停留可读：资源、状态、队友/对象摘要、下一步说明。
- 展开后可读：完整数值、历史、说明和低频设置。
- 同屏只保留一个视觉主操作；危险操作必须与普通操作在位置、颜色或确认流程上可区分。
- 不能以颜色作为唯一信息通道；状态必须同时使用文字、图标、形状或位置之一。

## 页面状态设计

每个交互对象都必须定义 `default`、`focused`、`pressed`、`disabled`、`loading`、`empty`、`error` 与成功反馈；不适用的状态必须明确说明原因。

- 禁用时说明不可用原因，不能只变灰。
- 异步提交必须防重复点击，并在成功、失败、取消、超时和页面关闭时统一收口。
- 删除、退出、覆盖、消耗等不可逆动作必须具备明确后果、确认方式和取消路径。
- 模态框一次只占用一个决策焦点；关闭后恢复触发它的控件焦点。

## 导航与焦点

- 鼠标、键盘与手柄均需可完成核心流程；焦点顺序跟随视觉阅读顺序。
- Esc/取消优先关闭最上层可关闭页面，不得越级退出游戏或关闭底层页面。
- 首次打开页面设置确定的默认焦点；关闭页面后恢复先前焦点。
- 禁止只依赖 hover 才能理解功能；手柄焦点需要清晰可见的描边、缩放或状态变化。

## 文案、本地化与数字

- 文案不烘焙到图片；所有可翻译文本由 TMP/本地化系统输出。
- 预留长文本空间，避免以固定英文宽度设计控件。
- 数字、日期、单位、百分比和快捷键由项目本地化规则格式化，不在业务代码中手拼。
- 不使用截图、颜色或布局暗示未实现功能。

## 页面规格最小表

| 项目 | 必填内容 |
|---|---|
| 页面目的 | 玩家/用户要完成的唯一主要任务 |
| 打开与关闭 | 入口、返回、Esc、异常退出 |
| 数据 | 来源、刷新时机、空值与加载态 |
| 操作 | 可用条件、提交、成功/失败/取消 |
| 状态 | 默认、禁用、加载、空、错误、危险 |
| 适配 | 全屏/HUD/模态、最小安全空间、长文本策略 |
| 验收 | 截图基准、交互路径、性能与无障碍检查 |
