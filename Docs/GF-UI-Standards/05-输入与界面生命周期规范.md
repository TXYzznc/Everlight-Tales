# 输入与界面生命周期规范

## 输入唯一入口

- 所有键盘、鼠标、手柄、触摸映射均经过项目 InputModule / 输入服务。
- Form、Item 和业务代码不得直接读取 `Input`、Input System device 或轮询按键。
- Button 点击是 UI 事件；键盘/手柄触发同一操作时必须汇聚到同一个意图处理函数。

## 输入优先级

1. 系统级阻断或不可关闭错误。
2. 顶层模态框。
3. 暂停、设置等全屏覆盖页。
4. 当前独立 UIForm。
5. 战斗/HUD 或场景输入。

顶层 UI 消费取消、确认、导航等输入后，底层不得再次响应。关闭顶层页面后才恢复下层输入。

## 打开与关闭时序

1. 校验页面状态与参数。
2. 由 GF 打开 Form，完成控件绑定和初始数据快照。
3. 设置焦点并开启允许的输入。
4. 提交异步/业务请求时锁定重复操作。
5. 关闭前取消未完成请求、关闭子 overlay、释放输入捕获。
6. Form 回收后取消订阅、清理 Item 与临时状态。

阶段切换、场景卸载、返回主菜单、断线或异常结束必须遵循相同关闭路径；不得让晚到回调重开已关闭页面或写入旧页面。

## 时间尺度

- UI 倒计时、动画和提示使用哪种时间尺度必须明确：暂停期间仍计时的 UI 用 unscaled time；与世界同步的表现用 scaled time。
- 页面暂停不等于世界暂停；由项目的游戏状态/流程服务决定模拟是否推进。
- 异步动画、延迟回调和对象池 Item 需携带页面/请求版本，避免复用后串写。
