# 适配、可访问性与性能规范

## 分辨率与安全区

- 通用项目建议验收 16:9、16:10、21:9，以及项目声明的最小/最大桌面分辨率。
- AutoEra 当前第一版的 AI 强制验收仅覆盖 `1920×1080`；其他比例由用户后续手动处理，不得因缺少其截图、适配或证据阻塞 AI 任务完成。
- 全屏遮罩必须铺满；HUD 贴合语义边缘；模态框居中；背景允许裁切但主要内容不得裁切。
- 使用锚点、CanvasScaler、Layout Group 和安全边距适配，不为每种分辨率复制 Prefab。
- 仍应保留合理锚点和布局边界，避免主动妨碍后续人工适配；当前不要求 AI 为其他比例调整、截图或出具验收证据。

## 可访问性

- 正文、按钮、状态文字与背景具备足够对比度；危险/成功不只依赖红绿。
- 文本大小、动态数字、图标尺寸和触控/手柄焦点区域应在项目目标距离清晰可读。
- 关键声音/震动反馈有视觉替代；关键视觉状态有文字或图标替代。
- 支持完整键盘/手柄导航；焦点、禁用、加载和错误状态明确。
- 动画避免强烈闪烁和无理由的持续运动；提供项目级减弱动态效果入口。

## 性能

- 静态 UI 尽量合批；不要为纯装饰节点增加不必要 Canvas。
- 列表、聊天、日志和背包使用对象池与虚拟化策略；大数据量不得一次实例化全部行。
- 避免 Layout Group 与 ContentSizeFitter 形成递归重建；动态布局更新应批量提交。
- 图像按显示尺寸导入，避免超大透明图、重复纹理和无意义的高精度资源。
- 高频刷新只更新变化字段；TMP 文本、字符串格式化和事件订阅不得在 Update 中产生持续 GC。
- 用 Profiler/Frame Debugger 检查 Canvas rebuild、UI draw call、GC alloc、布局重建和图片内存。
