# 界面清单与实现状态

> 用途：一份清单，两轨使用。
> - **程序侧**：按「待补界面」补齐预制体与脚本（逻辑已做的接表现，完全没做的从零做）。
> - **美术侧**：按「美术资源需求」逐界面出设计稿与 UI 资源。
>
> 依据：`02-系统设计/` 各流程文档（11 任务系统、16 维修准备、17 盘面奖励、18 单关结算、19 地图解锁、20 四时段、21 存档恢复、22 加工台、23 图鉴、07 家园、28 教学切片 等）。

## 0. 状态图例与承载方式

| 状态 | 含义 |
|---|---|
| ✅ 已实现 | 程序化可跑（脚本在 `Assets/Game/Scripts/EverlightTales/UI/`） |
| 🟡 逻辑有、表现缺 | 纯逻辑已实现并通过探针，玩家可见 UI 未做/未完整 |
| ❌ 完全未做 | 策划案明确提到，程序与表现均无 |

| 承载方式 | 说明 |
|---|---|
| 预制体 | 独立 UIForm，登记 `UITable.xlsx`，走 UIFormBase 生命周期（打开/关闭/分组/返回键） |
| 程序化 | 代码 `AddComponent` 构建，挂在宿主（MainPageShell 内容容器 / BoardPage / 对话框）下 |
| 待定 | 由程序实现时按是否需独立生命周期决定 |

当前预制体仅 3 个：`MainPageShell`（主页壳）、`BoardPage`（盘面）、`DialogView`（对话框）；其余均为程序化。

## 4. 美术侧需求（设计稿 + UI 资源）

程序补完界面后，按此逐界面出设计稿与 UI 资源。资源类型对齐 `11-美术规范/美术素材清单与资源目录.md`（UI/九宫格、控件、图标）。

### 4.1 界面级设计稿（每界面一稿）

- 城市地图主界面（含时段条/节点四态/跟踪卡片/等待按钮）
- 地点详情页 + 事件卡 + 事件详情页
- 任务系统三页（事件/任务/怪谈）+ 各类卡片 + 条目详情
- 准备页三段 + 携带选择两栏 + 关卡预览层
- 盘面局内（六区布局 + 零件卡弹窗 + 四选一弹窗 + 本轮小结）
- 结算面板（成功/失败/撤退四段）
- 家园五区（加工台/图鉴/档案/资料台/来客/服务 + 材料背包）
- 对话界面 + 现场调查
- 恢复面板 + 设置界面

### 4.2 通用 UI 资源（跨界面复用）

- 九宫格：面板（16px）/ 对话框（20px）/ 按钮（8px）/ 页签（8px）
- 控件：按钮（主/次/置灰）、页签、进度条、槽位、角标、滚动条、输入框
- 图标：事件类型（维修/处置/生活/调查/怪谈）、资源（材料×6、维修费、图样、定势残晶、异常纹样）、状态（可处理/进行中/未到时段/已错过/可领奖/已完成）、地图地点节点、跟踪/定位/等待
- 通用元素：顶部时段条、分数飘字、连击计数、提示 toast、加载/过渡

### 4.3 顺序建议

先做 **P0 一局闭环** 涉及的界面（准备页、四选一、结算、失败），再 **P1 地图信息层**，后 **P2 叙事层**，与程序补界面的优先级对齐。
