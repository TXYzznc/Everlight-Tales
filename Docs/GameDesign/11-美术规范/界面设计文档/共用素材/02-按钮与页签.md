> 本批交付：**10 项 / 源图 36 张**（4 个按钮族 × 4 态 = 16，图标按钮 4 态，3 个页签族 × 3 态 = 9，筛选片 3 态，一键补充 4 态）

## 1. 固定模块（每项提示词都要接在后面，逐字复用）

### A · UI 视觉语言

```
一款竖屏手机游戏的界面设计，2D 数字绘制，成熟的商业游戏 UI 完成度。
整体基调：深夜仍在营业的老式精密修理铺——黄铜工具的秩序感与门外未知之物的侵蚀感同处一框。
克制的低饱和深色底，靠局部暖光与冷光建立层次；不使用大面积高亮、不糖果色、不卡通描边，
不使用拟真照片贴图、玻璃拟态、霓虹赛博或扁平极简白底风格。
面板与控件用「薄金属板 + 蚀刻线 + 轻微内阴影」构成，边缘清晰、拐角圆润但克制（圆角半径小），
有实体感与触感，像一块被反复使用的工装面板。避免：厚塑料质感、浮雕过多、廉价渐变、立体投影过重。
```

### B · 色彩体系

```
以深色为绝对主体，具体色值：最底背景 #171A20，页面背景 #1E2229，
面板底 #262B34，卡片底与悬停 #2F3540，分隔线与描边 #3E4652，
主文本 #E8EAF0，次文本 #A8B0BC，弱文本与禁用 #6E7684。
强调色两支：暖铜 #E0A858（主按钮、高亮、当前选中、金属暖面），
冷紫 #A86AC8（怪谈、异常、待处理、警示性的神秘感）。
辅助功能色：工具青 #5A9EB8（次级强调、链接）、成功 #5AB878、危险 #D05A5A、警告 #D8A858。
暖铜与冷紫是画面唯一的两处「光」，其余全部压在深灰蓝的中低明度区间；
暖冷面积比大致 3:1，暖为主、冷为异。禁止大面积高饱和与多色并列竞争。
```

### C · 材质与光影

```
光源假定来自画面内的灯具与屏幕本身：左上偏暖的方向光，边缘有极轻微的冷紫反射光。
金属件强调转折面与窄亮反光带，不画照片级反射；布料与纸张用大面平涂加少量褶皱折线。
面板高光只在边缘 1~2px 处出现，形成薄金属收边；阴影短、硬、贴合结构，不做长投影与浓重 AO。
所有发光元素（指示灯、符文、异常侵蚀）用有限的光晕，光晕不超过元素自身尺寸的 1.5 倍。
整体干净、层次分明，从缩略图能读出分区，放大能看见刻线与铆钉的细节安排。
```

### D · 细节与统一性

```
统一全画面的圆角尺度、描边宽度（1~2px）、刻线间距与图标笔画粗细；
功能图标用统一线宽与统一圆角，风格一致，可成套使用；
同类控件在所有界面中保持同一种视觉语言，不因界面不同而改变造型。
焦点区域（主按钮、当前选中页签、提示信息）才允许更高对比与更精细的细节，
次要区域概括处理。不得让某一区域突然变成其他画风、摄影写实或手绘涂鸦。
```

neon cyberpunk, holographic, flat white minimalism, material design, iOS default style,

## 2. 本批的核心原则：**先出母版，再换色派生**

按钮族是「母版 + 派生」的典型。**最大的风险是让 AI 分别设计四个按钮**，
结果得到四种圆角、四种收边、四种厚度的「看起来差不多的按钮」——这是 UI 不统一的主要来源。

正确做法：

```
第 1 步  出「基础按钮形状」—— 只定义形状，不定义色彩语义
         （外形轮廓、圆角半径、收边宽度、内阴影、高光位置、刻线）
第 2 步  用同一个形状，只换色彩语义，派生 4 个变体：
         主按钮（暖铜实底） / 次按钮（深灰描边） / 危险按钮（低饱和红） / 一键补充（暖铜亮底）
第 3 步  每个变体各出 4 个交互状态（用 §3.2 的统一后缀表）
```

> **务必把第 1 步的「基础按钮形状」保留下来**，后面派生的所有按钮、以及全部 20 个界面文档里的按钮，
> 都以它为形状基准。若某个界面需要新按钮，先回来判断能否用换色解决。

### 九宫格约束

| 约束 | 说明 |
|---|---|
| 源图尺寸 | 大按钮 256×128，小按钮 256×64，页签 256×64，筛选片 128×64，图标按钮 128×128 |
| border | 一律 8（图标按钮 16，一键补充 12） |
| 中心与四边中段 | 必须是**低对比纯色**，被拉伸区域不得有图案或横向渐变 |
| 外扩 | **禁止向外投影/外发光**，拉伸后会变成沿边的平行色带 |
| 文字 | 不画。按钮上的文字由程序用 TMP 渲染，素材只是「空壳」 |

|---|---|
| 源图 | 256×128，透明背景 |

**提示词**

```
一个游戏 UI 按钮的通用外形底板，横向长方形，居中绘制，**只表现形状与结构，色彩按后续说明替换**。
外形：圆角矩形，圆角半径小（约 8px），上下左右对称。
结构：四边一圈 1px 的浅色收边线；收边线内侧距边 4px 处有一道极淡的内阴影形成厚度；

板面中央完全平整纯色，无图案、无横向渐变、无文字。
四个角在 border 8px 范围内干净收口，不向外投影。
```

### 3.2 统一状态后缀表（**四个按钮变体共用**）

出每个变体的 4 个状态时，把下表对应的一句追加在 §3.1 形状描述之后。
**形状与尺寸描述逐字不变，只按变体替换基础色。**

| 状态 | 追加句 |
|---|---|
| `normal` | 该变体的基础色按下方变体表填充，其余保持上述形状描述不变。 |
| `hover` | 与 normal **完全相同的形状与尺寸**；整体亮度提高约 10%，上缘高光线加宽到 2px，四边收边线提亮一档，板面左下角出现一小片极淡的暖色反光。 |
| `pressed` | 与 normal **完全相同的形状与尺寸**；整体亮度降低约 12%（暖铜面压到 #C88A3A），上缘高光线消失、上缘内侧改为内阴影，整块板像一个被按进去 1px 的键帽。 |
| `disabled` | 与 normal **完全相同的形状与尺寸**；整体去饱和，明度压到 #2A2E36 一带，收边线与高光线都降到几乎看不见，叠一层约 55% 不透明度的灰，文字位（中央空白区）保持干净。 |

> 出图时**务必一次把某个变体的 4 态连出**，不要跳着出——同一个变体的 4 态由同一次生成保证一致性最好。

> 行内按钮尺寸小，**细节必须比大按钮更概括**——不要在小按钮上堆铆钉、刻线、多重收边。
> 小尺寸下这些细节只会糊成脏点。这是本批最容易出错的一项。

### 3.3 页签族（SHR-026 / SHR-027 / SHR-028）

三个页签是**同一个形状的三个宽度版本**，必须一次出，保证同族。

| 编号 | 用途 | 宽度基准 | 文件名 |
|---|---|---|---|
| SHR-026 | 任务三页 / 加工台三页 / 图鉴三页 | 200×56（3 等分） | `shared_tab3_<状态>@256x64.png` |
| SHR-027 | 主页壳底部 4 页签 | 200×56（4 等分） | `shared_tab4_<状态>@256x64.png` |
| SHR-028 | 家园五区 | 190×56（5 等分） | `shared_tab5_<状态>@256x64.png` |

**共性规格**：源图 256×64，border 8，透明背景。

**提示词（三族共用）**

```
一个游戏 UI 的页签底板，横向长方形，居中绘制。外形与按钮同族但更扁更薄。
只画底板的**外缘轮廓**：左右两侧各一道 1px 的竖向分隔刻线（表示相邻页签之间的界），
上缘一道 1px 的窄亮高光线，板面平整。
因为页签是并排紧密排列的，**左右两侧不能在画布外留空隙**，分隔刻线要落在画布内边缘处，
使相邻两个页签拼接时刻线正好贴合。
不画文字、不画图标、不向外投影。
```

**状态后缀表**

| 状态 | 追加句 |
|---|---|
| `normal`（未选中） | 板面 `#1E2229`（与页面背景齐平，看起来「缩在里面」），上缘高光线极暗，左右分隔刻线为 `#3E4652`。 |
| `hover` | 与 normal 完全相同的形状与尺寸；板面提到 `#262B34`，上缘高光线提到纸白 `#E8EAF0` 的 60% 亮度，左右分隔刻线提亮。 |
| `active`（当前页） | 与 normal 完全相同的形状与尺寸；**板面换成暖铜 `#E0A858` 实底**，上缘高光线为 `#F0C888`，左右分隔刻线被暖铜盖住（消失），板面比 normal 略高（上缘上移 1px 的视觉暗示）。文字由程序渲染为 `#171A20` 深色。 |

> **`active` 态是本族的关键**：暖铜实底 + 深色文字。
> 页签的「选中」不是加个框，而是整块变成暖铜——这与本项目「暖铜 = 秩序/当前」的语义一致。

**SHR-027 额外状态 `badge`**：在 `active` 或 `normal` 底板的**右上角外侧**留一个 36×26 的干净空位（不加任何图形），
程序会在那里叠 `SHR-043 角标底座` 并填数字（如未处理事件数）。
→ 因此 SHR-027 需额外出一版 `shared_tab4_badge@256x64.png`：与 normal 相同，但右上角空位外的区域保持透明。

四边 1px 收边，板面平整。**造型要比按钮「轻」**——它是可选可取消的筛选条件，不是动作。

## 4. 出图批次建议

本批 36 张，是全部共用素材里最需要控质量的一批。建议分 **5 次**：

| 次序 | 内容 | 张数 | 说明 |
|---|---|---|---|
| 第 1 次 | §3.1 母版形状 | 1 | **只出形状，不定色**。挑最满意的保留为基准 |
| 第 2 次 | SHR-025 图标按钮 4 态 | 4 | 方形族先出，它被 15 个界面引用、复用面最广 |
| 第 3 次 | SHR-021 主按钮 4 态 + SHR-022 次按钮 4 态 | 8 | 带着母版一起喂，只换色 |

## 5. 本批验收要点

- [ ] **所有按钮共用同一个外形轮廓**——叠在一起看，圆角、收边宽度、高光位置、内阴影完全重合，只有颜色不同
- [ ] 四个按钮变体的**视觉权重排序清晰**：一键补充 > 主按钮 > 危险按钮 > 次按钮
- [ ] 主按钮「亮面」、次按钮「亮边」（hover 时次按钮是描边转青，不是板面变亮）——两者不要做成同一种强调方式
- [ ] 危险按钮是**低饱和**的工装红，不是鲜红
- [ ] 图标按钮中央 56×56 完全干净（要被功能图标覆盖，不能有底色花纹）
- [ ] 页签三族同族：3/4/5 页版本放在一起，形状、圆角、分隔刻线完全一致，只有宽度不同
- [ ] 页签 `active` 是暖铜实底；筛选片 `active` 是工具青实底——**两者不能撞色**
- [ ] 小按钮（行内）细节比大按钮更概括，没有出现糊成一团的铆钉与多重收边
- [ ] 每个多状态族的各态**画布尺寸与外轮廓逐像素一致**（切换时不跳变）
- [ ] 全部透明背景、无文字、无图标、无向外投影/发光
- [ ] 文件按变体+状态命名，放入 `Assets/Game/Sprites/UI/控件/`
