## 1. 固定模块（每个素材提示词都要接在后面，逐字复用）

### UI 视觉语言

```
一款竖屏手机游戏的界面设计，2D 数字绘制，成熟的商业游戏 UI 完成度。
整体基调：深夜仍在营业的老式精密修理铺——黄铜工具的秩序感与门外未知之物的侵蚀感同处一框。
克制的低饱和深色底，靠局部暖光与冷光建立层次；不使用大面积高亮、不糖果色、不卡通描边，
不使用拟真照片贴图、玻璃拟态、霓虹赛博或扁平极简白底风格。
面板与控件用「薄金属板 + 蚀刻线 + 轻微内阴影」构成，边缘清晰、拐角圆润但克制（圆角半径小），
有实体感与触感，像一块被反复使用的工装面板。避免：厚塑料质感、浮雕过多、廉价渐变、立体投影过重。
```

### 色彩体系

```
以深色为绝对主体，具体色值：最底背景 #171A20，页面背景 #1E2229，
面板底 #262B34，卡片底与悬停 #2F3540，分隔线与描边 #3E4652，
主文本 #E8EAF0，次文本 #A8B0BC，弱文本与禁用 #6E7684。
强调色两支：暖铜 #E0A858（主按钮、高亮、当前选中、金属暖面），
冷紫 #A86AC8（怪谈、异常、待处理、警示性的神秘感）。
辅助功能色：工具青 #5A9EB8（次级强调、链接）、成功 #5AB878、危险 #D05A5A、警告 #D8A858。
暖铜与冷紫是画面唯一的两处「光」，其余全部压在深灰蓝的中低明度区间；
暖冷面积比大致 3:1，暖为主、冷为异。禁止大面积高饱和与多色并列竞争。
```

### 材质与光影

```
光源假定来自画面内的灯具与屏幕本身：左上偏暖的方向光，边缘有极轻微的冷紫反射光。
金属件强调转折面与窄亮反光带，不画照片级反射；布料与纸张用大面平涂加少量褶皱折线。

所有发光元素（指示灯、符文、异常侵蚀）用有限的光晕，光晕不超过元素自身尺寸的 1.5 倍。
整体干净、层次分明，从缩略图能读出分区，放大能看见刻线与铆钉的细节安排。
```

### 细节与统一性

```

焦点区域（主按钮、当前选中页签、提示信息）才允许更高对比与更精细的细节，
次要区域概括处理。不得让某一区域突然变成其他画风、摄影写实或手绘涂鸦。

## 2. 本批硬性约束

### 2.1 结构与构图：同一个热点，四种状态

| 项目 | 规格 |
|---|---|
| 独立源图 | 每张 **256×256**，正方形，RGBA PNG，sRGB；一张只画一个状态 |
| 实际显示 | 热点根节点 **140×140**，场景中的位置由数据提供；圆环不包含场景物件 |
| 对齐 | 四张画布、中心、朝向、透明留白基准一致；中心为 `(127.5, 127.5)` |
| 母版主环 | 正面平视的正圆，中心线半径约 **108px**，环带总宽约 **8px**；主环直径约占画布 **84%** |
| pulse 变化 | 主环中心线半径约 **119px**，比 idle 外扩约 **10%**；画布与中心不变，不能放大整个画布再裁切 |
| pressed 变化 | 保留半径约 108px 的主环，在内部增加半径约 **82px**、宽约 **4px** 的同心扫描环 |
| 中央留白 | 主环内部保持透明；pressed 的扫描线以外也透明，不画填充圆盘或玻璃镜片 |
| 画布边缘 | 所有描边与微光完整收在画布内，四边至少保留约 **2px** 全透明像素；pulse 尤其不得切边 |
| 材质 | 轻薄的精密工装指示环；有限的蚀刻细节和窄亮收边，不画厚重金属框、铆钉阵列或繁复符文 |
| 独立节点 | 标签在热点下方，确认勾在右上方；四张环图都不绘制标签、底板、文字或勾 |

本批的布局约束来自已存在的热点模板，不另行设计页面布局。圆环是覆盖在场景上的提示标记，玩家应先看见线索物件，再看见标记；不能把热点画成一枚遮住物件的实心徽章。

### 2.2 冷紫 → 暖铜的状态语义与透明度

| 状态 | 语义 | 主色 | 环带主体 Alpha 目标 | 形状变化 |
|---|---|---|---|---|
| `idle` | 尚未确认的异常位置 | 冷紫 `#A86AC8` | 约 **0.35** | 基础单环 |
| `pulse` | 未确认热点的高亮相位 | 冷紫 `#A86AC8` | 约 **0.42**，比 idle 提升约 20% | 同心外扩约 10%，微光略增强 |
| `pressed` | 点击瞬间的扫描反馈 | 冷紫 `#A86AC8` | 主环约 **0.55**；内部扫描线不高于主环 | 基础主环 + 内部同心扫描环 |
| `confirmed` | 该线索已经确认 | 暖铜 `#E0A858` | 约 **0.55** | 回到基础主环尺寸，更稳定、完整 |

固定色彩模块定义的是整套 UI 风格；**本批单张状态图按本表分配主色**。未确认三态以冷紫为主，不为了满足全界面暖冷面积比而加入暖铜亮点；已确认环以暖铜为主，不改成成功绿圆环。

Alpha 数值是交付检查目标，不是要求生图模型精确输出某个通道值。主体可有窄幅明暗层次与抗锯齿边缘；画布边角、中心和非环区域应保持真实透明。对照深色和浅色背景检查，避免将半透明误画成实心灰色，或将棋盘格背景画进 PNG。

当前组件以白色 `Image.color` 显示资源，**颜色和基础透明度由 PNG 提供**。不要把彩色环再次统一乘冷紫或暖铜，也不要重复乘 0.35/0.55，使圆环变得过暗。

### 2.3 与现有 SpriteSwap 绑定的对应关系

| Unity 状态 / 行为 | 使用素材 | 说明 |
|---|---|---|
| Image 默认图 / Normal | `SCR-16-04-idle` | 尚未确认 |
| Highlighted | `SCR-16-04-pulse` | 当前用于悬停高亮 |
| Pressed | `SCR-16-06-pressed` | 按下反馈；必须含主环，不能只交一张额外叠加层 |
| Selected | 复用 `SCR-16-04-idle` | 不新增第五张选中图 |
| Disabled（确认后） | `SCR-16-05-confirmed` | 业务确认后禁止重复点击；此处 Disabled 表示“已确认”，不画成灰色禁用环 |
| 未确认时的呼吸 | 当前 Sprite 的透明度变化 | 现有代码周期约 **1.6s**，白色乘色 Alpha 约在 0.8～1.0 之间变化；不是 idle/pulse 两张图片自动轮播 |

`pulse` 仍按设计提供“呼吸高亮相位”形状，当前接入效果是悬停切图加透明度呼吸。若后续需要连续的两帧外扩动画，需要另外实现图片混合或动画；本批四张 PNG 本身不包含播放逻辑。

### 2.4 已确认勾与旧文档差异

旧版现场调查专属清单将已确认状态写成“暖铜实环 + 中心小勾”。当前模板已有独立的 `Img_Confirmed`：使用 `ICO-026已完成.png`，右上角 **28×28**，由代码在确认后显示。

**本批按当前接入结构交付：已确认 PNG 只画暖铜环，不把勾烘焙到中心。** 标签文字由 `Txt_Title` 提供；标签背景由 `LabelBackground` 提供。这样覆盖现有 PNG 后即可保持现有节点职责，避免双勾和重复标签。

### 2.5 本批追加排除项

```
solid filled disc, opaque center, opaque background, checkerboard background,
scene illustration, furniture, character, clue object, text, numbers, label plate,
checkmark, tick icon, success badge, magnifying glass, crosshair, radar display,
complex magic circle, occult symbols, concentric rings in idle or confirmed,
thick mechanical frame, large screws, heavy rivets, starburst, sparks,

```

```
绘制一张游戏现场调查用的“未确认热点圆环”独立 UI 素材。

统一交付目录：`Assets/Game/Sprites/UI/控件/`。文件名以本表为准，尤其按下态使用 **`pressed`**，不改成旧清单中的 `press`。

可以另外制作四态并排的检查图，但检查图不算交付素材，不进入运行时资源目录。若生成工具只支持更大的输出尺寸，保持正方形和同一构图基准，统一缩至 256×256 后再交付；不对四态分别自动裁掉透明边。

## 5. Unity 导入与覆盖要求

| 项目 | 约定 |
|---|---|
| Texture Type / Sprite Mode | Sprite (2D and UI) / Single |
| 显示组件 | Image.Type.Simple，Preserve Aspect 开启；不使用九宫格拉伸 |
| Pivot / PPU | 源图 Pivot 中心 `(0.5, 0.5)`；Pixels Per Unit = 100 |
| Sprite Mesh / Border | Full Rect；Border = `(0, 0, 0, 0)` |
| 透明与颜色 | RGBA；Alpha Is Transparency 开启；sRGB 开启；运行时白色乘色 |
| 采样 | Mip Maps 关闭；Wrap Mode = Clamp；Filter Mode = Bilinear |
| 尺寸与压缩 | 最终 256×256；Max Size 至少 256，不将最终图降到更小；交付检查使用无压缩以保留半透明环边 |
| 更新现有资源 | **仅覆盖同名 PNG，保留已有 `.meta` 和 GUID**，保持现有 Prefab / SpriteState 引用 |

保持圆心、画布与透明留白一致，不通过改变热点 RectTransform 尺寸来补偿某张图偏大或偏心。覆盖后应检查实际导入设置与各平台覆盖设置；本提示词文档不代表导入或运行验收已经完成。

## 6. 验收要点

- [ ] 四个唯一编号对应四张独立 PNG，文件名与 §4 完全一致，最终全部为 256×256。
- [ ] 四张正圆共用同一中心、方向与材质；idle/pressed/confirmed 的基础主环轮廓对齐，pulse 只有规定的同心外扩。
- [ ] pulse 最大外圈与微光没有裁边，四边保留全透明像素；四态切换时圆心不跳动。
- [ ] idle/pulse/pressed 明确是冷紫，confirmed 明确是暖铜，不把已确认误画成灰色禁用或成功绿环。
- [ ] pressed 是“主环 + 扫描环”的完整图，不是只能叠加使用的半成品特效层。
- [ ] PNG 有真实 Alpha；深色、浅色和复杂场景底上均无实心背景、棋盘格、灰边或光晕硬裁。
- [ ] 四图中心留白，不遮住场景线索；不含文字、标签底或确认勾。
- [ ] 在 140×140 实际显示尺寸下检查：主环清晰、扫描线能辨认，细节不糊成噪点。
- [ ] 与现有下方标签和右上 28×28 确认勾一起检查，确认后只显示一个勾。
- [ ] 使用当前绑定验证 normal→idle、highlighted→pulse、pressed→pressed、selected→idle、确认后的 disabled→confirmed。
- [ ] 当前约 1.6s 的透明度呼吸不会使 idle 消失；不要把“交付两张图”记录成“已实现两帧外扩动画”。
- [ ] 只覆盖 PNG 并保留 meta/GUID；导入后四个 Sprite 引用仍有效，PlayMode 检查按下、确认与对象池复用。
