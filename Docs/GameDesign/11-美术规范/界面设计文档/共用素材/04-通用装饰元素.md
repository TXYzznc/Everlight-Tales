## 1. 固定模块（每项提示词都要接在后面，逐字复用）

### A · UI 视觉语言

```
一款竖屏手机游戏的界面设计，2D 数字绘制，成熟的商业游戏 UI 完成度。
整体基调：深夜仍在营业的老式精密修理铺——黄铜工具的秩序感与门外未知之物的侵蚀感同处一框。
克制的低饱和深色底，靠局部暖光与冷光建立层次；不使用大面积高亮、不糖果色、不卡通描边，
不使用拟真照片贴图、玻璃拟态、霓虹赛博或扁平极简白底风格。
面板与控件用「薄金属板 + 蚀刻线 + 轻微内阴影」构成，边缘清晰、拐角圆润但克制（圆角半径小），
有实体感与触感，像一块被反复使用的工装面板。避免：厚塑料质感、浮雕过多、廉价渐变、立体投影过重。
```

### B · 色彩体系

```
以深色为绝对主体，具体色值：最底背景 #171A20，页面背景 #1E2229，
面板底 #262B34，卡片底与悬停 #2F3540，分隔线与描边 #3E4652，
主文本 #E8EAF0，次文本 #A8B0BC，弱文本与禁用 #6E7684。
强调色两支：暖铜 #E0A858（主按钮、高亮、当前选中、金属暖面），
冷紫 #A86AC8（怪谈、异常、待处理、警示性的神秘感）。
辅助功能色：工具青 #5A9EB8（次级强调、链接）、成功 #5AB878、危险 #D05A5A、警告 #D8A858。
暖铜与冷紫是画面唯一的两处「光」，其余全部压在深灰蓝的中低明度区间；
暖冷面积比大致 3:1，暖为主、冷为异。禁止大面积高饱和与多色并列竞争。
```

### C · 材质与光影

```
光源假定来自画面内的灯具与屏幕本身：左上偏暖的方向光，边缘有极轻微的冷紫反射光。
金属件强调转折面与窄亮反光带，不画照片级反射；布料与纸张用大面平涂加少量褶皱折线。
面板高光只在边缘 1~2px 处出现，形成薄金属收边；阴影短、硬、贴合结构，不做长投影与浓重 AO。
所有发光元素（指示灯、符文、异常侵蚀）用有限的光晕，光晕不超过元素自身尺寸的 1.5 倍。
整体干净、层次分明，从缩略图能读出分区，放大能看见刻线与铆钉的细节安排。
```

### D · 细节与统一性

```
统一全画面的圆角尺度、描边宽度（1~2px）、刻线间距与图标笔画粗细；
功能图标用统一线宽与统一圆角，风格一致，可成套使用；
同类控件在所有界面中保持同一种视觉语言，不因界面不同而改变造型。
焦点区域（主按钮、当前选中页签、提示信息）才允许更高对比与更精细的细节，
次要区域概括处理。不得让某一区域突然变成其他画风、摄影写实或手绘涂鸦。
```

## 2. 本批的两个特殊说明

### 2.1 `SHR-048` 与前七项不是一类

SHR-041 ~ SHR-047 都是**容器 / 控件 / 装饰件**——九宫格或独立小图，透明背景，不画内容。
`SHR-048 空状态插画` 是**一幅小插画**，需要构图、有主体、有场景感。

两者提示词写法完全不同：前者强调「结构、可切、中心留白」，后者强调「构图、主体、情绪、给文字留白」。
**出图时不要把 SHR-048 和前七项混在一次里出。**

### 2.2 装饰件的「克制度」

SHR-044 分隔线、SHR-045 分组标题、SHR-047 边角件是**辅助元素**，
玩家不应该「注意到」它们，只应该「感觉到」界面是有结构的。

> 判断标准：把这三个元素从界面上拿掉，界面会变松散、分不出组——这就是做对了。
> 如果它们本身很抢眼，就是做错了。**装饰件的第一原则是低对比。**

## 3. 逐项提示词

### SHR-041 · Toast 提示条

| 规格 | 值 |
|---|---|
| 源图 | 512×128，透明背景 |
| 九宫格 border | 16 |
| 显示基准 | 680×84 |
| 状态 | `info` / `success` / `warning` / `danger` |
| 文件名 | `shared_toast_<状态>@512x128.png` |
| 引用界面 | 全局（`GlobalUI.ShowToast`） |

**提示词主体**

```
一个游戏内浮动提示条，横向长方形，居中绘制，像一片悬浮在画面之上的薄金属片。
关键是**要看起来比它下面的界面「浮起来一层」**，靠边缘处理实现而不是靠更高的亮度：
四边一圈 1px 的窄亮收边（细亮线），板面是暗到近乎黑的深色 #101319，
下缘内侧有一道 2px 的柔和暗影，暗示它与下方界面之间有一层间隙；
左右两端略向内收（端面是斜切的小倒角，不是直角）；
**左端内侧有一个宽 4px、高约占 70% 的竖条位**，这是状态色条的位置。
板面中央完全平整（文字位留给程序），不得有任何图案。
不画文字、不画图标、不向外投影。
```

**四个状态的差异**（**只有左端竖条的颜色不同，其余逐像素一致**）

| 状态 | 左端竖条颜色 | 语义 |
|---|---|---|
| `info` | 暖铜 `#E0A858` | 一般信息（形态切换、已跟踪、前往某处） |
| `success` | 成功绿 `#5AB878` | 操作成功（领取成功、解锁） |
| `warning` | 警告黄 `#D8A858` | 需要注意（资源不足、时段将尽） |
| `danger` | 危险红 `#D05A5A` 低饱和 | 操作失败 / 造成后果 |

### SHR-042 · 加载遮罩 loading

| 规格 | 值 |
|---|---|
| 源图 | 128×128，透明背景 |
| 状态 | `spin`（单态，由程序旋转） |
| 文件名 | `shared_loading_ring@128x128.png` |
| 引用界面 | 全局 |

**提示词**

```
一个游戏加载指示器的旋转装饰环，方形画布内居中绘制的**圆形**图形，直径约占画布的 88%。
造型：一圈细金属环，环体宽约 6px，环上有**四段等距的短刻线**（每段约占圆周的 12%），
刻线比环体略亮，像刻度盘上的标记；环的内侧有一道极淡的暗色内圈增加厚度感。
外形必须是**完整的正圆**（因为它会被程序持续旋转，任何不对称都会在转动时暴露）。
环的中央完全透明（不放任何文字或图形，加载文案由程序渲染在环的下方）。
不画数字、不向外投影。
```

> **能被程序旋转的素材必须是正圆且左右上下对称**——这是硬约束。
> 环上的四段刻线要均匀分布（90° 一个），这样才能在旋转中产生节奏感。

| 规格 | 值 |
|---|---|

| 九宫格 border | 2（**仅左右**） |
| 状态 | 单态 |
| 文件名 | `shared_divider@64x8.png` |

**提示词**

```
一条游戏 UI 的横向分组分隔线，极细的短横条，居中绘制。
```

### SHR-048 · 空状态插画 empty-state

| 规格 | 值 |
|---|---|
| 源图 | 512×512，透明背景 |
| 状态 | `empty-list`（空列表）/ `empty-slot`（无内容）/ `locked`（未解锁） |
| 文件名 | `shared_empty_<状态>@512x512.png` |
| 引用界面 | 05 10 11 12 13 |

> **本项是插画，不是容器。** 构图要留白、有主体、有情绪，且要给下方的文字留出空间。

**提示词主体**

```
一幅游戏 UI 的空状态小插画，正方形构图，透明背景，主体居中偏上、下方留出约 20% 的空白。
风格是克制的静物：画面里没有人物，只有一两件与「修理铺」相关的旧物，
用大面平涂 + 少量硬边笔触画出，低饱和深色为主，只有一处暖铜色的光。
整体要传达「这里本来是满的，现在空着」的感觉，而不是「出错了」——
情绪是安静的等待，不是警告。
不画文字、不画边框、不画背景板。
```

| 状态 | 画面主体 | 情绪 |
|---|---|---|
| `empty-list` | 一张空的工作台，台面上只有一盏还亮着的小灯和一枚孤零零的螺丝；台面的大部分是空的 | 今天还没有活干 |
| `empty-slot` | 一个打开的、内部空空的小零件盒，盒底衬布有几道压痕说明曾经放过东西 | 差的那一件还没找到 |
| `locked` | 一扇挂着铜锁的小柜门（或一个被铁链绕住的抽屉），锁上有一层极薄的灰 | 还没到能打开的时候 |

**三张插画的构图必须一致**（同一视角、同一地平线、主体占画布约 55% 且位置相同），
这样它们出现在不同界面时，玩家会认出「这是同一套空状态图」，而不是三张无关的画。

**色彩**：主体压在中低明度（`#262B34` ~ `#3E4652` 一带），
唯一的高光是画面里那一小处暖铜（灯 / 铜锁 / 盒边），面积不超过画面的 8%。
`locked` 态允许在锁上带**极薄的一点冷紫**（约 5% 面积），暗示封锁与怪谈有关。

## 4. 出图批次建议

本批 17 张，分 **3 次**：

| 次序 | 内容 | 张数 | 说明 |
|---|---|---|---|
| 第 1 次 | SHR-047 边角件 + SHR-044 分隔线 + SHR-045 分组标题 | 3 | 三个**装饰件**一起出——它们同为「低对比辅助元素」，一次出能统一克制度 |

> 把它放到任意一个界面截图上，如果第一眼就看见它，说明对比过高，要压暗重出。

## 5. 本批验收要点

- [ ] **SHR-044 / 045 / 047 三个装饰件不抢眼**：单独看很不起眼，放进界面里能让结构变清楚——做对了；一眼就看见——做错了
- [ ] SHR-047 边角件的两枚铆钉大小一致，且在不同面板缩放下仍然清晰（不要小到看不见，也不要大到像按钮）
- [ ] SHR-045 分组标题装饰**左右严格镜像对称**，中央留白区完全透明（文字位干净）
- [ ] SHR-042 加载环是**完整正圆、上下左右对称**，旋转时不会看出偏心或晃动
