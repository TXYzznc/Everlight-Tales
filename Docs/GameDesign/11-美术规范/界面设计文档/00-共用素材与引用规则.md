> **本文件是索引与协调文档，不是出图文档——不要整份喂给生图 AI。**
> 实际出图用 `共用素材/` 下的 8 个**批次文档**，每个都是自包含的（含固定风格模块 + 逐项提示词 + 状态后缀）。

## 1. 三种处理策略（判断「该不该共用」）

界面之间共用素材有**三种不同情况**，处理方式不同，混用会出错：

| 情况 | 判断标准 | 处理方式 | 例子 |
|---|---|---|---|
| **A · 完全共用（一份图，多处引用）** | 各界面用法在视觉上完全一致，无任何差异 | **只出一份**，各界面共同引用 | 面板九宫格、主按钮、功能图标、滑块、滚动条 |
| **B · 同族变体（一份母版 + 少量派生）** | 同一控件在不同界面需要不同尺寸/色调/语义 | **出母版 + 派生**，派生只改尺寸或一个语义色 | 按钮主/次/危险、页签 3/4/5 页、卡片普通/强调 |
| **C · 形似而不同（各出一份）** | 看起来像但承载不同信息，改了会误导玩家 | **各界面单独出**，不做共用 | 地图地点节点、盘面棋子、事件类型图标 |

> 判断口诀：**改一张图能不能同时满足两处？能 → A；只需要换色/换尺寸？→ B；会丢失信息或造成误读？→ C。**

**每批文档里已经在用这个策略**，例如：
- `02-按钮与页签` 的 §2 明确要求「先出母版形状，再换色派生 4 个变体」——这是策略 B 的落地做法
- `05-图标-导航与功能` 全部单色（一套图适配 6 种颜色语境）——策略 A 的极致做法
- `08-图标-地图地点` 五座建筑各出一份、不可合并——策略 C 的典型

## 2. 编号规则

**每个需绘制的素材 = 一个状态 = 一张图 = 一个唯一编号。**
不同状态的素材**不能视作一个素材**——每个状态都有独立的编号、独立的提示词、独立的交付文件。

| 前缀 | 含义 | 定义位置 |
|---|---|---|
| `SHR-` | 共用素材（九宫格 / 控件 / 通用元素） | `共用素材/01`~`04` |
| `ICO-` | 图标（功能 / 状态 / 类型 / 资源 / 地点） | `共用素材/05`~`08` |
| `SCR-<界面号>-` | 界面专属素材 | 各界面文档（`界面/01`~`20`） |

**编号格式**：`<前缀><族号>[-<状态>]`

- 单态素材：编号不带状态后缀，如 `SHR-001`（面板，只有一张）
- 多态素材：每个状态一个编号，如 `SHR-003-normal` / `SHR-003-hover` / `SHR-003-pressed` /
  `SHR-003-disabled` / `SHR-003-selected`

**状态后缀 = 文件名里的状态词**（英文小写，多词用连字符）：

```
normal / hover / pressed / disabled / active / selected / empty / filled / highlight
daylight / night / modal / pause / alert / badge
info / success / warning / danger / empty-list / empty-slot / locked
day-active / day-idle / night-active / night-idle
```

**素材命名**：`<域>_<部件>_<状态>@<尺寸>.png`（状态词与编号后缀一致）

| 域前缀 | 用于 | 例 |
|---|---|---|
| `shared_` | SHR- 共用素材 | `shared_btn_primary_normal@256x128.png` |
| `ico_` | ICO- 图标 | `ico_map@128x128.png` |
| `<界面>_` | SCR- 界面专属 | `codex_row_owned@1000x92.png` |

> 编号 ↔ 文件对应示例：`SHR-021-hover` ↔ `shared_btn_primary_hover@256x128.png`。
> 界面文档引用时写「族编号」即可（如「引用 SHR-021 主按钮」＝该族全部状态），
> 出图与交付按「状态级编号」逐一进行。

### 出图优先级

1. **第一优先（引用 ≥10 处）**：`SHR-025` 图标按钮、`SHR-021` 主按钮、`SHR-001` 面板、`SHR-047` 边角件、`SHR-002` 对话框
2. **第二优先（引用 4~9 处）**：`SHR-006` 顶部条、`SHR-022` 次按钮、`SHR-003` 卡片、`SHR-026` 页签3、`SHR-041` Toast、`SHR-048` 空状态
3. **第三优先（引用 1~3 处）**：其余 SHR
4. **图标组**：`ICO-001`~`016` 导航功能（每界面都用）→ `ICO-021`~`030` 状态 → `ICO-041`~`046` 类型 → `ICO-051`~`062` 资源 → `ICO-071`~`075` 地点

> 注意优先级**只在批次内部**决定先后，不要跨批插队：
> `共用素材/01` 先整体出完，再进 `共用素材/02`。
> 因为容器的造型语言是后面所有控件的基础。

## 4. 引用规则（写文档时必须遵守）

1. **界面文档只写编号**，不复制提示词。例：`引用：SHR-021 主按钮（normal/hover/pressed/disabled）`。
2. **共用素材的提示词只在 `共用素材/` 的批次文档里维护**，改动一处即全局生效。
3. 若某界面确实需要共用素材的**变体**（如某种卡片要更窄）：
   **先判断能否用九宫格拉伸解决**；不能才新增 `SCR-<界面号>-` 专属条目，并在本文件 §2 登记。
4. **禁止**在界面文档里另起一个「差不多的按钮」——这会产生 12 个近似版本，是 UI 不统一的根源。
5. 新增共用素材时：写进对应的批次文档，并同步更新本文件 §0 索引与 §3 引用矩阵。
