# 10 · 加工台

> 对应脚本：`Assets/Game/Scripts/EverlightTales/UI/WorkbenchPanel.cs`、`WorkbenchLayout.cs`
> 承载方式：程序化构建，作为家园「加工」区（Zone 1）的内容，也由主页壳 Tab 3 直接进入
> 策划出处：`02-系统设计/22-加工台与形态切换流程.md`、`25-加工配方与经济节奏.md`、`14-首批改装形态与日常成长.md`

---

## 1. 界面概述

加工台是**形态（F 类通用形态 + M 类怪谈形态）的加工与切换中心**。三段结构：

```
上方：宿主零件选择 → 中部：该宿主的形态卡列表 → 下方：详情 + 加工/切换按钮
```

三个子页签：**加工 / 材料 / 账目**（`m_SubTab` 0/1/2）。

- 打开入口：家园 Zone 1，或主页壳 Tab 3
- 核心数据：`WorkbenchLayout.OwnedHostParts(world)`、`WorkbenchLayout.FormCards(world, host)`
- 核心动作：`FormService.Unlock`（加工）、`FormService.SwitchCurrent`（切换）

**形态卡的四种状态**（`FormCardState`）：

| 状态 | 含义 | 卡片文案 | 按钮 |
|---|---|---|---|
| `Current` | 已解锁且为当前使用 | 「★ {名}（使用中）」 | 「使用中」（禁用，灰） |
| `Unlocked` | 已解锁但非当前 | 「{名}（已解锁）」 | 「切换」（蓝） |
| `Craftable` | 有图样未解锁，或无需图样 | 「{名}（可加工）」 | 「加工」（绿） |
| `Unknown` | 未取得图样 | 「{名}（未取得图样）」 | 「未取得图样」（禁用，灰） |

### 2.1 顶部条与宿主行

| 元素 | 锚点 | 位置 | 尺寸 | 字号 | 颜色 |
|---|---|---|---|---|---|
| workbench_top 底 | min(0,1) max(1,1) pivot(0.5,1) | (0,0) | (0,96) | — | `#1A1F29` @92% |
| 费用文本 | — | (−24,−24) | (240,36) | 26 | 白，右对齐，`维修费 {N}` |
| 子页签 ×3 | — | (−430+i·150, −24) | (140,56) | 26 | 选中绿 / 未选蓝 |
| host_row | min(0,1) max(1,1) pivot(0.5,1) | (0,0) | (0,90) | — | — |
| 宿主按钮 | min(0,1) max(0,1) pivot(0,1) | (20+i·212, −45) | (200,60) | 24 | 选中绿 / 未选蓝 |

**宿主按钮横向滚动**：`x` 从 20 开始，每枚步进 212（即按钮宽 200 + 间距 12）。
宿主较多时会超出屏宽——**当前程序未实现横向滚动**，制作时需按「超出部分被裁切」或建议程序加横向滚动。

### 2.2 形态卡列表

| 元素 | 锚点 | 位置 | 尺寸 | 字号 | 颜色 |
|---|---|---|---|---|---|
| form_list 容器 | min(0,1) max(1,1) pivot(0.5,1) | (0,−100) | (0,300) | — | — |
| 形态卡 | min(0,1) max(1,1) pivot(0.5,1) | (0, −i·68) | (−40,60) | — | 使用中绿 / 其他蓝 |
| 卡文字 | 居中 | — | — | 24 | 白 |

> **形态卡列表高 300，但每张卡步进 68** → 一次可见 **4 张**（4×68 = 272 < 300）。
> 超过 4 张时超出部分会被裁切（**当前无滚动**）。设计时按「可见 4 张 + 底部渐隐提示可滚动」处理。

### 2.3 详情区与操作区

| 元素 | 锚点 | 位置 | 尺寸 | 字号 | 颜色 |
|---|---|---|---|---|---|
| detail 文本 | min(0,1) max(1,1) pivot(0.5,1) | (0,−420) | (−40,380) | 26 | `#EBEBEB`，左上对齐 |
| action 按钮 | min(0,1) max(1,1) pivot(0.5,1) | (0,−820) | (−40,64) | 26 | 见状态色表 |
| action_hint | min(0,1) max(1,1) pivot(0.5,1) | (0,−900) | (−40,40) | 22 | `#99A6B3`，居中 |

**详情文本模板**（`WorkbenchPanel.SelectForm`）：

```
基础形态                                   ← 或 {形态名}
{card.Description}
解锁费：{UnlockFee} 维修费                 ← 非基础形态才有
图样：已取得                                ← 有图样要求时（二选一）
图样：未取得（{SourceHint}）                ← 未取得时
材料：{材料名} {Held}/{Required} ✓          ← 逐项，够用打 ✓
材料：{材料名} {Held}/{Required} ✗          ← 不足打 ✗
```

**空态（无已拥有宿主零件）**：
```
暂无已拥有的宿主零件。
（先通过事件/委托获取零件与图样）
```
此时 `action` 按钮隐藏，`action_hint` 清空。

### 2.4 操作按钮的四种状态色

| 形态卡状态 | 按钮文案 | interactable | 按钮色 |
|---|---|---|---|
| `Current` | 「使用中」 | **false** | `ButtonGrey` ≈ `#474747` |
| `Unlocked` | 「切换」 | true | `ButtonBlue` ≈ `#4D6B8C` |
| `Craftable` | 「加工」 | true | `ButtonGreen` ≈ `#428557` |
| `Unknown` | 「未取得图样」 | **false** | `ButtonGrey` |

> **注意**：「加工」用绿色、「切换」用蓝色、「使用中/未取得」用灰色。
> 这是三套语义色的实际使用场景，设计时需保证绿/蓝/灰在**同一画面内**可清晰区分。

### 2.5 材料页（`m_SubTab = 1`）

```
背包为空。                        ← 空态，色 #99A6B3
{材料名}（{来源怪谈}）× {数量}     ← 每行一个材料栈，字号 26，色 #EBEBEB，行高 52
```

> 材料栈按 `MaterialStack` 逐条渲染。**异常纹样 MT-006 按来源怪谈类型化**，
> 因此会出现「异常纹样（红舞鞋）× 1」与「异常纹样（画皮）× 2」两条独立记录——
> 设计上需为「类型化材料」留出一个来源标签位。

### 2.6 账目页（`m_SubTab = 2`）

```
暂无收支记录。                    ← 空态
+40 费 · 结算 · {原因}             ← 收入，色 (0.5,0.9,0.55) ≈ #80E68C，行高 52
-120 费 · 加工 · {原因}            ← 支出，色 (0.95,0.6,0.5) ≈ #F29980
```

**通道中文**（`ChannelText`）：结算 / 任务 / 回访 / 加工 / 其他。
**方向符号**：收入 `+`，支出 `-`。
**排序**：倒序（最新在上，代码用 `for (i = count−1; i >= 0; i--)`）。

## 验收要点（原版）

- [ ] 四种形态卡状态在缩略图下可区分（底色的绿/蓝/蓝/灰 + 左缘色条）
- [ ] 「加工」按钮是页面内最强的行动召唤（横贯全宽的绿色实底）
- [ ] 宿主按钮排列整齐，选中态明确；超出屏宽时的处理方案已确定
- [ ] 详情区文字行距足够（材料清单可能 4~5 行，须在 380 高内排下）
- [ ] ✓ / ✗ 标记成套，线宽与视觉重量一致，颜色语义清晰（✓ 成功绿 / ✗ 危险红）
- [ ] 账目行的收入绿与支出红对比清楚，不刺眼
- [ ] 类型化材料（异常纹样）的来源标签位已预留
- [ ] 空态（无宿主零件 / 背包为空 / 无账目）都有对应处理，不出现空白区
- [ ] 形态卡列表超过 4 张时有底部渐隐提示

## 10. Prefab 制作契约（文档确认后执行）

> 本节只描述 Prefab 制作，不生成效果图。Assets/Test 中对应的 Image 仅用于 1080×1920 PlayMode 对照验收；运行时禁止把整张对照图挂到页面上。

### 10.1 页面根节点与布局基准

| 项目 | 约束 |
|---|---|
| 设计分辨率 | 1080×1920 竖屏；Canvas Scaler 使用 Scale With Screen Size；SafeArea 内缩 |
| 页面根节点 | UIForm → SafeArea → 背景/固定层/内容层/弹窗层 |
| 对照图 | 仅用于截图对照，不作为 Prefab 子节点或运行时资源 |

### 10.2 节点树与节点职责

页面必须包含 SafeArea、Background、Header、Content、Footer、Overlay。Background 位于最底层并只绑定正式背景；Header 顶部 Stretch，包含标题、返回和状态条；Content 位于 Header 与 Footer 之间，列表只保留动态容器；Footer 底部 Stretch，按钮同一基线；Overlay 覆盖 SafeArea，默认隐藏并负责弹窗、Toast、Loading。

### 10.3 逐节点设计表

### 10.4 UIItem 模板与动态创建

页面 Prefab 只保存模板引用字段和动态容器，不保存重复 Item 实例。每种重复对象在 Assets/Game/Prefabs/UI/Item/<ItemName>.prefab 独立制作，根节点挂 Item 脚本和 GF UIItemObject；图标、标题、详情、数值/操作的相对关系固定。页面打开、刷新或切换分类时从对象池创建，关闭或切换页面时回收，空列表显示 Empty 节点。Item 只负责视图绑定、状态切换和事件转发。

### 10.5 正式资源接入规则

1. 每条资源必须解析为 Assets/Game/Sprites/UI 下的实际文件。
2. SHR 九宫格使用 Image.Type.Sliced；图标使用 preserveAspect。
3. 控件状态按文件名后缀绑定；缺失状态按资源表回退。
4. 资源缺失、节点缺失、节点重复或引用对照图均记入差异表。

### 10.6 制作与验收顺序

1. 按节点树创建固定节点并设置 1080×1920 锚点。
2. 按资源表绑定正式 Sprite、字体和控件状态。
3. 创建并验证 Item 模板，再接入模板引用和动态容器。
4. PlayMode 使用 1080×1920 截图，对照 Assets/Test 的 Image。
5. 逐项验收层级、资源、Item 创建/回收、空态/选中态/禁用态、SafeArea 和输入阻挡。
