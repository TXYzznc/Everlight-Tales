# 18 · 全局弹窗与反馈

> 对应脚本：`Assets/Game/Scripts/EverlightTales/UI/DialogView.cs`、`GlobalUI.cs`、`GlobalUIRoot.cs`、`ToastItem.cs`
> 对应预制体：`Assets/Game/Prefabs/UI/DialogView.prefab`（无契约文件，数值取自预制体 YAML）
> 承载方式：预制体（UIForm，Dialog 分组 `sortingOrder = 200`）；Toast/Loading 由 `GlobalUIRoot` 独立 Canvas 承载（`sortingOrder = 500`）

---

## 1. 界面概述

本界面包含三类**全局反馈**，它们被所有界面复用，是玩家见到频率最高的 UI：

| 类型 | 触发方式 | 层级 | 是否阻断交互 |
|---|---|---|---|
| **通用对话框** `DialogView` | `GlobalUI.ShowDialog` / `Confirm` / `ShowUnlock` | 200 | 是（全屏 Dimed 遮罩） |
| **Toast 提示** | `GlobalUI.ShowToast` | 500 | 否（2 秒后自动消失） |
| **Loading 遮罩** | `GlobalUI.ShowLoading` / `HideLoading` | 500 | 是（全屏黑色 55%） |

三个全局入口的实际用法（散落在各界面中）：

| 入口 | 用法 | 典型调用点 |
|---|---|---|
| `ShowDialog(title, content)` | 单按钮弹窗 | 零件卡、本轮小结、规则、目标地点、领取成功、助手来电 |
| `Confirm(title, content, onOk, onCancel)` | 双按钮确认 | 等待到下一时段、删除存档、放弃本关、恢复维修尝试、事件详情 |
| `ShowUnlock(title, content)` | 「解锁 · {title}」单按钮弹窗 | 新形态加工解锁 |
| `ShowToast(msg)` | 浮动提示 | 形态切换、已跟踪、无法搬动、材料不足、前往地图 |
| `ShowLoading()` / `HideLoading()` | 全屏遮罩（引用计数） | 切页签/Hotfix 流程 |

> **优先级**：Toast（500）> Dialog（200）。因此 Toast 会显示在弹窗之上——
> 例如「无法搬动：…」的 Toast 会浮在盘面弹窗上层。

## 2. 布局规格（基准 1080×1920）

### 2.1 通用对话框 `DialogView`

```

        │             标题                │  Title 高 90，字号44
        │      「卡住的卷帘门」            │  上下拉伸，pivot(0.5,1)
```

> - 单按钮（`ShowDialog`）：宽度可取 400~480，居中
> - 双按钮（`Confirm`）：各约 360，间距 40，居中排布

## 6. 交互控件状态

| 控件 | 尺寸 | 状态 | 视觉变化 |
|---|---|---|---|
| 弹窗主按钮（确认/确定） | 360~480×64 | `normal` / `hover` / `pressed` / `disabled` | 暖铜实底 + 深色字；pressed 压暗到 `#C88A3A` + 下沉 2px；disabled 灰 |
| 弹窗次按钮（取消） | 360×64 | `normal` / `hover` / `pressed` | 透明底 + 1px `#3E4652` 描边 + 浅字；hover 描边转 `#A8B0BC` + 底 10% 白 |
| 危险确认按钮（删除/放弃） | 360×64 | `normal` / `hover` / `pressed` | 用 `SHR-024` 危险红系 |
| Toast 条 | 680×84 | `show` / `fade-out` | 显示 2 秒后淡出；淡出时长建议 0.25s（由程序控制，素材只需一态） |
| Loading | 全屏 | `show` / `hide` | 装饰环持续旋转（素材只需一态） |

> **按钮状态要点**：弹窗内按钮**同时存在主/次/危险三种语义**在同一容器里。
> 设计时须保证三者在同一行并排时权重排序清晰：主 > 危险 > 次。
> 「删除存档」与「放弃本关」的确认按钮应用危险色，让玩家意识到后果。

## 8. 验收要点

- [ ] 弹窗在任意界面之上都能「浮起来一层」（细亮描边 + 柔和投影，不靠更亮更大）
- [ ] 遮罩 50% 足够压暗背景，但仍能看见上下文（不是全黑）
- [ ] 正文区能容纳多行信息（最多 3~4 行，字号 34），不溢出对话框
- [ ] 单按钮排版（居中占满）与双按钮排版（左右等分）都已提供
- [ ] 双按钮时主/次/危险的权重排序清晰（主按钮最醒目，危险按钮次之，取消最弱）
- [ ] Toast 在底部 4% 处，不遮挡底部页签栏与盘面操作按钮（安全区已考虑）
- [ ] 多条 Toast 纵向堆叠时不错位（间距 12）
- [ ] Toast 四类（info/success/warning/danger）的左缘色条可区分
- [ ] Loading 的装饰环与「加载中…」文字视觉协调
- [ ] 所有弹窗按钮的文字居中对齐，且左右内边距一致（不出现文字贴边）

## 10. Prefab 制作契约（文档确认后执行）

> 本节只描述 Prefab 制作，不生成效果图。Assets/Test 中对应的 Image 仅用于 1080×1920 PlayMode 对照验收；运行时禁止把整张对照图挂到页面上。

### 10.1 页面根节点与布局基准

| 项目 | 约束 |
|---|---|
| 设计分辨率 | 1080×1920 竖屏；Canvas Scaler 使用 Scale With Screen Size；SafeArea 内缩 |
| 页面根节点 | UIForm → SafeArea → 背景/固定层/内容层/弹窗层 |
| 对照图 | 仅用于截图对照，不作为 Prefab 子节点或运行时资源 |

### 10.2 节点树与节点职责

页面必须包含 SafeArea、Background、Header、Content、Footer、Overlay。Background 位于最底层并只绑定正式背景；Header 顶部 Stretch，包含标题、返回和状态条；Content 位于 Header 与 Footer 之间，列表只保留动态容器；Footer 底部 Stretch，按钮同一基线；Overlay 覆盖 SafeArea，默认隐藏并负责弹窗、Toast、Loading。

### 10.4 UIItem 模板与动态创建

页面 Prefab 只保存模板引用字段和动态容器，不保存重复 Item 实例。每种重复对象在 Assets/Game/Prefabs/UI/Item/<ItemName>.prefab 独立制作，根节点挂 Item 脚本和 GF UIItemObject；图标、标题、详情、数值/操作的相对关系固定。页面打开、刷新或切换分类时从对象池创建，关闭或切换页面时回收，空列表显示 Empty 节点。Item 只负责视图绑定、状态切换和事件转发。

### 10.5 正式资源接入规则

1. 每条资源必须解析为 Assets/Game/Sprites/UI 下的实际文件。
2. SHR 九宫格使用 Image.Type.Sliced；图标使用 preserveAspect。
3. 控件状态按文件名后缀绑定；缺失状态按资源表回退。
4. 资源缺失、节点缺失、节点重复或引用对照图均记入差异表。

### 10.6 制作与验收顺序

1. 按节点树创建固定节点并设置 1080×1920 锚点。
2. 按资源表绑定正式 Sprite、字体和控件状态。
3. 创建并验证 Item 模板，再接入模板引用和动态容器。
4. PlayMode 使用 1080×1920 截图，对照 Assets/Test 的 Image。
5. 逐项验收层级、资源、Item 创建/回收、空态/选中态/禁用态、SafeArea 和输入阻挡。
