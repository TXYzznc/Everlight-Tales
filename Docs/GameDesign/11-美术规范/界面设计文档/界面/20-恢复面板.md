# 20 · 恢复面板

> 对应脚本：`Assets/Game/Scripts/EverlightTales/UI/MainPageShell.cs`（`OnRecoveryContinue` / `OnRecoveryAbandon`）、
> `ServicePanel.cs`（服务区入口）、`GlobalUI.Confirm`
> 逻辑：`Meta/RecoveryService(hasAttemptSave).Resolve(chooseContinue)` → `FreshStart` / `Continue` / `AbandonAsRetreat`
> 策划出处：`02-系统设计/21-存档与恢复流程.md`

---

## 1. 界面概述

**异常退出后的恢复决策**。游戏检测到有未完成的维修尝试时，在主页壳打开后弹出「继续 / 放弃」询问。

| 结果 | 语义 |
|---|---|
| **继续** | 恢复该次维修尝试（同一轮、同一盘面、同一资源状态） |
| **放弃** | `AbandonAsRetreat` —— 按**撤退**处理（怪谈回到维修前状态 / 普通事件按撤退规则） |

- 触发时机：`MainPageShell.OnOpen` 中 `WorldSession.Current.HasAttemptSave` 为真
- 另一入口：家园 → 服务区 → 「恢复面板」（只读提示，见 `14-服务区.md`）
- 幂等：`RecoveryService` 有 `_resolved` 防重，继续/放弃各只结算一次

> **当前实现状态**：主页壳的「继续」分支只弹了一个 Toast（「首版尝试存档未持久化，暂跳过」），
> 「放弃」只弹 Toast（「已放弃维修尝试」）。**正式版需要真正接入 `RecoveryService.Resolve`**。
> 本界面按**正式版设计**出图——它是「一天闭环」上不可缺的一环。

## 6. 交互控件状态

| 控件 | 尺寸 | 状态 | 视觉变化 |
|---|---|---|---|
| 继续按钮 | 360×64 | `normal` / `hover` / `pressed` / `disabled` | 暖铜实底 `#E0A858` + 深色字 `#171A20`；hover 外发光 +30%；pressed 压暗到 `#C88A3A` + 下沉 2px；disabled 用于尝试存档损坏 |
| 放弃按钮 | 360×64 | `normal` / `hover` / `pressed` / `disabled` | 透明底 + 1px `#3E4652` 描边 + `#E8EAF0` 字；hover 描边转 `#A8B0BC` + 底 10% 白 + 文字微暖（暗示这是「结束」）；pressed 底压暗 |
| 确定按钮（空态） | 440×64 | `normal` / `hover` / `pressed` | 同 `SHR-021` 主按钮 |

> **「放弃」的 hover 处理需要谨慎**：它是破坏性操作，但设计上**不应使用危险红**
> （因为放弃尝试并不等于失败，只是结束这次维修），而应用**冷紫**——
> 与本项目「冷紫 = 退向混沌」的语义一致。这与 `放弃本关`（暂停菜单内）用危险红形成层次区别。

## 8. 验收要点

- [ ] 「继续」与「放弃」两个按钮的权重差异明显（实底 vs 描边），主次清楚
- [ ] 「放弃」不使用危险红，用中性/冷紫处理（语义是「结束」而非「失败」）
- [ ] 三行信息行（事件/轮次/时间）有图标 + 文字的对齐关系，读起来像一张工单
- [ ] 说明行（字号 26，灰）与信息行（字号 34，亮）层级分明
- [ ] 对话框高度 620 足够容纳正文（首行 + 空行 + 三行 + 空行 + 说明行 ≈ 5~7 行）
- [ ] 空态（无尝试）只有一行正文 + 单按钮，版式依然成立，不出现大片空白
- [ ] 背景虚化的地图界面仍能看出上下文（玩家知道自己在哪）
- [ ] 对话框的金属板质感与 `18-全局弹窗` 同族，但可以更「厚」一些以承载中断语义
