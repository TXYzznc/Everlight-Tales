## 1. 界面概述

玩家在地图选定事件、进入盘面之前的**决策页**。这一页回答三个问题：

1. **这次要修什么** → 关卡信息区（事件名/目标/耗时/轮次/特殊目标/可借用件）
2. **我带哪 6 种零件** → 携带选择区（6 个槽位 + 可选零件列表 + 一键补关键件）
3. **值不值得现在开始** → 盘面预览区（固定元素 + 关键件的只读缩影）

准备、预览、切换形态、取消都不消耗地图时间（D-021）。

- 打开入口：地点事件卡 → 确认 → 准备页
- 确认后：`WorldSession.ConfirmRollerDoor()` → 打开 `UIViews.BoardPage`
- 返回：`OnClickClose()` → 回地图，不扣时间

### 2.2 槽位颜色逻辑（重要）

```
空槽   SlotEmptyColor  = (0.1843, 0.2078, 0.2510) ≈ #2F3540
已选   SlotFilledColor = (0.6588, 0.4157, 0.7843) ≈ #A86AC8   ← 冷紫！
```

> 已选槽位用**冷紫**而非暖铜，这是「怪谈冷紫」轴在准备页的落点——
> 被选中的零件是被玩家「带进怪谈现场」的东西，用冷紫提示其危险性。设计时必须保留这个语义。

**槽位标签**：空槽显示「—」，已选显示零件名（`PartCodexCatalog.Get(part).Name`）。

### 2.3 预览区渲染（`PreviewBoardView`）

预览区在 `Panel_PreviewContent` 内程序化绘制，不显示随机件：

| 内容 | 颜色 |
|---|---|
| 点顶大六边形轮廓 | `(0.35,0.78,1.0,0.55)` 半透明青蓝，描边宽 2.5 |
| 固定障碍 | `(0.30,0.22,0.22)` 暗红 |
| 任务标记 / 可移动标记 | `(0.95,0.80,0.20)` 金黄 |
| 端点标签 | `(0.62,0.40,0.92)` 紫 |
| 固定设施 | `(0.22,0.24,0.28)` 深灰 |
| 关键件 | `EntityVisuals.GetPartColor(partType)` |
| 实体描边 | `(0,0,0,0.45)` 黑 45% |

**缩放算法**：`cellSize = min(容器宽, 容器高) × 0.9 / (4 × (boardRadius + 1))`，钳制在 4~20。
大六边形直径 = `4 × (boardRadius + 1) × cellSize`。

**预览摘要文案**（`Txt_PreviewSummary`）：
```
半径 {BoardRadius} · 固定元素 {FixedElements.Count} · 关键件 {KeyPieces.Count}
```

## 8. 验收要点

- [ ] 三块面板视觉同族（同一套边角件与刻线），形成「一叠工单」的整体感
- [ ] 六个槽位排列整齐，行间距 16、列间距 20，且上下两行严格对齐
- [ ] 空槽与已选槽一眼可分（深灰 vs 冷紫），且已选槽看得出「被插入」的实体感
- [ ] 进度提示「已选 N/6」的位置需明确（当前代码未实现，设计时预留标题行右侧或槽位网格下方）
- [ ] 预览区的大六边形轮廓清晰，内部色块可辨识种类（颜色 + 形状）
- [ ] 确认按钮与返回按钮左右分列、宽度不等（320 vs 220），视觉权重上确认明显更强
- [ ] 确认按钮 disabled 态与 normal 态差异显著
- [ ] 可选零件列表在只有 1~2 项时不会出现大片空白（考虑顶部对齐而非垂直居中）
- [ ] 长零件名不溢出槽位（槽宽 300，左右各留 8px）

## 10. Prefab 制作契约（文档确认后执行）

> 本节只描述 Prefab 制作，不生成效果图。Assets/Test 中对应的 Image 仅用于 1080×1920 PlayMode 对照验收；运行时禁止把整张对照图挂到页面上。

### 10.1 页面根节点与布局基准

| 项目 | 约束 |
|---|---|
| 设计分辨率 | 1080×1920 竖屏；Canvas Scaler 使用 Scale With Screen Size；SafeArea 内缩 |
| 页面根节点 | UIForm → SafeArea → 背景/固定层/内容层/弹窗层 |
| 对照图 | 仅用于截图对照，不作为 Prefab 子节点或运行时资源 |

### 10.2 节点树与节点职责

页面必须包含 SafeArea、Background、Header、Content、Footer、Overlay。Background 位于最底层并只绑定正式背景；Header 顶部 Stretch，包含标题、返回和状态条；Content 位于 Header 与 Footer 之间，列表只保留动态容器；Footer 底部 Stretch，按钮同一基线；Overlay 覆盖 SafeArea，默认隐藏并负责弹窗、Toast、Loading。

### 10.3 逐节点设计表

| 节点名 | 父节点 | 锚点/尺寸 | 组件职责 | 正式资源路径 | 状态 |
|---|---|---|---|---|---|
| Txt_Title | Header | 左上；距左48、距上32；高64 | TMP 页面标题 | 无；项目字体材质 | 始终显示 |
| Btn_Back | Header | 右上；48×48 触控区 | Button 返回上级 | 本页资源表指定 ICO-* | 可用/禁用 |
| ScrollViewport | Content | 四边 Stretch | Mask 裁切内容 | 无 | 超出时滚动 |
| ContentRoot | ScrollViewport | 顶部 Stretch | LayoutGroup 承载运行时 Item | 无 | 只含动态实例 |
| Btn_Primary | Footer | 底部居中 | Button 主流程动作 | Assets/Game/Sprites/UI/控件/SHR-021-*主按钮.png | normal/hover/pressed/disabled |
| Btn_Secondary | Footer | 与主按钮同基线 | Button 次流程动作 | Assets/Game/Sprites/UI/控件/SHR-022-*次按钮.png | normal/hover/pressed/disabled |
| Overlay | 页面根节点 | Stretch | CanvasGroup 阻挡输入 | SHR-041/042/002，按页面资源表 | 默认隐藏 |

### 10.4 UIItem 模板与动态创建

页面 Prefab 只保存模板引用字段和动态容器，不保存重复 Item 实例。每种重复对象在 Assets/Game/Prefabs/UI/Item/<ItemName>.prefab 独立制作，根节点挂 Item 脚本和 GF UIItemObject；图标、标题、详情、数值/操作的相对关系固定。页面打开、刷新或切换分类时从对象池创建，关闭或切换页面时回收，空列表显示 Empty 节点。Item 只负责视图绑定、状态切换和事件转发。

### 10.5 正式资源接入规则

1. 每条资源必须解析为 Assets/Game/Sprites/UI 下的实际文件。
2. SHR 九宫格使用 Image.Type.Sliced；图标使用 preserveAspect。
3. 控件状态按文件名后缀绑定；缺失状态按资源表回退。
4. 资源缺失、节点缺失、节点重复或引用对照图均记入差异表。

### 10.6 制作与验收顺序

1. 按节点树创建固定节点并设置 1080×1920 锚点。
2. 按资源表绑定正式 Sprite、字体和控件状态。
3. 创建并验证 Item 模板，再接入模板引用和动态容器。
4. PlayMode 使用 1080×1920 截图，对照 Assets/Test 的 Image。
5. 逐项验收层级、资源、Item 创建/回收、空态/选中态/禁用态、SafeArea 和输入阻挡。
