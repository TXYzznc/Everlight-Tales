# 14 · 服务区

> 对应脚本：`Assets/Game/Scripts/EverlightTales/UI/ServicePanel.cs`
> 承载方式：程序化构建，作为家园「服务」区（Zone 4）的内容
> 说明：非经营区，不做客流/好感/经营数值（D-323）。本区是三个快捷入口的集合。
> 布局数值见 `09-家园五区.md`；本文档聚焦素材与状态。

---

## 1. 界面概述

服务区只有三个入口：

| 入口 | 行为 |
|---|---|
| **配装（携带选择）** | Toast「配装请在准备页调整（进入事件前）」 |
| **恢复面板** | `GlobalUI.ShowDialog` 展示有无未完成维修尝试 |
| **设置** | `GF.UI.OpenUIForm(UIViews.Settings)` |

- 打开入口：家园 Zone 4
- 数据依赖：`WorldSession.Current.HasAttemptSave`

> 本区内容最少，但**是「设置」与「恢复」的唯一入口之一**（另一处在暂停菜单），
> 因此仍然需要出效果图，且要与暂停菜单的视觉语言保持一致。

### 2.2 恢复面板弹窗

`GlobalUI.ShowDialog`，标题「恢复维修尝试」：

| 条件 | 正文 |
|---|---|
| `HasAttemptSave == true` | 「检测到未完成的维修尝试，可继续或放弃。」 |
| `HasAttemptSave == false` | 「当前没有未完成的维修尝试。」 |

- 只有「确定」一个按钮（`ShowDialog` 单按钮）
- 详情见 `20-恢复面板.md`（正式恢复面板应有「继续 / 放弃」双按钮，本处为轻量提示）

## 6. 交互控件状态

| 控件 | 尺寸 | 状态 | 视觉变化 |
|---|---|---|---|
| 配装功能卡 | 940×160 | `normal` / `hover` / `pressed` / `disabled` | normal 底 `#262B34` + 左缘 4px 工具青；hover 底 `#333C48` + 右缘出现「▸」；pressed 下沉 2px；disabled（未进入事件时）压灰 + 副说明改为「进入事件前可调整」 |
| 恢复面板功能卡 | 940×160 | `normal` / `hover` / `pressed` / **`pending`** | `pending`（有未完成尝试）时右端出现暖铜提醒点 + 副说明改为「检测到未完成尝试」 |
| 设置功能卡 | 940×160 | `normal` / `hover` / `pressed` | 同上 |
| 恢复提示弹窗按钮 | — | `normal` / `hover` / `pressed` | `SHR-021` 主按钮 |

> **`pending` 状态是本区唯一的动态状态**，必须设计——它告诉玩家「你有一局没打完」。
> 这比单纯一个按钮更有信息价值。

## 9. 验收要点

- [ ] 三个入口的图标成套，线宽与视觉重量一致
- [ ] 功能卡方案填充了中下区域，避免大屏幕上出现「三个孤零零的按钮」
- [ ] 「恢复面板」的 `pending` 状态有明显的视觉提醒（不是只有点进去才知道）
- [ ] 设置入口的视觉语言与暂停菜单里的「设置」保持一致
- [ ] 下方场景区的插画不抢三块卡片的注意力
- [ ] 副说明文字能表达「现在能不能用」（如配装必须进入事件前）
