# 12 · 保管区与材料背包

> 对应脚本：`Assets/Game/Scripts/EverlightTales/UI/ArchivePanel.cs`
> 承载方式：程序化构建，作为家园「保管」区（Zone 3）的内容
> 策划出处：`02-系统设计/07-家园收集强化与奖励.md`、`24-材料与货币.md`、`25-加工配方与经济节奏.md`

## 1. 界面概述

保管区是**所有物的清点页**——陈列物、材料、图样、永久零件与形态。
只读展示，不产生属性或维护负担。

页面结构（无子页签，一页到底，用分组标题分隔）：

```
陈列物 → 拥有物（维修费）→ 材料（六种）→ 图样 → 永久零件与形态 → 纪念物与档案
```

- 打开入口：家园 Zone 3
- 数据源：`WorldState.DisplayItems` / `Materials` / `Blueprints` / `OwnedParts` / `UnlockedForms` / `RepairFee`

### 2.2 各分组的行内容

| 分组 | 行格式 | 备注 |
|---|---|---|
| 陈列物 | `◆ {DisplayItem.Name}（第 {ObtainedDay} 天 · {KindLabel}）` | 空时「（尚无陈列物，完成维修/怪谈后陆续出现）」，色 `#808085` |
| 拥有物 | `维修费  {RepairFee}` | 单行 |
| 材料 | `· {MaterialConfig.Name} ×{计数}` | 六种全列；计数 0 时整行压暗 |
| 图样 | `· {BlueprintId}` | 空时「（无）」，色 `#808085` |
| 汇总 1 | `永久零件与形态  {OwnedParts.Count} 零件 / {UnlockedForms.Count} 形态` | 单行 |
| 汇总 2 | `纪念物与档案  {DisplayItems.Count}` | 单行 |

**陈列物类型中文**（`KindLabel`）：维修（默认）/ 回礼（LifeGift）/ 展览（Exhibition）/ 纪念（CaseMemento）。

**材料的类型化计数**：异常纹样（`IsTypedByCase = true`）会**跨来源求和**——
`TotalMaterial` 遍历所有 MaterialStack 累加同 `MaterialId` 的数量。
因此「异常纹样 ×3」可能是「红舞鞋 ×1 + 画皮 ×2」的和。

> **设计建议**：类型化材料在保管区被合并计数，玩家看不到来源拆分。
> 建议为这一类材料增加**来源拆分展开行**（点击展开），制作时预留该状态。

## 10. Prefab 制作契约（文档确认后执行）

> 本节只描述 Prefab 制作，不生成效果图。Assets/Test 中对应的 Image 仅用于 1080×1920 PlayMode 对照验收；运行时禁止把整张对照图挂到页面上。

### 10.1 页面根节点与布局基准

| 项目 | 约束 |
|---|---|
| 设计分辨率 | 1080×1920 竖屏；Canvas Scaler 使用 Scale With Screen Size；SafeArea 内缩 |
| 页面根节点 | UIForm → SafeArea → 背景/固定层/内容层/弹窗层 |
| 对照图 | 仅用于截图对照，不作为 Prefab 子节点或运行时资源 |

### 10.2 节点树与节点职责

页面必须包含 SafeArea、Background、Header、Content、Footer、Overlay。Background 位于最底层并只绑定正式背景；Header 顶部 Stretch，包含标题、返回和状态条；Content 位于 Header 与 Footer 之间，列表只保留动态容器；Footer 底部 Stretch，按钮同一基线；Overlay 覆盖 SafeArea，默认隐藏并负责弹窗、Toast、Loading。

### 10.4 UIItem 模板与动态创建

页面 Prefab 只保存模板引用字段和动态容器，不保存重复 Item 实例。每种重复对象在 Assets/Game/Prefabs/UI/Item/<ItemName>.prefab 独立制作，根节点挂 Item 脚本和 GF UIItemObject；图标、标题、详情、数值/操作的相对关系固定。页面打开、刷新或切换分类时从对象池创建，关闭或切换页面时回收，空列表显示 Empty 节点。Item 只负责视图绑定、状态切换和事件转发。

### 10.5 正式资源接入规则

1. 每条资源必须解析为 Assets/Game/Sprites/UI 下的实际文件。
2. SHR 九宫格使用 Image.Type.Sliced；图标使用 preserveAspect。
3. 控件状态按文件名后缀绑定；缺失状态按资源表回退。
4. 资源缺失、节点缺失、节点重复或引用对照图均记入差异表。

### 10.6 制作与验收顺序

1. 按节点树创建固定节点并设置 1080×1920 锚点。
2. 按资源表绑定正式 Sprite、字体和控件状态。
3. 创建并验证 Item 模板，再接入模板引用和动态容器。
4. PlayMode 使用 1080×1920 截图，对照 Assets/Test 的 Image。

固定节点 `Panel_ArchiveTop`、五个分组标题和 `Panel_ArchiveList` 由页面 Prefab 持有；重复行全部使用 Item Prefab 动态创建。五类容器必须按“陈列物、拥有物、材料、图样、汇总”顺序存在，切换或刷新时只刷新对应容器。

|---|---|---|---|---|---|
| `ArchiveDisplayItem` | `Content_Display` | 宽度 Stretch，高 160；垂直间距 12 | `Icon` 40×40、`Txt_Title`、`Txt_Detail`、`Txt_Value` | `Assets/Game/Sprites/UI/九宫格/SHR-003-normal卡片.png`；默认图标 `Assets/Game/Sprites/UI/图标/ICO-008保管.png` | `DisplayItems`；normal/hover/pressed；只读但可打开详情 |
| `ArchiveOwnedItem` | `Content_Owned` | 宽度 Stretch，高 96；垂直间距 12 | `Icon`、`Txt_Title`、`Txt_Detail`、`Txt_Value` | `Assets/Game/Sprites/UI/九宫格/SHR-005-normal列表行.png`；部件图标按 `PartCodexCatalog` 映射 | `OwnedParts`、`UnlockedForms`；只读 |
