# 13 · 来客区

> 对应脚本：`Assets/Game/Scripts/EverlightTales/UI/GuestPanel.cs`
> 承载方式：程序化构建，作为家园「来客」区（Zone 0）的内容
> 策划出处：`02-系统设计/07-家园收集强化与奖励.md`、`03-玩家体验/02-昼夜双主线剧情.md`
> 说明：本区是**轻量入口**，不经营客流、不计算好感、不新增经营数值（设计决策 D-323）。
> 布局数值见 `09-家园五区.md` §2.2；本文档聚焦于「来客区」的素材与状态细节。

---

## 1. 界面概述

来客区承载**白天主线**的三件事：

| 模块 | 内容 | 状态机 |
|---|---|---|
| **沈遥感谢** | L-01 红舞鞋解决后的回访领取 | 未触发 / 尚未解决 / 待上午领取 / 可领取 / 感谢已领取 |
| **当天到店委托** | `Supply` 中 `PlaceId == "home"` 且未处理的实例 | 有委托 / 空态 |
| **改装支线入口** | 四条改装支线（T-G01~04）的跳转入口 | 常驻 |

- 打开入口：家园 Zone 0
- 关键交互：`session.RevisitCase("L-01")` 领取感谢；`OnNavigate(0)` 跳地图处理委托；`OnNavigate(1)` 跳任务页

**沈遥的身份**（重要，避免张冠李戴）：社区舞蹈教师，红舞鞋怪谈 L-01 的核心受害者。
不是修理铺主人，也不是玩家。立绘三态：紧绷起舞 / 能回应 / 坐下恢复。

### 2.2 沈遥感谢的五态

| 展开条件 | 状态文案 | 按钮 | 按钮色 |
|---|---|---|---|
| 案件不存在 或 `NotTriggered` | 「尚未触发」 | 不可点 | `#474747` |
| 案件 `Revisited` | 「感谢已领取」 | 不可点 | `#474747` |
| 案件 `AwaitingRevisit` 且 时段 = 上午 | **「可领取感谢」** | **可点** | `#428557` |
| 案件 `AwaitingRevisit` 且 时段 ≠ 上午 | 「待上午领取」 | 不可点 | `#474747` |
| 其他（`Investigating`/`AwaitingRepair`/`Repairing`） | 「尚未解决」 | 不可点 | `#474747` |

**行文案模板**：`沈遥感谢：{状态文案}`

**领取反馈**：
- 已领取过 → Toast「感谢已领取」
- 未到回访 → Toast「尚未到回访」
- 成功 → 刷新面板（状态变为「感谢已领取」）

### 2.3 委托与支线

**委托行文案**：`· {SupplyInstance.Template.Name}`（模板为空时回退 `InstanceId`）
**委托筛选**：`PlaceId == "home"` 且 `!Processed`
**委托空态**：`当前没有到店委托`
**去处理反馈**：Toast「前往地图处理：{名}」→ `OnNavigate(0)`（跳地图页签）

**支线提示文案**（固定）：`贯通/横推撞锤、轴向/定时线圈试机`
**任务页按钮**：`OnNavigate(1)`（跳任务页）

## 8. 验收要点

- [ ] 沈遥立绘的三种状态（紧绷起舞 / 能回应 / 坐下恢复）姿态差异明显，一眼可辨
- [ ] 立绘不遮挡下方的感谢状态行与委托列表
- [ ] 「可领取感谢」的按钮是页面内最吸引注意的元素（绿 + 外发光）
- [ ] 不可领取时的灰按钮配有**时间门控提示**，玩家能明白「为什么不能领」
- [ ] 三层信息（感谢 / 委托 / 支线）的层级与间距清楚，不糊成一团
- [ ] 委托为空时有明确空态，不出现大片空白
- [ ] 立绘的冷紫影子与暖铜主调形成本项目「暖铜 × 冷紫」的典型同框
- [ ] 白天/夜晚两版场景板的色温差异明显
