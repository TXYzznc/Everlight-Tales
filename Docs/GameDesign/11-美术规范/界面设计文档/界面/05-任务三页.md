# 05 · 任务三页

> 对应脚本：`Assets/Game/Scripts/EverlightTales/UI/JournalPanel.cs`、`JournalPages.cs`、
> `EventPageLayout.cs`、`TaskPageLayout.cs`、`CasePageLayout.cs`
> 承载方式：程序化构建，挂在主页壳内容容器（`MainPageShell.Content`）下，主页壳 Tab 1
> 策划出处：`02-系统设计/11-任务系统.md`

---

## 1. 界面概述

任务系统是一个宿主 + 三个子页签的结构：

| 子页签 | 内容 | 分组 |
|---|---|---|
| **事件** | 当前时段可处理/不可处理的普通供给事件 | 可处理 / 未到开放时段·本段已错过 |
| **任务** | 委托任务（含四条改装支线） | 进行中 / 可领奖 / 已完成 |
| **怪谈** | 已触发的怪谈档案 | 按批次分组，批次内按状态排序 |

- 打开入口：主页壳 Tab 1（任务）
- 顶部右侧常驻「维修费 {N}」余额
- 三个子页签各带角标（可处理事件数 / 可领奖任务数 / 进行中怪谈数），为 0 时不显示

### 2.1 事件页结构

```
—— 可处理 ——
  ◆ {事件名}（{N} 格）              ← 可点卡片，文字色 #EBEBEB
  ...
—— 未到开放时段 / 本段已错过 ——
  ◇ {事件名}（未到开放/已错过）      ← 可点卡片，文字色 #9EA3AE
```

卡片前缀符号：可处理用实心 `◆`，不可处理用空心 `◇`。
无内容时插入一行「（无）」。

### 2.2 任务页结构

```
—— 进行中 ——
  ● {任务名}（{CurrentStep}/{TotalSteps}）   [跟踪][定位]   ← 行 + 两个 120×44 按钮
  ...
—— 可领奖 ——
  ● {任务名}（奖励 {N} 费）                  [领取]        ← 行 + 一个 140×44 按钮
  ...
—— 已完成 ——
  ○ {任务名}                                ← 可点卡片，灰字 #9EA3AE
```

| 子元素 | 锚点 | 位置 | 尺寸 | 字号 |
|---|---|---|---|---|
| 进行中行文本 | min(0,1) max(1,1) pivot(0.5,1) | (0,y) | (−300,50) | 24，`#EBEBEB`，左对齐 |
| 跟踪按钮 | min(1,1) max(1,1) pivot(1,1) | (−160,y) | (120,44) | 22，白，底 `ButtonGreen` |
| 定位按钮 | 同上 | (−20,y) | (120,44) | 22，白，底 `ButtonBlue` |
| 可领奖行文本 | min(0,1) max(1,1) pivot(0.5,1) | (0,y) | (−200,50) | 24，`#FFFFFF` |
| 领取按钮 | min(1,1) max(1,1) pivot(1,1) | (−20,y) | (140,44) | 22，白，底 `ButtonGreen` |

### 2.3 怪谈页结构

```
—— 批次 B1 ——
  · 红舞鞋（调查中）                 ← 可点卡片，白字
—— 批次 B2 ——
  · 画皮（待维修）
```

**批次标题格式**：`"批次 " + CaseConfig.Batch`。
**状态中文**（`CaseKindText`）：调查中 / 待维修 / 维修中 / 已解决 / 待回访 / 已回访 / 未触发（不显示）。

## 9. 验收要点

- [ ] 三个子页签在缩略图下可区分（图标 + 文字 + 选中底色三重表达）
- [ ] 角标位置统一（同一相对页签的偏移），数字为 0 时不出现
- [ ] 分组标题与卡片行在视觉上有明确层级差（暖黄刻线 vs 深色卡片）
- [ ] ◆/◇/○/· 四个符号成套，线宽与视觉重量一致
- [ ] 「可领奖」的领取按钮是页面内最强的行动召唤，一眼能找到
- [ ] 事件页六筛选片等宽、间距一致，选中态明确
- [ ] 长任务名不溢出卡片（设计预留左右 20px 内边距）
- [ ] 空列表时有空状态插画或「（无）」占位，不出现大片空白
