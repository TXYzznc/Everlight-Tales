| 字段 | 内容 |
|---|---|
| 类别 | 怪谈专属挑战 |
| 玩家首次出现阶段 | S2 |

| 核心零件 | P-013 照明棱镜、P-002 计量棘轮、P-014 铆合钳；路线调整可使用 P-001、P-004 与玩家自带的第六种零件。 |

## 挑战含义

画皮挑战将“分辨真假”拆成三个可操作状态：对象真实身份、当前伪装层数与对象所在路线。真实身份在本次维修开始时固定；照明只减少伪装层，重画只恢复当前外观。玩家因此能根据已经确认的信息规划分流，而不必在每次伪装变化后重新猜答案。

本挑战使用接应口和封存口验证交付对象。错误对象进入出口时，出口拒绝接收，对象留在上一合法格，本拍照常消耗。它造成路线和拍击成本，但不会把一次错误移动直接升级为不可恢复的故事失败。

## 首次关卡的组成

L02-G01 使用以下对象：

| 对象 | 初始伪装 | 关卡职责 |
|---|---:|---|
| HUMAN 顾师傅 | 1 层 | 受困者；修复锁扣后送入接应口。 |
| SKIN 画皮载体 | 2 层 | 封存目标；第一轮结束后恢复 1 层外观，最高 2 层。 |
| ECHO 假影 | 1 层 | 照明与连锁扰动对象；不参与最终交付。 |
| LOCK 遮光帘锁扣 | `0/1` 维修进度 | P-014 使用公共维修能量修复后开启接应口。 |

三轮把它们依次组织为：照明三名对象一次、修复锁扣并让载体伪装归零、救援顾师傅并封存载体。完整布局、分数、随机范围、局内奖励和结算见对应关卡文档。

## 可复用接口

后续关卡或再发案件可以复用本挑战的以下字段，而不改变其基本语义：

| 字段 | 说明 |
|---|---|
| `identity` | `human`、`carrier`、`echo` 等真实身份。实例创建后不可改写。 |
| `disguiseLayers` | 当前伪装层数；由照明去层或重画加层。 |
| `revealedRecord` | 是否已被照明记录过；重画不清除。 |
| `rescueExit`、`sealExit` | 出口位置、开启条件和允许交付的身份。 |
| `repairObject` | 与出口、照明或帷幕关联的待维修对象及其 1～5 点进度。 |
| `repaintTiming` | 重画发生的轮次、目标、层数上限与停止条件。 |
| `echoVariant` | 是否生成、移动或扩散假影；首次关卡只使用固定数量的一个假影。 |

后续变体可增加伪装层、改变照明区域、加入假影扩散或让出口开启条件变化。它们必须在具体关卡中分别写明，不能用“画皮挑战”这个名称默认启用。

## 2D 表现

- 三名对象共享同脸基础立绘；照明后以衣袖补痕、接缝、倒影缺失和名称标签展示差异。
- 伪装层数以半透明面纱图标和短暂的重绘闪动表示。
- 出口拒绝交付时，门框闪出身份校验符号，对象回到上一合法格。
- LOCK 修复完成时，后间门、接应口和店内光源同时切换到开启状态。
