# 失败分支索引 v1.0

> 2026-09。按 D-023 要求汇总"来源事件 → 失败分支 → 后续入口"。结论：第一版当前**没有任何已设计的剧情失败分支**；所有条目要么按 D-022 轻量结案，要么按"无分支 → 保留重试"，怪谈按 D-024 恢复本次维修起点。新增失败分支必须按[统一事件管理设计草案](统一事件管理设计草案.md)的字段单独登记，并回填本索引。

## 口径回顾

| 规则 | 适用 | 失败／撤退后续 |
|---|---|---|
| D-022 | 可重复且与剧情无关的普通事件 | 本实例轻量收尾结案，同类以后仍可生成新实例 |
| D-023 | 剧情相关普通事件 | 有已设计失败分支则进入分支；无则保留任务并提供重试 |
| D-024 | 怪谈维修 | 恢复本关开始前状态，回到待维修，保留调查与已成功前关 |

剧情相关事件必须先标"是否有失败分支"，尚未设计不能声称已有分支（D-023）。

## 结论与维护

- 当前 0 条剧情失败分支；所有"失败后续"都是"重试"或"结案"，不产生新的失败支线事件。
- 若未来为某事件设计失败分支（如"改用纸质资料与人工讲解"），必须登记：失败分支标识与名称、来源事件与触发、失败收尾、后续入口、影响与衔接、耗时、原目标是否返回，并同步回填本索引与[任务系统](../02-系统设计/11-任务系统.md)对应条目。
- 本索引不含"高分收益""档案重放"等长期候选，它们不是失败分支。
