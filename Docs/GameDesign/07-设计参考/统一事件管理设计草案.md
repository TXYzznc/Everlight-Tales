## 任务系统入口与事件刷新

任务系统面向玩家分为三个入口：

| 入口 | 记录内容 | 可以执行的操作 | 奖励处理 |
|---|---|---|---|
| 事件 | 当前昼夜阶段可交互的地图事件 | 查看概要、地点、预计耗时与状态；定位到地图对应位置 | 在事件现场结算 |
| 任务 | 主线任务与玩家成长相关支线 | 查看目标、进度、前往地点与领取已完成任务的奖励 | 在任务页领取 |
| 怪谈 | 已触发怪谈及当前调查、维修或回访阶段 | 查看已知线索、阶段名称、阶段进度并定位相关地点 | 不在怪谈页领取，由对应人物后续互动交付 |

事件页是地图内容的快捷索引，不代替地图交互。玩家必须定位到地图上的事件地点，才能开始调查、维修、交谈等处理。查看事件页和定位地图不消耗时间，开始处理后按事件配置结算时间。

普通事件以昼夜交替为刷新边界。进入白天或夜晚时生成该阶段的普通事件；处理完成的实例立即结算并从当前列表移除，未处理实例在下一次昼夜交替时被新一批实例替换，不记为失败。同一事件模板可以在以后生成新的实例。

任务与怪谈产生的关键事件不进入普通事件刷新池。它们在未完成时持续保留；若当前时段、地点或前置条件不允许处理，则显示暂不可处理及已知开放条件。怪谈一经触发永久等待，不因昼夜交替消失。

主线在剧情触发后自动进入任务页；支线只有在地图现场互动并接受后进入。任务奖励完成后由任务页领取，怪谈奖励由对应人物在后续互动中交付。正式页面、状态和内容配置见[任务系统](../02-系统设计/11-任务系统.md)。

## 管理对象与层次

统一管理案件的发现、调查、待维修、维修尝试、完成、回访与奖励。区分持续存在的案件档案和一次可成功、撤退或中断的维修尝试。不同怪谈可有不同调查数量和维修阶段，不强制统一三段关卡。

案件档案保留已获线索、已完成调查、触发资格、故事完成、回访和奖励领取记录。维修尝试保留本次初始条件、携带池、盘面、临时资源、阶段状态及结果。最终故事完成只记一次；批次不等回访或领奖。

## 推荐的案件流程

未发现 → 已发现线索／调查中 → 待维修 → 维修中 → 已解决。

发现入口可以来自白天或夜晚，允许短路径直接确认异常进入待维修。未达批次资格时只保留允许出现的铺垫，不提前触发完整怪谈。回访可用与奖励可领取作为完成后的独立记录，避免领奖状态阻挡下一批。

待维修永久保留；不同已触发案件可并存。同一案的多条入口合并进同一档案；档案重玩独立于真实故事状态，不重复发首次奖励。

## 已确认：明确维修前基准（D-020）

“维修前”指玩家本次点击开始维修、进入盘面前，而不是最近一次拍击或当前小阶段开始。进入前保存案件现场初始状态；在一次连续维修中，操作结果按现有规则持续演变。

主动撤退时，案件回到待维修：保留此前调查和已读资料，回退本次盘面、本局Buff及尚未最终结案的阶段推进。再次开始可以重新配装，不必重跑调查。这里的回退属于本次作业进度恢复，不在剧情里解释成时间倒流。已正式完成、记入案件档案的救援不被日后档案重玩撤销。

红鞋的分离与封存属于同一关时，分离后撤退就恢复本次维修起点，重试从导流开始。若未来某案明确分成数次独立维修，每次分别配置预计耗时与初始状态，已完成的前一次维修可以保留。不能由系统自动把每个阶段都当独立维修。

## 结果与尚待讨论项

| 行为／结果 | 已定结果或当前建议 | 待定细节 |
|---|---|---|
| 怪谈成功 | 按本案成功条件记录解决，批次计一次；回访独立 | 奖励具体发放环节按单案确认 |
| 怪谈撤退 | 已确认恢复维修前并等待重试；基准为本次开始维修前 | 随机种子、外带消耗品；扣时按D-021统一执行 |
| 可重复、非剧情普通事件失败／撤退 | 本实例失败结案，呈现轻量收尾，同类可继续出现（D-022） | 文案、经济后果与刷新配置；扣时按D-021统一执行 |
| 剧情相关普通事件失败／撤退 | 有失败分支进入分支，无分支保留重试（D-023） | 逐项列出具体分支、后果与后续入口 |
| 怪谈维修判定失败 | 显示失败原因，统一耗时，恢复本次维修前并等待重试（D-024） | 外带消耗品、重试随机条件及具体保存实现 |
| 关闭程序／掉线 | 暂停本次尝试，按轮存档恢复，不当主动撤退 | 轮存档与轮间奖励的先后及恢复显示 |

事件尝试结束的时间结算与现场回退分别处理，按D-021，时间不会因为现场复原而返还。高分收益仍暂缓。

## 后续统一设计的交付结构

用户要求整体架构稍后集中设计。本轮不继续拆散新增架构决定。正式设计将用一份总图和一组相互对应的表，说明：事件类型与案件／尝试的关系；发现至回访的状态与转移条件；时间、进度、盘面与资源的保存范围；成功、失败、撤退、中断的结果；地图投放及批次资格；奖励领取与档案重玩。以红鞋和一个普通维修事件贯穿示例，检查各流程能否闭合。

案件与尝试分层，失败按关重试，事件结果统一扣时；外带消耗品与重试随机条件待设计。

## 第二轮已确认：事件耗时与结果无关（D-021）

处理事件消耗该事件配置的游戏时间，成功、失败、撤退只是结果状态，不分别计价。

| 事件耗时 | 成功 | 失败 | 撤退 |
|---|---|---|---|
| 1格 | 1格 | 1格 | 1格 |
| 2格 | 2格 | 2格 | 2格 |
| 3格 | 3格 | 3格 | 3格 |
| 4格 | 4格 | 4格 | 4格 |

进入前查看、加工、配装及取消进入不耗时。开始处理后，无论最终结果如何，都在本次尝试结束时统一结算该事件时间；不按现实停留时长、拍击次数、成功与否或撤退早晚改变耗时。中断恢复的是同一次尝试，不产生额外事件或重复扣时。

例如夜晚剩1格，处理一个4格怪谈：成功、失败或撤退后均进入深夜且剩1格。成功保存案件解决结果；撤退恢复本次维修前现场、保留调查并等待重试。结果处理与时间结算分开。

信息卡只显示事件预计耗时和预计结束时段，不增加失败／撤退耗时栏。怪谈重试属于新的一次处理，重新消耗该次事件配置时间。

## 第三轮已确认：可重复普通事件失败后结案（D-022）

适用于与剧情无关、可无限次出现的普通事件。本次失败或主动撤退后，依次结算事件时间、呈现失败收尾、记录本实例结案；具体界面播放顺序可在统一架构中整理。失败收尾只产生较小影响，之后同类事件仍可正常出现。

区分可反复使用的事件内容与每次发生的实例。同一“卷帘门维修”内容可以生成不同地点、委托人或时间的订单；每张订单有自己的结果，结束后不重新打开原单。也可以再次遇到相同地点和设备，但需以新的故障或新的委托说明这次发生的事情，不能无说明抹去旧结果。

失败的结束是玩家看得到的结果：简短说明本次没有修好、对方如何暂时应对，再返回地图。不会凭空把失败记成修好，也不以永久封店、居民离开、切断服务或全城恶化作为这类日常事件的默认后果。

### 失败收尾文案试稿（待评阅）

| 事件 | 收尾示例 | 本次结果与后续 |
|---|---|---|
| 卷帘门维修 | 店主看了看卡住的门：“看来今天修不好了。我先走侧门，明天再联系人看看。辛苦你跑一趟。” | 本单失败结案；交代临时通行方式，不永久关闭商店。以后可出现新的门具维修委托 |
| 普通设备堵料 | 负责人关掉开关：“这台先停一会儿，我换备用机。今天就先到这里吧。” | 本单失败结案；设备未被虚构修好，现场有替代办法，同类事件继续投放 |
| 非剧情找物 | 居民收起手电：“还是没找到啊。我再去问问失物招领处，谢谢你陪我找。” | 本次寻找失败结案；不由此引出重大损失或永久关系破裂，后续找物为新实例 |

这些例子仅示范结果呈现，不预设失败报酬、退款、罚款或信誉数值。普通日常收尾不强行衍生怪谈。普通事件统一在昼夜交替时刷新；同类模板何时再次被抽中仍由地点条件和投放权重决定。

剧情关联性与可重复性需在事件条目中明确，不能仅靠EV-01～EV-04类别推断：一次普通维修也可能承担剧情，不能误用本节规则使其线索永久丢失。剧情普通事件按下文D-023处理。

## 第四轮已确认：剧情普通事件有分支走分支，无分支可重试（D-023）

本次处理失败或主动撤退 → 结算本事件完整耗时并记录失败 → 检查已配置失败分支。

- 有失败分支：展示相应收尾，进入设计好的后续路径。原事件没有被改判成功；原目标是否以后还能恢复，由该分支明确，不默认同时给原事件重试按钮。
- 没有失败分支：保留剧情任务与此前已得资料，提供重新处理入口；再次处理是新尝试，重新消耗事件配置时间。已读委托说明可跳过。

进入失败分支不是自动完成分支内全部事件；后续可处理的新事件按各自配置展示并消耗时间。失败本次与后续成功分别记录，避免重复发首次奖励。

### 后续单项文档必须单列的失败设计

| 字段 | 填写要求 |
|---|---|
| 是否有失败分支 | 明确有／无；尚未设计不能声称已有分支 |
| 失败分支标识与名称 | 有分支时单独列出，能够追溯到对应正文；标识格式在统一架构中整理 |
| 来源与触发 | 原事件及具体失败结果；多个失败结果指向不同路径时分别列出，撤退按失败处理 |
| 失败收尾 | 当事人反应、当前事件怎样结束、为何出现后续 |
| 后续入口 | 指向下一事件或明确剧情结果；未立即可参与时说明开放条件 |
| 影响与衔接 | 人物／世界变化、线索、主线进度和奖励；不得无说明视作原任务成功 |
| 耗时 | 原尝试照常耗时；后续每个可处理事件分别配置 |
| 原目标是否返回 | 明确分支是否以及怎样重新开放原目标，避免自动同时提供重试和分支 |

汇总文档后续提供失败分支索引，按“来源事件→失败分支→后续入口”列出已实际设计的条目。当前没有因为本轮确认自动新增任何现有故事的正式失败支线。

### 说明示例（仅试稿）

修复展播放设备维修：若没有失败分支，失败后陆宁说明设备留待再次维修，提供重试；若正式设计了“改用纸质资料与人工讲解”分支，失败后就进入该分支。两种配置并非在同一次失败后由系统临时任选。示例尚未写入正式展览剧情，具体支路需独立设计。

## 第五轮已确认：怪谈维修判定失败（D-024）

状态：用户“同意”确认本轮方案。D-020已确认主动撤退恢复本次维修起点；D-024将该起点用于判定失败，不修改各案现有胜败条件。

怪谈判定失败与主动撤退共用恢复起点：结束本次尝试，结算事件完整耗时，呈现与失败原因对应的反馈，然后案件返回待维修。恢复本次维修开始前的现场，清除本次未最终结案的阶段推进和临时盘面变化。一次连续维修不自动保留已通过的小阶段；已正式完成的独立维修仍按原记录保留。

保留此前调查、人物交流，以及本次确实获得且已写入档案的规则／线索信息。失败不自动揭示尚未发现的隐藏规则，也不把整份攻略解锁。未获正式成功的救援、完成计数和通关奖励不提前发放。永久收藏与已确认剧情结果继续保留；外带一次性物品消耗另行讨论。

失败反馈对应具体原因，说明本次尝试为何中止；案件不被记为永久失败，不删除怪谈或阻断批次。再次处理从同一维修节点开始，可以重新配装；重试布局和随机种子尚待决定。时间已经结算，不随现场恢复返还。程序中断仍恢复同一次进行中的尝试，不作为失败。

例：红鞋导流失败使束缚达到本案阈值。反馈显示“持续运动未能导出，本次分离失败”，本次维修结束并消耗配置时间。案件回到待维修，下次从导流开始；已读调查和已获得规则说明保留。若分离、封存属于同一次连续作业，即使后段失败也从这次作业起点重来。不能一边登记沈遥已正式获救、一边在重试时又把这个正式结果撤销。

本案永久等待意味着跨日不丢失处理机会，不等于取消盘面上的失败条件。失败画面是本次挑战的反馈，世界结果只有在正式结案时记入；具体台词不能提前宣告与可重试基准矛盾的永久死亡或城市结局。

怪谈失败按当前关重试；剧情普通事件的失败分支按D-023配置。

## 拍击、轮、关与完整怪谈（D-029）

- 一次拍击：提交方向，完成一次运动与连锁。
- 一轮游戏：一关内部的一个维修阶段，由若干次拍击完成相应阶段目标；不单独扣地图时间，不作为失败重试起点。
- 一关游戏：一次独立维修事件，通常是一个晚上能够完成的连续现场处理，可包含多轮。每关独立配置耗时；成功、失败、撤退均结算本关完整时间。
- 一个怪谈：从线索到最终解决的完整故事。通常核心维修为一关；若故事需要第一晚维修后继续寻找线索、在后续日期再次维修，则分为多关。每关分别记录成功，全部必要关卡及最终故事目标完成后才记整案完成。

“一个晚上”描述通常的内容跨度，不增加夜尽强制失败或截止时间；既有跨时段完成、怪谈永久等待继续有效。单关失败后隔天重试仍是同一关，不因日期变化成为多关。

每关失败或撤退后，从该关第一轮重新开始；此前成功关卡与已取得调查信息保留。关内已过轮次不自动保留为重试点。程序中断继续同一次尝试，不作为失败。

关间调查若为独立事件，按自身配置耗时；准备、加工、配装、查看已有资料不耗时。整案耗时为实际处理的各次事件耗时之和。轮数、每轮拍击数、轮间补给和盘面继承的具体配置依各案设计，不由术语对应自动固定。

例：第一晚第一关成功 → 后续调查 → 另一晚第二关。第二关第三轮失败，仅恢复第二关第一轮，完整扣除第二关本次耗时；第一关的成功和关间已完成调查保留。具体十五案如何分关、分轮仍需逐案标注。

## 中断恢复补充（D-032）

异常退出或关闭游戏按轮存档恢复当前关的同一次尝试，恢复存档记录的棋盘、分数、拍击额度及相关资源；恢复资源取自该轮存档，地图时间按同一次尝试结算。具体轮存档点与轮间奖励的先后仍需细化。正常失败、主动撤退仍从当前关第一轮重试，已成功前关保留。
