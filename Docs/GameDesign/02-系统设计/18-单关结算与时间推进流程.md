# 单关结算与时间推进流程 v0.1

> 2026-09-15。本页补完“单关结算与时间推进”模块：一次维修的三种终局与一种中断、结算面板结构、发奖与记录时点、事件时间的一次性推进、跨时段与跨日处理、结算与世界刷新之间的顺序。轮内流程见[盘面与每拍奖励流程](17-盘面与每拍奖励流程.md)，过关判定见[共用语义与配装](08-零件挑战共用语义与配装.md)，时间格与供给见[地图供给与事件开放](15-地图供给与事件开放.md)。数值与文案待试玩。

## 这一页解决什么

一关维修在最后一拍结算时同时产生五件事：本关胜败、本局资源与盘面的去向、事件记录与世界结果、游戏时间推进多少、接下来玩家去哪里。如果这五件事各自决定，很容易出现重复扣时、重复发奖或失败后世界状态已经前进的矛盾。本页把它们固定成一次事务，按确定顺序执行一次。

## 三种终局与一种中断

| 结果 | 判定 | 盘面与现场 | 记录与奖励 | 时间 |
|---|---|---|---|---|
| 成功 | 最后一轮拍数用尽，累计分数达标且全部特殊目标完成 | 盘面收束，现场按本关成功状态改变 | 写入本关结果与关卡奖励；怪谈多关时保留案件进度 | 按本关完整耗时推进一次 |
| 失败 | 拍数用尽仍未达标，或命中即时失败条件 | 现场按失败状态变化，不使用血腥与怪物表现 | 按事件类型分流；本局盘面变化与本局Buff不保留 | 按本关完整耗时推进一次 |
| 撤退 | 玩家在暂停菜单选择放弃本关 | 回到本关开始前的现场状态 | 与失败同样占用时间与尝试记录，文案区分 | 按本关完整耗时推进一次 |
| 中断 | 关闭程序或异常退出 | 保留当前盘面 | 不判胜败，不发奖 | 不结算，恢复后继续同一次尝试 |

失败与撤退的区分只在文案、人物反馈与记录标注上，时间、奖励与重试口径相同。中断不是终局，不进入结算面板。

## 成功结算

成功先判定、再演出、最后展示面板，避免玩家在演出中途看到数字跳变。

- 本关成功但案件仍有后续关时，案件记录停在维修中，下一关入口写入案件页与地图；本关盘面、分数与本局Buff随本关结束清空，不带入下一关。
- 本关成功且案件全部解决时，案件转为待回访，通关奖励不在面板直接发放，由对应人物按故事安排在后续互动中交付；面板只预告这件后续。
- 普通事件与试机成功时，奖励在结算面板内即时结算并显示明细，不留待回访。

## 失败结算

失败面板必须让玩家知道差在哪里，不接受只显示维修失败。面板至少给出三项中的实际命中项：

- 累计分数与目标分的差额。
- 每一项未完成特殊目标的当前进度。
- 命中的即时失败条件及其触发者。

失败后的分流按事件类型配置：

| 事件类型 | 失败与撤退后续 |
|---|---|
| 可重复且与剧情无关的普通事件 | 本实例轻量收尾结案，同类以后仍能生成新实例 |
| 剧情相关普通事件 | 有已设计失败分支则进入分支，没有则保留任务并提供重试 |
| 怪谈 | 恢复本关开始前状态并回到待维修；已完成的调查与前关结果保留，本关重试从第一轮开始 |
| 试机 | 恢复到试机现场，可重新借用同一样机再试 |

再次处理时重新进入准备页并重新配装，按本关完整耗时再结算一次。

## 撤退结算

撤退由玩家在暂停菜单主动选择，判定与失败一致：本关未完成，记录本次尝试，时间照常推进。怪谈撤退恢复本关开始前状态并等待再次维修；普通事件按上表分流。

撤退面板写清本次已经推进的时间，以及案件或任务当前停在哪个可重新进入的位置。

## 中断恢复

关闭程序或异常退出不判定胜败、不结算时间、不消耗奖励，恢复本次尝试。

存档点只设三处：开始一次维修时写入本次尝试与初盘；每轮结束时更新轮次、盘面、分数、资源与已取得的Buff；结算与时间推进全部完成后写入世界存档。因此中断最坏情况是把已经确定的结算重放一遍，不会重复扣时或重复发奖。

## 时间推进

时间推进是结算事务的最后一段，按本关配置耗时一次性推进 N 格。

- 事件开始前显示预计耗时与预计结束时段；开始后不按现实操作时长、拍击次数或是否撤退改变耗时。
- 关内轮次不逐轮扣时，整关结束时统一结算。
- 剩余格数不足时照常开始，结束后统一结算超出部分。例如夜晚剩 1 格、本关耗时 3 格，结束后进入深夜并剩 2 格。
- 恰好用完一段时直接进入下一段，深夜之后进入次日上午，时间格重新补满。
- 跨段只展示结束时段仍然有效的供给，不为跨过的时段补发事件或播放未发生的失败。
- 一次性事件与调查按各自的配置耗时推进，和维修关互不替代；整案不额外叠加扣时。

## 结算与世界更新的顺序

结算事务按固定顺序执行，实现时保存本次结果与时间结算标记，防止中断后重复执行：

1. 写入本次事件结果：成功、失败或撤退，物件与人物变化，关卡完成情况。
2. 按本关完整耗时推进游戏时间，确定结束时段与剩余格数。
3. 用新的剧情状态与结束时段更新资格：跨昼夜时生成下一批普通供给与下一批怪谈资格；只跨上午与下午、夜晚与深夜时保留同批实例。
4. 更新持续关键事件的开放状态与人物位置。
5. 展示结算面板，玩家确认后返回城市地图；不自动高亮、跟踪或开始后续入口。

第 3 步先应用世界结果再刷新供给，避免生成已经被剧情排除的普通事件。

## 结算面板结构

三种终局共用同一骨架，只替换内容，玩家不需要为每种结果学习一套界面。

| 段落 | 成功 | 失败 | 撤退 |
|---|---|---|---|
| 结果段 | 本关名称与完成状态、现场收束表现 | 失败原因与现场表现 | 撤退说明与现场恢复表现 |
| 成绩段 | 各轮得分、累计分、目标分、特殊目标完成情况 | 目标分差额与未完成特殊目标进度 | 已完成轮次与本轮停在何处 |
| 收获段 | 维修费与物品明细、解锁内容、案件进度变化 | 无奖励时写明本次无报酬 | 无奖励时写明本次无报酬 |
| 时间与后续段 | 本次耗时、结束位置、下一步入口 | 本次耗时、重试入口或失败分支入口 | 本次耗时、重试入口 |

底部只保留一个主按钮，避免玩家在结算页反复取舍。

## 配置字段

| 字段 | 用途 |
|---|---|
| 本关完整耗时 | 事件详情与结算面板显示 |
| 关内轮数与各轮通过条件 | 失败原因定位到具体轮次 |
| 即时失败条件与文案 | 失败面板的即时失败项 |
| 成功、失败、撤退三种现场状态 | 结算前后的现场表现切换 |
| 关卡奖励与交付方式 | 即时结算或留待人物回访 |
| 案件后续关入口 | 成功后的下一步 |
| 失败后续类型 | 轻量结案、失败分支或重试 |
| 结算面板文案覆盖 | 具体事件的自定义表述 |

## 验收检查

- 一次维修只推进一次时间，成功、失败、撤退同价，中断不推进。
- 失败面板能读到分数差额、未完成特殊目标进度与即时失败条件。
- 怪谈失败与撤退从本关第一轮重试，此前成功关卡与调查信息保留。
- 可重复普通事件失败后本实例结案，同类事件之后仍能出现。
- 结算与世界更新按固定顺序执行，中断重放不会重复扣时或重复发奖。
- 跨时段与跨日结算后，地图只展示结束时段仍然有效的供给。
- 多关怪谈成功一关后不清除案件进度，也不提前发放通关奖励。

## 待试玩

- 结算面板的演出时长与信息密度，连续多关时是否需要更快节奏。
- 时间推进的跨段提示形式，怎样让玩家既看清又不需要反复确认。
- 失败原因在分数与特殊目标同时不达标时的呈现顺序。

## 已确认（D-080）

- 本关结算后主按钮回到城市地图，不高亮、不自动跟踪，玩家自行选择下一步。
