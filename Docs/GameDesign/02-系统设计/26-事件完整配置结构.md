# 事件完整配置结构

每个可处理事件都是一次完整的内容单元。事件文档必须把玩家为什么前往、怎样处理、耗时、世界如何变化以及得到什么，一次写清。维修费、材料、图样、怪谈形态、线索和收藏等奖励只在对应事件的结果中配置。

本结构用于普通地图事件、主线和支线任务步骤、调查、非盘面小任务、下盘维修，以及怪谈的调查关、维修关和回访。它不规定所有事件都必须有盘面、奖励、失败分支或多步骤；没有的项直接标注无。

## 一、事件、任务与怪谈的关系

| 名称 | 含义 | 记录位置 | 与其它对象的关系 |
|---|---|---|---|
| 事件模板 | 可被创建和处理的一次内容定义，写明触发、内容、时间、结果与奖励 | 对应事件库或怪谈文件夹 | 一个模板可生成多次普通事件实例，也可只服务一次剧情推进 |
| 事件实例 | 当前地图上实际出现的一次可处理内容，保存地点、开放状态、随机结果与处理结果 | 运行时状态与事件页 | 普通事件在昼夜交替时替换；关键事件持续保留 |
| 任务 | 持续记录玩家目标和进度的外层条目 | 任务页与任务库 | 可要求完成一个或多个事件；任务奖励在任务页领取 |
| 怪谈档案 | 一条已触发怪谈的长期故事记录 | 怪谈页与怪谈文件夹 | 由调查、维修、回访等多个事件共同推进；奖励由人物后续互动交付 |

一个事件可以推进任务或怪谈，也可以独立结束。一个怪谈不等于一个事件：单关怪谈由一个维修事件构成；多日、多关怪谈按阶段配置多个独立事件，每关分别消耗时间、分别重试。

## 二、每份事件文档的固定结构

### 1. 基本资料

| 字段 | 要写清的内容 |
|---|---|
| 事件ID与名称 | 全局唯一ID、玩家可见名称、所属库或怪谈档案 |
| 事件类型 | 地图交互、非盘面小任务、调查、普通维修、临时处置、怪谈阶段、回访或其它实际玩法类型 |
| 一句话目的 | 玩家此时为什么到这里，以及完成后直接改变什么 |
| 地点与地图标记 | 所在地点、地图坐标或节点、使用的图标和地点状态 |
| 关联人物与表现 | 出场人物、立绘状态、对话节点、场景底图、可复用动画或音效；无额外资源时写明以对话和既有状态表现 |
| 关联记录 | 关联的任务ID、怪谈ID、前后事件ID、资料或档案条目 |

### 2. 出现、开放与持续规则

| 字段 | 要写清的内容 |
|---|---|
| 出现方式 | 昼夜刷新候选、剧情创建、资料台索引后现场确认、前置事件完成后出现，或其它明确方式 |
| 开放时段 | 上午、下午、夜晚、深夜中的可处理窗口；错过窗口后是等待下次窗口、昼夜替换，还是持续可处理 |
| 前置条件 | 已完成事件、任务进度、怪谈批次资格、角色状态、地点解锁、拥有或借用条件等；分别写出全部条件 |
| 可重复规则 | 可重复模板、一次性剧情步骤、可回访内容或一次性领奖；普通事件还要写刷新批次和候选权重 |
| 并存与排斥 | 能否与其它事件同时存在；同一人物、地点或状态被占用时如何显示和恢复 |
| 玩家可见信息 | 地图、事件页、任务页、怪谈页分别显示的名称、预计耗时、已知线索、开放限制和状态 |

普通事件必须写明昼夜替换规则。主线、已接受支线、怪谈及其调查、维修、回访事件必须写明持续规则，不能因为普通供给刷新而消失。

### 3. 进入后的内容与步骤

按实际处理顺序列出步骤。每一步都写清玩家做什么、使用什么表现、是否消耗时间、成功如何进入下一步；只读查看、准备、配装、加工和关卡预览为零时间操作，不写成处理步骤。

| 步骤字段 | 要写清的内容 |
|---|---|
| 步骤名称与目标 | 此步要达成的具体事情，例如核对记录、交还物件、找到断点、完成一关维修 |
| 交互形式 | 对话选择、地点调查、物件交付、小游戏、六相定势盘维修或组合；明确玩家可操作的内容 |
| 盘面配置 | 仅下盘步骤填写：关数、轮数、每轮拍击数、目标分数、特殊效果、特殊目标、固定与随机元素、初盘、借用零件、携带限制、规则、维修对象和奖励池配置 |
| 时间消耗 | 成功、失败、撤退分别消耗几格；多步骤事件逐步标记并给出总耗时与跨时段结果 |
| 状态保存 | 已完成的调查、交付、盘面关卡或准备是否保留；重试从哪一步、哪一关或哪一轮开始 |
| 叙事反馈 | 立绘、对话、场景状态、动画、广播或音效怎样反映这一步结果 |

下盘维修使用独立的维修关配置。每个维修关写明准备页预览中可见的固定部分，以及进入局内才生成的随机部分；随机与固定由具体字段逐项指定，不按地形、零件或维修对象强制划分。

### 4. 结果、状态变化与奖励

每个结局分别填写成功、失败、撤退；没有某项时写无。奖励与后果在此处随结果配置，不能拆到独立掉落表。

| 结果字段 | 要写清的内容 |
|---|---|
| 达成条件 | 哪些步骤、盘面目标、选择或状态满足后进入该结果 |
| 时间结算 | 此结果消耗的时间格、是否跨时段、事件结束后世界刷新顺序 |
| 状态变化 | 事件实例、任务、怪谈阶段、NPC、地点、地图标记、档案、家园陈列和后续事件资格的变化 |
| 重试或结束 | 普通可重复事件失败后本实例结束；剧情事件按是否有失败分支进入分支或保留重试；怪谈维修失败或撤退回到本次维修前，等待再次开始 |
| 奖励内容 | 维修费、材料及数量、图样、形态解锁资格、线索、关系、收藏、家园状态或其它实际产出；写明每项数量、是否首次限定、何时发放 |
| 发放位置 | 现场立即结算、任务页领取、NPC后续交付或只改变记录；与任务和怪谈既有领奖规则一致 |
| 收尾表现 | 对话、立绘状态、场景变化、失败文案或离场反馈 |

同一奖励如果存在首次完成、重复完成、失败、撤退等不同结果，必须逐个写明。没有奖励的事件也要写明其提供的线索、状态变化或叙事回报。

## 三、盘面维修关的附表

只要事件包含六相定势盘，就在事件文档后附一张维修关表。每个独立维修关单独一行或单独小节；跨多日怪谈的不同关不能共用一份未分段的配置。

| 字段 | 要写清的内容 |
|---|---|
| 关卡ID与关名 | 关联事件、是否是怪谈的第几关 |
| 进入条件 | 完成的调查、携带或借用要求、开放时段 |
| 预计耗时 | 成功、失败、撤退的时间格；跨时段后的地图状态 |
| 轮次 | 每轮拍击次数、目标分数、特殊效果、特殊目标；分数与盘面跨轮继承，跨关清零 |
| 固定配置 | 预览可见的地形、规则、初始特定零件、维修对象、位置和表现 |
| 随机配置 | 进入局内才决定的地形、挑战、零件、维修对象或位置；候选池、数量、合法落点和随机约束 |
| 维修与挑战 | 待维修对象的进度、所需维修零件提示、公共维修能量来源、障碍、异常、失败条件和规则反应 |
| 局内奖励 | 每拍或换轮奖励池、候选数量、叠加规则、落点和满盘处理；局内奖励只在本关有效，除非结果栏另行写入永久产出 |
| 结局衔接 | 成功、失败、撤退后回到事件的哪一个步骤和世界状态 |

## 四、事件文档的完成检查

一份事件达到可进入制作排期前，至少能回答以下问题：

1. 玩家在什么条件下、什么时段、什么地点看到它。
2. 玩家为什么愿意处理它，处理中实际做什么。
3. 每一步和每种结果分别消耗多少时间，跨时段后什么会刷新。
4. 如果包含盘面，固定和随机内容分别是什么，关、轮、分数、特殊目标和维修对象怎样配置。
5. 成功、失败、撤退各自结束、重试或分支到哪里，世界哪些记录改变。
6. 玩家从每种结果得到或失去什么，奖励在何处发放。
7. 地图、事件页、任务页、怪谈页和家园各自如何同步显示。

## 五、文档归档方式

- 可重复普通事件：放入[普通事件库](../09-普通事件库/00-索引.md)，每个模板独立成文，并在总览列出刷新、耗时、结果和奖励。
- 主线、成长支线与其步骤：任务总览记录目标、进度和任务领奖；每个实际处理步骤按本结构记录，可放在[任务库](../08-任务库/00-索引.md)或关联地点的事件文档中。
- 怪谈：怪谈文件夹的总览保留故事、阶段和总奖励；每个调查、维修、回访阶段按本结构独立成文，完整盘面配置附在对应维修阶段中。
- 共用规则只放系统设计、零件库、挑战库或规则库。具体事件只引用共用条目，并写明本次使用的对象、数值、随机范围和结果。
