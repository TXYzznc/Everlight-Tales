# 零件与挑战组合场景 v0.1

> 以下是设计推演与机制观测脚本，不是已经运行的游戏测试。先隔离少量对象观察事件，再放入完整盘面与随机初盘试玩。完整规则见[共用语义](08-零件挑战共用语义与配装.md)及[规则库](04-怪谈规则库.md)。

## 场景一：两次爆破拆开同一隔板

使用 [爆破线圈](../04-零件库/01-通用零件/P-003-爆破线圈.md) 与 [脆裂隔板](../05-挑战库/01-障碍设施/O-002-脆裂隔板.md)。

机制观测摆放：线圈甲(0,0)，乙(0,1)，隔板(1,0)，耐久2。甲乙与隔板均相邻。观测脚本先暂停基础定势，只施加一次对甲的冲击，以检查爆破命中范围和队列；实际关卡再用夹持座固定爆点、撞锤碰撞安排起爆。

1. 甲起爆，隔板受一次冲击，耐久剩1；乙收到待执行的受击。
2. 乙起爆，同一隔板再受一次独立冲击，耐久归零移除。
3. 恢复基础定势移动后，上游零件可进入缺口；下一拍破口保持。

关键选择是提前拆路，还是保留隔板聚集更多零件。检查不能把同一个爆破的重复回调计成两次伤害，也不能把两次独立爆破合并成一次。

## 场景二：把前一拍的飞轮留给后一拍

使用 [蓄能飞轮](../04-零件库/01-通用零件/P-011-蓄能飞轮.md)、[夹持座](../05-挑战库/01-障碍设施/O-005-夹持座.md) 和爆破线圈。

飞轮固定在中心，蓄量初始0。前拍安排两次独立碰撞，蓄量到2；拍末不清零。下一拍调整两枚线圈到飞轮射线能触达的位置，再给第三次碰撞，飞轮第三次受击支付1点零件能量并扣3蓄量，射线触发爆点。

玩家可以立刻释放，也可以先用夹持座稳定位置、等待更好布局。检查飞轮不会因为跨拍丢掉准备成果，电池可补零件能量，但不直接补蓄量或代替第三次受击。

## 场景三：把回声凑成三敲，截住第四敲

使用 [叩击音叉](../04-零件库/01-通用零件/P-015-叩击音叉.md)、[回声区域](../05-挑战库/02-棋盘异常/A-003-回声区域.md)、[回声簧（花子形态）](../04-零件库/02-怪谈形态/M-010-回声簧（花子形态）.md) 与 [花子挑战](../05-挑战库/03-怪谈专属挑战/C-014-花子三敲与回应窗口.md)。

初始门计数0，回声区域剩1额度；音叉甲位于区域内，乙在区域外，二者声音路径都接真实第三间。

1. 甲发出真实声，计数1；派生回声随后到达，计数2。
2. 乙的真实声到达，计数3，打开本拍回应窗口。
3. 后段铆合请求送出夏夏。若还有音叉丙，会产生第四声；给丙装回声簧并预设截留，就把这声留到以后。

代价来自真实选择：提前截留乙的声，则本拍只有两声、窗口不开。改装改变信号时机，不凭空增加敲击数；线路分叉后同根仍只计一次。

## 场景四：把扫帚供水变成排水与能量

使用 [扫帚挑战](../05-挑战库/03-怪谈专属挑战/C-009-扫帚供水与劈分失控.md)、[排水叶轮](../04-零件库/01-通用零件/P-016-排水叶轮.md)、[接力电池](../04-零件库/01-通用零件/P-020-接力电池.md)。

初始积水2，两扫帚各供1份水，叶轮初始4充能，两条水路均接入同一叶轮。

| 事件 | 积水变化 | 叶轮余能 | 获得维修能量 |
|---|---|---|---|
| 第一份来水进入并排水 | 2＋1－2＝1 | 3 | 2 |
| 第二份来水进入并排水 | 1＋1－2＝0 | 2 | 2 |

这一拍水被控制住且获得4能量，但扫帚还未停止，故事尚未成功。主动劈分会使下一拍供水者更多，也更快消耗叶轮充能。电池可以延续排水，停止架则真正减少供给源。

分流泵只改变水去向。输入1份时不能给两端各1份；若配置1:1，余量流向预选端。检查必须区分水位、维修能量、零件工作充能三种计量。

## 场景五：静默区先运货，超载场再爆发

使用 [静默区](../05-挑战库/02-棋盘异常/A-004-静默区.md)、[交换拨叉](../04-零件库/01-通用零件/P-009-交换拨叉.md)、[超载蓄势场](../05-挑战库/02-棋盘异常/A-006-超载蓄势场.md)。

线圈在静默区承受冲击不消耗、不爆炸；拨叉把它换到区域外，再给新的受击才起爆。在另一区域，三件可充电器械各执行一次令场热达到3，消耗一枚过载芯，器械获得补能。三枚芯用尽后场转静默，玩家可把这里重新当作安全运送爆点的区域。

检查抑制发生在能力实际执行时；旧受击不会在出区时补放。充电不算新受击，也不应自激增加场热。

## 场景六：缓冲库存有来处，也有去处

使用 [画像挑战](../05-挑战库/03-怪谈专属挑战/C-010-画像代偿与负荷卸载.md)、[缓冲囊](../04-零件库/01-通用零件/P-017-缓冲囊.md) 与铆合钳。

取初始P=5、Q=1，囊容量3。先将2份设备负荷转入囊，再将剩余可接收的1份转入，P降为2、囊内3、Q仍为1。囊向明确设备卸载口分两次排出2份和1份，三份记入已处置废热。此后关闭新增转嫁、完成封框。

这是可耗散设备冲击的具体处置，不表示任何故事代价都能排掉。若不经卸载而直接移除缓冲囊，负荷必须回原接收端，不能消失。检查转移与处置记录守恒，封框条件与原LR对应，不能只检查盘上物件变少。

## 后续真实试玩记录

每次测试记录内容版本、C案、P/M/O/A清单、初始布局与种子、本关携带池、关键事件序列、最终目标状态，以及玩家实际采用了哪条路线。重点比较连续准备是否有价值、连锁高潮是否成立、失败是否能解释。上述脚本通过文档推演不能替代真实操作、手感与随机可解性验证。
