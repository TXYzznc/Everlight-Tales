# 四时段与刷新流程 v0.1

> 2026-09-15。本页补完“四时段与刷新”模块：时段条呈现、时间格读法、开始前的耗时预告、结算后的跨段表现、昼夜刷新的界面反馈与主动等待。时间规则、供给权重与刷新顺序见[地图供给与事件开放](15-地图供给与事件开放.md)，结算事务见[单关结算与时间推进流程](18-单关结算与时间推进流程.md)，本页只写玩家看到什么、点什么、系统提示什么。

## 这一页解决什么

时间在这个游戏里只有两种变化：处理完一件事之后一次性推进，或者玩家主动等待到下一时段。玩家需要随时知道四件事：现在处于哪个时段、这一段还剩几格、手头这件事要做多久、做完之后会落在哪里。本页把这四件事固定成常驻显示与固定提示，让跨段与跨日不产生意外。

## 时段条

顶部常驻一条时段条，四个时段横向排列，当前时段高亮。

| 位置 | 显示 |
|---|---|
| 左侧 | 当前时段名与第几天，例如“第3天 · 下午” |
| 中部 | 上午、下午、夜晚、深夜四格时段名，当前项高亮 |
| 右侧 | 本段剩余格数，例如“剩2／4” |

白天两段与夜晚两段用底色区分，中间保留一条昼夜分界。时段条在打开地点、事件详情、准备页与结算面板时都可见；进入局内维修后时段条收起，本次预计耗时与结束位置在暂停菜单查看。

## 时间格的读法

每段4格是当前试配。时间格在界面上有两种表达，按信息量分工：

- 时段条右侧只显示本段剩余格数，让玩家一眼看到今天还能做多少事。
- 事件卡与事件详情显示“预计耗时：N格”和“预计结束：某时段”，让玩家在开始前就知道这次要做多久、会落在哪里。

剩余格数不足时照常可以开始。事件详情在耗时预告旁补一句结束位置，例如“本次共3格，结束后进入深夜，剩2格”；恰好用完整段时显示“结束后进入夜晚”。

## 开始前的耗时预告

事件卡与事件详情都带耗时预告，玩家在比较去处时就能看到。开始按钮上方固定显示三项：

- 本次处理预计耗时N格。
- 处理结束后的时段与剩余格数。
- 本次是否跨昼夜；跨昼夜时提示普通事件会随交替刷新。

确认后进入现场或准备页，预告数值冻结，不随现实操作时长变化。开始前返回或取消不消耗时间。

## 结算后的跨段表现

时间推进发生在结算事务里，界面负责把结果讲清楚。结算面板的“时间与后续段”固定给出三项：本次耗时、结束位置、下一步入口。

- 同段内结束：显示“本次2格，下午剩1格”，不加额外提示。
- 跨到下一段：显示移动后的时段名与剩余格数，例如“结算后进入深夜，剩2格”。
- 跨昼夜：在时段移动提示后补一行刷新说明，例如“进入夜晚，普通事件已更新”；不逐条列出退出与新增的事件。
- 跨日：显示“第4天 · 上午，时间格已补满”。

跨段提示只出现一次，停留在结算面板的时间段内，不弹出二次确认。玩家确认后回到地图，地图上的时段条与事件列表已经是推进后的状态。

## 昼夜刷新的界面反馈

进入白天或夜晚时刷新一批普通实例。刷新在结算或等待之后自动完成，界面按三处更新：

- 地图主区：普通事件图标与数量角标更新；退出实例的图标消失，新实例的图标点亮。
- 事件页：普通事件列表替换为新一批，页签显示一次未读角标。
- 地点详情：地点当前事件列表按新一批更新；已解锁地点与人物位置保持。

未处理的普通实例随昼夜交替退出，退出不播放失败表现，也不发送提示。同一模板以后仍能生成新实例。主线、已接受支线、怪谈、关键调查与等待中的回访不参与这次替换，继续保留。

上午与下午之间、夜晚与深夜之间只更新开放状态：原本未到开放时段的事件变为可处理，只在上一段开放且已错过的事件显示为已过期窗口。整批普通实例保持不变。

## 主动等待

地图底部常驻“等待到下一时段”按钮。等待只推进时间：地图内容按刷新规则更新，未处理事件与奖励保持原状；加工、配装、资料查看与档案馆在等待前后都免费可用。

点击后先显示确认面板，包含三段信息：

| 段落 | 内容 | 示例 |
|---|---|---|
| 去向 | 将进入的时段、第几天、补满后的格数 | “进入夜晚 · 第3天，时间格补满为4” |
| 普通事件 | 跨昼夜时列出将随交替退出的未处理普通实例数量与名称 | “2个普通委托将在入夜时退出” |
| 保留内容 | 继续保留的关键内容摘要 | “红舞鞋待维修、修复展筹备保留” |

确认后推进时段，提示形式与结算跨段一致。同昼等待只更新开放状态并给出新时段名；跨昼夜等待额外说明普通事件已更新。等待期间玩家可以随时打开任务、怪谈与资料页查看，不受时段变化影响。

## 关键事件的窗口等待

每个关键事件在自己的详情里显示开放时段。当前不在窗口时，事件卡显示下一次开放时段，例如“下次可处理：上午”；地图保留灰色入口与原因。

错过的关键事件按下次窗口再次开放，不因等待消失。怪谈永久等待，跨日与跨时段都不改变其待维修状态。以上状态在任务页与怪谈页长期保留，事件页负责当前是否可处理。

## 免费操作与时间的关系

以下操作不消耗时间格，也不触发刷新：查看地图、地点详情、任务三页、资料索引与档案馆；加工、配装与形态切换；打开准备页、预览关卡与返回；主动等待前的确认操作。

处理事件才消耗时间：现场交谈、调查热点、维修盘与回访事件都在结算时按该事件配置推进。准备页确认后进入局内视为开始处理，中断恢复继续同一次尝试，不重复结算。

## 配置字段

| 字段 | 用途 |
|---|---|
| 每天时段数与每段格数 | 时段条与时间格显示 |
| 时段名称、昼夜归属与底色 | 时段条与昼夜分界 |
| 事件开放时段列表 | 事件卡、地点详情与窗口等待提示 |
| 事件预计耗时 | 开始前预告与结算时间推进 |
| 跨昼夜是否刷新普通供给 | 结算与等待的刷新判定 |
| 等待确认面板文案 | 去向、退出实例与保留内容 |
| 刷新提示文案 | 昼夜交替的一次性提示 |
| 关键事件窗口原因文案 | 灰色入口与下次开放提示 |

## 验收检查

- 时段条常驻显示当前时段、本段剩余格数与昼夜归属。
- 事件在开始前显示预计耗时与预计结束时段，剩余不足仍可开始。
- 结算与等待只在结束时推进一次时间，跨段与跨日给出明确落点。
- 昼夜交替刷新普通实例，上午与下午之间、夜晚与深夜之间保留整批实例。
- 未处理普通实例退出不播放失败表现，关键内容不被刷新删除。
- 主动等待的确认面板说明去向、将退出的普通实例与保留内容。
- 免费操作不消耗时间，也不触发刷新。

## 待试玩

- 时段条在移动端的可读性，四段名与格数是否改用更简的图标表达。
- 跨段提示的文案长度，连续跨段时是否打断节奏。
- 等待确认面板列出实例名称还是只给数量。
- 玩家对“开始前预告、结束后结算”的心智模型是否成立。
