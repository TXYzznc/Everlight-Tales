## 已确认决策

1. **统一范围**：所有可能涉及 UI 绑定的页面、弹窗、局部 View、Item、Editor 工具和 UI Prefab 全部纳入；当前没有明显问题的界面也必须迁移或通过统一契约校验。
2. **运行时契约**：运行时代码优先使用 Prefab 上的序列化引用；复杂区域由独立 View 组件持有内部引用。节点改变父级不应影响绑定。
3. **路径查找边界**：`Transform.Find` 等固定路径查找不得作为运行时功能依赖，只允许存在于明确的 Editor 迁移、自动绑定或诊断逻辑中。
4. **依赖隔离**：必选列表依赖与可选详情依赖分开校验；详情字段缺失不得阻断列表生成；错误必须包含组件、字段和预制体定位信息。
5. **实施方式**：按照界面逐个处理，每个界面完成代码、Prefab 引用、Editor 校验、编译和运行验收后再处理下一个；禁止未经审阅的批量自动改写。
6. **验收入口**：保留并扩展现有 UI 深度审计、页面烟雾测试和 Prefab 验证，增加“移动节点后引用仍有效”和“删除必选引用时明确失败”的验证场景。

## 分层契约

- 页面 Form/Panel：只持有页面级 View 引用和数据刷新生命周期。
- 局部 View：只持有自身的文本、图片、按钮、滚动容器和详情字段引用。
- Item View：只持有条目内部引用，向上层发出选择/操作事件。
- Editor Validator：在编辑阶段检查契约完整性，不替代运行时业务逻辑。

## 实施顺序

1. 完成代码与 Prefab 全量清单，并生成可追踪的审计报告。
2. 建立通用 View 引用校验基础设施和迁移模板。
3. 逐个迁移高风险页面，优先 `Home/Workbench`，随后按清单处理其他页面。
4. 逐个迁移弹窗和 Item 预制体。
5. 迁移 Editor 工具，删除运行时对固定层级的隐式依赖。
6. 运行全量静态审计、编译、页面烟雾测试和编辑器验证。
