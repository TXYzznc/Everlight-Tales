# 真实试玩与数值校准设计

## Context

P6-001/002/003。b48 的 LevelCalibrationRunner 只取 Rounds[0] 并枚举六种固定相位，其“可解率”是受限策略结果；b56真实奖励和机械臂路线证明存在可通路径，但不能代替随机奖励覆盖和人类试玩。先完成 b65 以免视觉占位干扰理解结论。

## Goals / Non-Goals

让统计与实际玩法一致，用可复现对照选择参数。教学、红鞋首关、卷帘门、一天经济成长/现有试机奖励在首发范围内；不新增玩法、玩家招募系统或遥测后台，不私自联系参与者。

## Decisions

### 1. 自动演算是受限策略评估

| 方案 | 优点 | 代价 | 选择 |
|---|---|---|---|
| 沿用六方向首轮统计称可解率 | 最快 | 结论失真 | 不采用 |
| 走真实多轮操作的确定性策略回放 | 可复现、可与玩家轨迹对照 | 非穷举，不证明无解 | 推荐 |
| 全状态穷举求解器 | 可作形式可解判断 | 分支爆炸，超出收尾范围 | 不采用 |

演算通过正式领域输入/规则执行，包含全部轮、轮间奖励、真实候选和选择、机械臂合法移动、定势与结算；不直接注入分数、指定不存在Buff或改棋盘以通关。策略接口明确动作预算与选择规则，可回放真实玩家输入。不能覆盖的功能报告 Unsupported，禁止算作失败或自动补成功。

默认建议固定100个种子（0～99）分别运行基线和候选，相同初始状态/RNG/策略预算。覆盖三教学、红鞋三轮、卷帘门；记录策略成功率、轮次/目标失败原因、剩余拍数、分数/耗时、奖励选择、输入步数及异常。分母是有效运行数，Unsupported/运行错误单列；“策略未找到”不称无解。相同种子重复结果应一致，抽取失败种子能在Editor重放。

### 2. 基线与候选隔离

基线记录有效源表版本/哈希，红鞋现行 StepsPerTap=1保留。候选优先对比1步与历史3步意图；在独立配置副本或测试覆盖层运行，不在玩家正式存档中混用。一次只改变一组相关参数，完整记录原因和前后值。红鞋3轮各3拍、30/100/170目标和导流6等先作为基线，不因校准表允许范围而自动调动全部。

CalibrationTable 是候选边界与报告入口，不是新运行时覆写权威。20/格收费、配方等已确认规则属于约束：可分析收入节奏，但修改规则/边界须另列明确候选由用户确认；不得将表的上下限当授权。进入正式配置的候选先经用户选定，再定向改源表并生成受影响产物，复跑基线回归；不包括全库round-trip治理。

### 3. 人工试玩与选择门槛

建议首轮至少5名未接触该版本的玩家，由用户提供/安排；人数和日期可在执行时确定。样本不足时仍可整理自动报告和现有反馈，但人工验收保持未完成。人工在Editor固定分辨率执行即可，不要求暂缓的移动端包。

记录匿名编号、是否首次、版本、路径、操作/卡点、提示次数、失败重试、通关/放弃、主观理解与节奏反馈；不收集姓名联系方式。任务：新档三教学→红鞋→卷帘门→一天循环/成长/回访，并观察现有试机奖励。记录自然奖励，禁止教导指定BF014路线后把结果称独立通关。

验收判断：零阻断崩溃/档损/重复结算；每个参与者关键卡点都有归因及处理决定；同一无提示教学理解障碍在2人及以上复现则必须修正或由用户明确接受；不强设未经研究的80%通关目标，也不把5人结果推广总体。参数报告须列“保留/修改/需更多样本”的理由。推荐候选不能出现新增确定性规则故障，不能靠无依据加奖绕过问题。

### 4. 交付证据

提供基线/候选参数表、100种子报告、可重放失败轨迹、匿名试玩表、改动理由与候选批准记录。若结论是保持现值也可合格，前提是真实证据齐全。人工体验欠缺不能用AI演算补填。

## Risks / Trade-offs

- 玩家资源不可用 → 自动部分继续，准确标记人工待验；不伪造参与者。
- 视觉可读性误判为难度 → b65先通过，再按卡点分类处理。
- 参数升级损坏未完成尝试 → 配置指纹变化按b58兼容策略处理，在b67复验。
- 小样本过拟合 → 基线/候选同种子对照，人工观察仅作为首轮证据。

## Migration Plan

先升级演算和报告口径，再冻结基线、执行对照与人工试玩，形成参数建议；用户选择后落表并回归。候选未批准不改正式数值。回退配置源和对应生成物成组，快照版本/配置不兼容走既定降级，世界进度保留。
