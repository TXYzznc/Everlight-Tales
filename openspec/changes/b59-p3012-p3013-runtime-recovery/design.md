# 正式世界写入与恢复流程设计

## Context

原任务：**P3-012、P3-013**，同属 G3；实施前置为 b58。三轮共识见 D-324，完整方案已获开始执行授权，当前正式恢复接线实施中。

现有三个槽位使用 PlayerPrefs；slot 1 沿用旧键，slot 2/3 插入槽位编号。`RecoveryPageForm` 和 `ServicePanel` 的恢复操作为占位，`RestoreFirstCaseProgress` 把维修中转成待维修，`WorldSaveService` 与实际保存字段不完全一致。正式可运行维修入口核对到卷帘门和红鞋；试机当前有服务/探针，不据此声称所有试机 UI 已接通。

## Goals / Non-Goals

**Goals:** 正式选档后安全恢复；真实继续/撤退；三槽隔离；损坏降级；将 b58 日志的绝对结果正确提交到原世界档。

**Non-Goals:** 不新建试机/档案玩法入口，不改变教学零耗时规则，不提供逐拍快照，不扩展十四案，不把 P6-004 或 G6 整体验收并入本批。

## Decisions

### 1. 世界档不迁移，适配器集中拥有键清单

复用现有 `WorldSession.Save/Restore` 的编码方式，收敛一个可枚举的槽位键注册表与映像适配器。映像只包含该槽位的业务键，禁止枚举/覆盖全部 PlayerPrefs（音量、其它槽位及框架设置都不属于结算）。受控字段明确类型、缺失/删除状态；`remainingCells`、slot meta、firstCase/places 不遗漏。新增必要的 `GenerationId`、`WorldRevision`、提交凭据和结算后供给/随机持久字段；新字段缺失有兼容默认值。

映像从最终候选世界状态生成，覆盖当前保存项及结算实际影响项，包括材料来源、任务进度、陈列、成功维修数、首案状态和地点。对当前未持久化但会受结算影响的供给实例、随机消费及事件处理状态补字段，避免重启再次供应已处理实例。涉及的编码和字段清单先做显式盘点，不使用过时 DTO 替换实际运行数据。

提交步骤沿用 b58：检查槽位/世代/预期修订 → 写全部受控绝对值及删除项 → 保存 → 验证结果 → 写提交凭据并保存 → 再验证 → 清理。凭据至少包含尝试号、目标修订、结果校验值；不能仅凭一个 bool 认定所有世界键已成功写入。未完成时禁止其它世界写入和切换至可操作地图；失败可重试或返回选档，不能让普通 `Save()` 覆盖候选状态。

候选比较：分散在每个奖励服务写防重标记改动大且易漏项；迁移整个世界 JSON 超过已确认范围；选择集中键映像适配，保留 PlayerPrefs 和现有世界语义。

### 2. 启动状态机和优先级

```text
选定槽位 -> 校验槽位世代/加载配置 -> 对账结算日志与提交凭据
        -> 读取已一致的世界档 -> 检查活动尝试主/备
          ├ 有效：显示恢复页（继续 / 放弃）
          ├ 无：正常进入（旧维修中无快照沿用可重试回退）
          └ 损坏/不兼容：隔离、无罚回到可重试状态并说明
```

不得在日志对账前运行普通恢复逻辑、刷新供给或把 `Repairing` 改回 `AwaitingRepair`。只在所有对账完成后发布可交互 `WorldSession.Current`，防止旧 UI 保存半恢复状态。已提交且快照仍残留时只做清理，不显示继续/撤退；更旧日志不得覆盖更高世界修订。日志与冗余均不可读时按 b58 极端损坏规则保留已有世界数据，不猜测处理。

恢复页沿用 GF.UI 与现有预制体，展示关卡、轮次和“回到本轮开始”的明确提示；从备份恢复更早轮次时展示实际轮次。关闭恢复页返回选档，保留待恢复尝试，不隐式撤退。地图和服务入口共用同一恢复协调器，删除占位 Toast/假成功路径。

### 3. 继续、撤退与写失败

继续必须重建正确事件类型、冻结携带、Buff、随机状态与专属目标，补回 `CurrentEvent`/`CurrentRedShoeLevel` 等一致引用后打开正式盘面，不调用新的确认入场、不重抽初盘、不重播开场、不重复轮初补给。恢复选择本身不写终局，也不删除快照。

放弃先确认完整耗时，只把选择提交一次给 b58 结算协议；成功保存终局后清理尝试并返回地图。反复点击、页面关闭和重开不产生新事务。I/O 失败时保留原状态与文件，明确提示重试，不显示“已放弃”。同一次撤退重试使用相同尝试号与结果。

无罚降级只结束无法恢复的活动尝试，不修改长期奖励/费用，不调用撤退服务；保留调查与已成功前关，重进关卡才创建新尝试。禁止将已有成功提交凭据的旧快照当成无罚重试机会。

### 4. 覆盖边界与生命周期

| 入口 | 本批验收范围 |
|---|---|
| EV-N01/经相同正式链启动的普通维修 | 首轮恢复、形态/目标状态、成功/失败/撤退、跨时段与供给结果 |
| 红鞋首案 | 三轮所有轮起点、轮间奖励、红鞋导流/分离/修匣/封存、成功后回访与防重 |
| S0 教学 | 保留现有段完成进度与零耗时重试；不伪造普通维修的收费恢复，不额外新增教学快照机制 |
| 准备/对话/调查/交付 | 不写维修尝试；取消准备不残留新尝试，已有世界进度按原契约保存 |
| 试机/档案重放 | 不新增当前缺失的正式入口；所有现有可到达入口须在实施盘点时列明并验证不会借此重复获奖，独立服务不可误认成普通维修 |

一个槽位世代最多一个活动尝试。回调持有 session/slot/generation/attempt 身份，旧拥有者失效即拒绝。继续/撤退等待操作时禁用重复按钮；关闭页面、切换槽位取消未开始的动作，但不能取消到一半后把已持久提交当作没发生。文件提交若在执行，先完成或进入可重试状态，再允许同一槽位新动作。

删除/覆盖新档先使旧世代失效并持久记录删除状态，阻止旧回调写回，再清理该槽位世界键及活动文件/备份/日志，完成后才展示空槽。中断后继续清理；其它槽位不动。隔离材料不自动作为新档输入。首次升级仅补身份字段，不搬迁 slot 1 的旧键。旧全局 attempt.json 无明确槽位绑定时不自动套用。

### 5. 验收方式

先测 b58 读写/状态对照和 b59 绝对结果提交，再从正式 Launch/选档执行真实维修。故障注入点覆盖日志准备前后、世界字段写入中、保存后/凭据前、凭据后/清理前和清理失败；重启后验证绝对数量与预期一致。测试运行不得直接注入成功分数、目标完成或奖励结果来冒充可玩验收。

保存测试前备份三个槽位键及相关目录，结束在 finally/清理入口恢复；证据包含步骤、输入、原始日志、关键截图和预期/实际值。仅保留必要的临时测试数据，不提交用户进度。编辑器结构修改停止 Play Mode 后走正常编译；不以 FSR 代替编译。

## Risks / Trade-offs

- 世界保存字段散落 → 枚举当前编码、读写/删除共用清单，验证槽位1旧键和其它槽位隔离。
- 首案恢复路径有旧回退 → 分开“存在有效尝试”和“旧档无尝试”分支，不能为了兼容吞掉新快照错误。
- b58 与 b59 分阶段 → 先批准再按依赖实施，联合正式运行通过后才能报告第一项完成；不给台账自动打勾。
- 无罚恢复可回退一轮 → 已确认按轮保存的取舍；复原随机消费，已提交结果禁止再次参与。
- 真机/发布和既有纯度问题暂缓 → 只报告 Editor 验证范围与已知限制，不关闭整个 G6；不借存档修复顺带处理暂缓项。

## Migration Plan

兼容旧世界键，逐槽惰性补身份；无快照旧档继续原行为。先完成 b58，再接入本批适配器和启动路由，最后全链验收。新档删除中断和旧回调必须作为迁移回归。开发回退保留备份并先处理未完成日志，不能在有未决事务时直接启用旧实现。

## 实施补充（2026-10-14）

提交凭据采用一个JSON值包含修订、尝试号和结果校验，避免三键间中断；旧字段读取仅兼容。普通终局四选一候选和领取状态进入runtime映像，重启先返回待选结算；领取本身用独立结果日志提交。准备页和轮奖励页增加会话/选择对象/尝试身份核对；世界修改在变更前阻止冲突操作。
