# 提案：碰撞与触发语义 + FIFO 能力事件队列（P1-005、P1-006）

覆盖任务：P1-005、P1-006。

## 目标

在 Events 层实现盘面事件链的两项基础：

1. **碰撞与触发语义（P1-005）**：从盘面结算日志的碰撞事实解析触发——新碰撞判定、单次触发、静止相邻不重复、推落回新触发、原子事件，与 SR-002 一致。
2. **FIFO 能力事件队列（P1-006）**：能力事件入队／取出／即时结果，同对象同事件只处理一次，新触发入队尾，队列顺序可复现。

## 前置

b06（P1-003 六相旋转 + P1-004 拍击结算事务）已完成并验收；`TapSettlement` 已在结算日志中产出 `Collision` 事实（移动方→被撞方）。

## 验收边界

- FIFO：入队顺序=取出顺序，新触发入队尾，不插队；顺序可复现。
- 去重：同一触发源（SourceId）的同一事件类别（Kind）在一次结算内只入队一次。
- 碰撞触发：每条 `Collision` 事实产生恰好一个触发（单次触发）；静止相邻不产生触发。
- 推落回新触发：被推开再落回形成角色反转（A→B 再 B→A）时，两条触发各自保留。
- 原子事件：每条碰撞对应一个即时结果（能力接入前收益为 0）。
- Events 层仍零引擎依赖（`verify_project_assemblies.py` 通过）。

## 关键决定

- 能力事件队列用 `FifoAbilityEventQueue` 实现 `IAbilityEventQueue`，去重键 `(SourceId, Kind)`（D-098）。
- 碰撞触发语义用 `CollisionTriggerResolver` 从 Board 结算日志 1:1 映射（D-099）。
