# 维修轮起点快照与结算结果日志设计

## Context

原任务：**P2-010、P2-011、P2-012**，同属 G2。D-324 的三轮选择已确认，本文已获整套方案开始执行授权，实际进度见tasks.md与verification.md。

当前 `RepairSaveService` 只保存部分实体、分数、Buff 和随机消费数；未覆盖地形、端点、异常区域、完整实体状态与红鞋对象。`SettlementTransaction._settled` 和事件实例状态均只在内存中。正式世界档实际由 `WorldSession.Save()` 写 PlayerPrefs，不能用字段不全的 `WorldSaveService` DTO 直接替换。动机与非范围见 [proposal](proposal.md)。

## Goals / Non-Goals

**Goals:** 完整恢复轮起点；按槽位隔离；结算结果可持久化且可重复提交；给 b59 提供稳定的读取、校验、恢复及提交契约。

**Non-Goals:** 不保存连锁播放中间帧/轮内每拍，不迁移世界存档，不实现声音事件/A-003/A-007 或改动首案数值；不把测试探针通过等同正式恢复交付。

## Decisions

### 1. 已确认的候选比较

| 存档候选 | 优点 | 代价 | 选择 |
|---|---|---|---|
| 世界 PlayerPrefs + 分槽 JSON 尝试 | 保留旧档，维修数据可版本化与备份 | 要处理跨载体一致性 | 第1轮选定 |
| 世界与尝试全部 JSON | 文件事务集中 | 全量迁移、回归扩大 | 不采用 |
| 全部 PlayerPrefs | 单一载体、键管理集中 | 大快照和损坏隔离不便 | 不采用 |

第2轮选定有效备份优先、均不可恢复则无罚重开；不采用技术故障自动扣撤退耗时，也不因单个尝试坏档锁死整个槽位。第3轮选定结算绝对结果日志；相比逐项操作流水，集中修改提交边界，避免每个奖励服务都引入持久操作编号。

### 2. 分层与接口

| 位置 | 拟承担职责 |
|---|---|
| Data | 不含引擎/运行时对象的身份、版本、状态枚举与提交契约 DTO |
| Board | 完整盘面/轮起点 DTO，红鞋与实体状态导出/恢复；不接文件或 PlayerPrefs |
| Events | 扩展 `RepairSaveService` 捕获/重建，保留 Buff 与事件语义；不直接写磁盘 |
| Meta/Save | 版本信封、校验、分槽文件读写、备份与隔离；泛型载荷或字符串，不引用 Board/Events |
| UI | `WorldSession` 协调事件、槽位、文件服务及世界适配器，GF.UI 只显示状态/转发动作 |

接口语义：`CaptureRoundStart`、`RestoreRoundStart`；文件层 `Read/WriteCheckpoint`、`Read/WriteJournal`、`Quarantine`；提交适配器 `CaptureWorldImage`、`ApplyWorldImage`、`VerifyAppliedImage`。名称可在实现时按现有约定调整，但输入必须包含槽位、世代、尝试身份，结果须区分成功、不存在、不兼容、损坏、I/O 失败；禁止 bool 吞掉错误。b59 实现正式 PlayerPrefs 适配与启动调用。旧 `world.json/attempt.json` 接口保留给原调用者，不自动认领无槽位身份的旧文件。

### 3. 文件身份和安全写入

运行时根目录来自 `Application.persistentDataPath`，不写机器固定路径。逻辑布局为 `Save/slots/<1..3>/<generation>/attempt.json`、`settlement.json` 及各自 `.bak`；临时文件与目标同卷，写完关闭并校验后替换。隔离文件置该槽位隔离目录，保留原因；日志只输出身份/状态，不输出完整存档。世代由 b59 管理，删除/新建槽位后不可匹配旧世代。

信封包含 `SchemaVersion`、`Slot`、`GenerationId`、`AttemptId`、`CheckpointSequence`、`SavedAtUtc`、载荷校验值。尝试另有事件/实例/关卡键、尝试类别、开始时间/原耗时、配置兼容指纹。实例 ID 不得仅使用 EV-N01 或固定关卡键；每次确认入场生成新身份，继续沿用原身份。

备份是上一份已验证的提交点；允许恢复更早的轮起点并明确提示，不声称一定是最新轮。不得从其它尝试、世代或槽位挑选备份。写首轮失败不能开放操作；写新轮失败停在过渡状态，重试同一份已确定载荷，不重新抽奖励或再次应用轮初补给。

### 4. 完整快照与写入时机

| 数据组 | 必须保存或可证明确定性重建的内容 |
|---|---|
| 关卡身份 | 类别、事件实例、关卡键、配置指纹、冻结携带/临时形态、时间费用上下文 |
| 棋盘 | 半径/几何、地形、端点标签、固定与动态实体、实体 ID 分配状态、判定需要的移动来源 |
| 实体 | 类型/位置/能量与容量、固定/锁定、维修进度、障碍状态、形态、待爆拍、蓄能/复制/存料/伪装等现有行为字段；实施前逐字段核对 |
| 异常与特殊目标 | 已实现异常区域范围/计数/开关、目标定义绑定与进度；未实现行为不在本批补玩法 |
| 红鞋 | 坐标/方向、已访问导流格集合、分离/束缚/封存、修匣进度及其它影响下一拍的状态；它不是普通实体，须独立载荷 |
| 会话 | 当前轮、轮初拍数/目标/分数、公共维修能量、机械臂次数、相位、连续拍序、Buff 及层数、随机种子/消费数 |

采用显式 DTO，不序列化 Unity 对象、配置对象引用、字典私有字段或事件队列。恢复所有落位/ID/类型/数值并检查返回值，未知 Buff 不再静默跳过；不可完整解释即返回不兼容。静态数据只在对应指纹匹配时按配置重建，动态覆盖以快照为准。指纹只覆盖该次尝试实际依赖的规则/配置，不因文案或图片变化废档。

写入时机：确认入场、完成初盘生成后且首拍前；轮间四选一全部处理、下一轮及轮初增益应用一次后且下一拍前。轮内退出回到该轮起点；奖励选择未完成时仍恢复上一轮起点，随机状态同步回退。不重抽初盘、不再次运行会消耗随机的初始化。恢复后第一段相同输入的演算结果必须与未退出基线一致。

### 5. 结算结果日志协议

```text
冻结操作 -> 从当前状态计算候选结果（不写世界档、不发布奖励 UI）
         -> 写入并验证 Prepared 日志及同结果冗余副本
         -> ApplyWorldImage（b59，写绝对值）
         -> VerifyAppliedImage + 持久提交凭据
         -> 清理该次尝试的主文件/备份与日志
         -> 释放操作并展示已确定的结算结果
```

日志含槽位/世代/尝试号、前置世界修订、目标修订、终局原因、结算前受控字段映像、结算后映像及校验值、展示摘要。记录准备与文件替换失败时不得修改 PlayerPrefs 或判定结算完成；允许重试相同结果。候选结果应在独立状态上计算；如果复用会改内存的现有服务，必须在隔离副本执行，失败不能污染正式会话。

结果映像是结算影响的世界字段绝对值及删除操作，不是“加 40 金币/减 2 时间格”的命令。包括时间剩余格、货币/材料、案件/地点、任务/计数、陈列、结算后的供给身份/随机状态，以及实际发生变化的持有/形态等；以 b59 的键清单为准。五步顺序保持结果→时间→资格/供给→人物位置→面板，修复当前 `Save()` 先于 `RefreshSupply()` 的覆盖缺口，不重设计供给规则。

重放遇到相同尝试与目标修订时写同一结果，不执行原奖励逻辑；更新过的世代/更高修订不得被旧日志覆盖。只有所有受控字段与目标校验匹配且提交凭据可持久化后才清理尝试文件；清理失败保持提交完成状态、阻止启动新尝试，重试清理不重发奖励。提交后的陈旧备份不能被当作可继续盘面。

### 6. 降级和版本边界

启动优先处理结算日志/提交凭据，再处理活动快照；b59 编排。有效已准备结算即使关卡版本变化也按已记录结果提交，不重新按新配置算奖。仅活动尝试主/备均不可恢复时执行无罚结束：保留已持久化长期结果，将该尝试的“维修中”标记恢复为可重试状态，不调用撤退扣时/成功发奖。

结算日志损坏先读相同事务的验证副本。若日志与副本也均损坏，保留当前世界字段和问题文件，提示结算恢复受损；不猜测补奖/追扣、不重新执行旧事务。此极端数据丢失不承诺恢复已丢失的原子结果，需与一般盘面快照损坏区分。未知新版本拒绝解释，绝不自动覆盖原始文件。

## Risks / Trade-offs

- 快照漏字段 → 逐字段清单、恢复前后状态摘要、相同输入的下一拍对照，覆盖红鞋和定时形态。
- 两载体非原子 → 日志在前、绝对值幂等提交、匹配世代/修订、写入期间禁止其它世界变更。PlayerPrefs 不具备可宣称的数据库事务保证；本批证明 Editor 故障注入与重启语义，不宣称真机断电测试通过。
- 后续障碍/异常新增状态 → 后续批次必须同步版本与快照测试；不能只添加运行时字段。
- 首轮/换轮写盘开销 → 只在稳定边界写入，不在 Update/拍击连锁里序列化；大小按最大现有盘面验证。Unity API 在主线程；若引入异步 I/O，必须绑定拥有者/世代并等待提交，不允许迟到写回。
- 与 b59 集成的依赖 → b58 的 G2 契约由适配器测试与正式入场/换轮调用证明；完整选档恢复在 b59 验收，不提前关闭整个维修恢复事项。

## Migration Plan

1. 审阅批准后先扩快照/存储/结果日志接口，保留现有世界键与原文件 API；无尝试文件的旧档正常读取。
2. b58 验证快照与协议；b59 接正式 PlayerPrefs 提交及恢复 UI，再执行端到端验收。
3. 禁止在未解决的日志存在时回退到旧客户端继续游戏。开发回滚前先备份测试存档并清理测试事务，不删除用户真实进度；旧客户端不承诺读取新尝试文件。
4. 运行验证使用临时测试槽位数据并备份/恢复 PlayerPrefs 和所有关联文件，不把测试通过写成用户槽位的真实进度。

## 实施补充（2026-10-14）

正式回归发现卷帘门的盘面推移目标未回填同名轮目标，已在BoardGame中同步PushedInto进度；规则版本纳入指纹，数值不变。普通终局四选一须冻结候选并保存领取状态；领取使用独立提交身份与相同绝对映像日志协议，防止重启/重开页面重复领奖，不创建新盘面。
