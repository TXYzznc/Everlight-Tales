## ADDED Requirements

### Requirement: 障碍设施逐项参数配置化
系统SHALL让 `Board/ObstacleTable` 承载障碍设施的逐项可调参数，使 O-003／O-005／O-007／O-008 的行为差异只靠改表即可调整，不需要改代码。覆盖 P2-002。

#### Scenario: 闸门初始开闭
- **WHEN** 关卡实例按 `ObstacleTable` 的 O-003 行放置联动闸门
- **THEN** 闸门初始开闭取自该行参数，初始关闭时阻挡进入

#### Scenario: 同根信号只切一次
- **WHEN** 同一根信号在连锁中多次到达同一闸门
- **THEN** 该根信号只切换一次开闭，后续新信号可再次切换

#### Scenario: 夹持座允许对象标签
- **WHEN** 关卡实例放置 O-005 夹持座并配置允许夹持标签
- **THEN** 只有匹配标签的实体可被锁定，其他实体不被夹持

#### Scenario: 支柱拆除附属隔板
- **WHEN** O-008 承压支柱耐久归零
- **THEN** 支柱被移除，并按该行参数移除预登记数量的附属隔板；参数为 0 时不产生额外塌落

#### Scenario: 未识别键报错
- **WHEN** 任一行 `ExtraData` 出现无法识别的键或非法值
- **THEN** 配置装载失败并抛出明确异常，不以默认值静默继续

### Requirement: 棋盘异常逐项参数配置化
系统SHALL让 `Board/AnomalyTable` 逐项承载 A-001~A-008 的真实参数，替换现有 8 行相同的占位值。覆盖 P2-003。

#### Scenario: 逐项参数生效
- **WHEN** 装载异常表
- **THEN** 每个异常类型的阈值、方向、额度、层数等参数来自各自行，不再共用同一组占位值

#### Scenario: 布局输入由关卡提供
- **WHEN** 关卡实例注册异常区域
- **THEN** 区域格集合、出口格与扩张格序列由关卡提供，异常表只提供类型参数

### Requirement: 回声区域与重绘帷幕行为
系统SHALL把 A-003 回声区域与 A-007 重绘帷幕从保留占位改为可运行类型，并保持既有 A-001／002／004／005／006／008 行为不变。覆盖 P2-003。

#### Scenario: 回声派生一次且不可再复制
- **WHEN** 区域内声音源发出一次根声音且剩余额度大于零
- **THEN** 传播完成后排入一次同端口同语义的派生声音并消耗一额度；该派生声音不再被任何回声区复制

#### Scenario: 额度跨拍保留与复位
- **WHEN** 额度耗尽后由复位端复位
- **THEN** 额度补至配置值；普通进入区域不会自动补满

#### Scenario: 重绘上限与轮转
- **WHEN** 一轮结束且帷幕内存在登记伪装载体
- **THEN** 按预登记顺序最多给配置数量的目标各加一层伪装，层数不超过配置上限，真人真实身份不被改写

#### Scenario: 类型改名不改变数值
- **WHEN** `AnomalyType` 的保留成员改为回声区域／重绘帷幕
- **THEN** 枚举数值与表内 `AnomalyKind` 保持不变，既有类型行为不回归

### Requirement: 怪谈专属挑战配置表
系统SHALL新增 `Board/ChallengeTable` 与 Data 层挑战配置／目录，使 C-001~C-015 具备可装载的元数据与关卡绑定，并使 C-001 红舞鞋按现有数值等价装配。覆盖 P1-021 口径。

#### Scenario: 装载 15 条挑战
- **WHEN** 装载挑战表
- **THEN** C-001~C-015 各有一条记录，包含案件键、挑战类型与规则编号

#### Scenario: C-001 等价装配
- **WHEN** 红舞鞋第一关进入准备与盘面
- **THEN** 挑战表提供 C-001 的关卡绑定与规则编号，三轮各三拍、30／100／170 分与六个导流格等既有数值保持不变

#### Scenario: 后置案不装配盘面
- **WHEN** C-002~C-015 尚未配置关卡键
- **THEN** 这些条目只作为元数据存在，不生成盘面装配，也不阻塞 C-001

### Requirement: 挑战投放覆盖
系统SHALL让 `Meta/StageReleaseTable` 覆盖 C-001~C-015，使用既有的挑战投放类型。覆盖 P1-021 口径。

#### Scenario: 挑战进入投放表
- **WHEN** 查询某一玩家阶段可投放内容
- **THEN** 对应阶段的 C-xxx 条目按投放表被列出，与既有零件／形态投放查询口径一致

### Requirement: 表头结构与源可重建
系统SHALL保持新增列与新表的表头结构符合框架生成约定，且 Excel 源可由工具重建。

#### Scenario: 结构校验通过
- **WHEN** 运行表头结构校验
- **THEN** 新列与新表的备注行满宽、字段与备注逐列对齐，校验无问题

#### Scenario: 往返一致
- **WHEN** 由 Excel 源重新生成 `.txt` 与 `.cs`
- **THEN** 生成物与提交内容一致，无多余 diff
