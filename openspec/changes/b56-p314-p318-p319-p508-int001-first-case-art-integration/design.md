## Context

用户2026-10-09四轮确认。原任务：P3-014、P3-018、P3-019、P5-008、INT-001。现有GF.UI页面、正式Sprite目录、RedShoeIntroService/InvestigationService/RedShoeService已有实现，但正式流程未连接；WorldSession的PlayerPrefs未保存案件/地点。

## Goals / Non-Goals

**Goals:** 首案地图入口→人物对话→调查→夜间准备/盘面→结算/回访可运行；三存档位兼容、隔离和防重；保留图片及Prefab GUID。

**Non-Goals:** 新依赖、新素材、音频、后续案件、数值校准、框架核心重构及真实移动端发布。

## Decisions

1. 沿用五层。Data提供首案台词/身份/步骤配置；Meta复用阶段与案件状态机；Board复用红鞋规则和三轮条件；UI只编排页面与显示。相较重建叙事系统或使用开发者演示入口，增量接线范围最小且玩家操作可验收。
2. DialoguePage用明确的输入数据与结束/取消回调承载现有DialogueGraph；选项清理和关闭取消绑定页面生命周期，不在已关闭页面继续推进剧情。相较把对话当Toast或继续使用禁用的DialoguePanel.Show，GF.UI可正确处理返回和分组。
3. 人物身份与台词文本分开；旁白不借用其他人物图片；首案盘面明确显示玩家与沈遥，普通维修隐藏未知来客。保持当前目录精确绑定与未知身份隐藏策略。
4. 首案阶段、案件和地图状态增量写入当前PlayerPrefs槽位。无字段的旧档使用安全默认值，不伪造案件已完成；删除存档同时删除新增键。相较切换到另一条JSON文件存档链，保留正式运行链兼容性。
5. 使用已有红舞鞋配置与规则，保留30/100/170分、三轮各三拍、4格耗时及现有回访奖励；移除首案流程对EnsureRedShoeResolved演示捷径的依赖。关闭重开只由正式进度推进，重复结算与回访为无操作。
6. Prefab通过Editor增量迁移修改，维护序列化引用和生成器接线，不手工改写YAML、不覆盖用户PNG或页面主布局。
7. 教学复用现有三段样张和正式BoardPage，通过真实拍击及结算解锁首案。同步TutorialComplete，并从已完成三段的旧档恢复标记，避免入口死锁。
8. 第四轮批准修正导流格为(0,-1)、(1,-2)、(1,-3)、(2,-4)、(2,-3)、(3,-3)。左右旋转接红鞋后续导向；两次合法机械臂、轮间真实奖励和九次拍击可达176分并封存。不改变三轮分数、拍数、耗时或导流数量；固定成功路线不代表随机奖励均可解。
9. 仅保存案件阶段和地点，当前运行链未保存逐拍盘面。Repairing恢复为AwaitingRepair，调查信息保留，重开本关初盘；不宣称恢复同次维修的中间局面。
10. 验收暴露70处既有TMP字体材质丢失引用，使用既有字体默认材质修复；盘面衬底置于场景图之前，开场覆盖层设置独立Canvas排序。测试辅助代码只在Editor编译，并在finally/OnDestroy恢复三槽PlayerPrefs备份。

## Risks / Trade-offs

- UI接线暴露旧模拟器/内容不一致 → 优先沿用运行规则，真实可玩性与分支测试分别记录，不伪称数值校准完成。
- 对话中关闭、异步打开失败或跨存档 → 捕获会话身份，完成与取消互斥，只有完整操作推进阶段。
- 校验过程中污染用户存档 → 运行验收保存/恢复所触及PlayerPrefs键，测试数据不覆盖用户槽位。
- 工作区已有Unity Skills文档/包/背景改动及纯度审计4项失败 → 不覆盖外部改动，分别报告既有失败和本批结果。
