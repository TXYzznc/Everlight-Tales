## Context

2026-10-08静态审计覆盖273张PNG和26个UI Prefab：UI153张（149共用＋4热点占位）、UI外61张正式、59张开发占位。UI仅62张具有直接引用或动态查询证据，91张没有实际使用证据。旧页面文档还混有独立Item、错误材料编号和通用节点模板。

既有b54通用行与b55携带/调查交互是已确认边界。四轮用户决定为功能图标优先、主图48＋徽标24＋状态文字、非阻塞短提示与操作弹窗分开、61张UI外正式图全部纳入规则。用户后续允许提出新增/淘汰资源，但新资源设计须在原界面文档下单独建文件夹。

## Goals / Non-Goals

**Goals:**

- 每一张现有图及待制作图都有唯一判定、语义、触发条件、挂点与回退。
- 为现有20页及6个Item补充可实施的资源与几何契约；保留统一行16类调用覆盖。
- 明确源图归一化、切片、动态目录与Editor/运行绑定的一致性。
- 独立交付新设计、资源增删建议与后续实施任务。

**Non-Goals:**

- 本轮不修改脚本、Prefab、meta、业务数据，不生成或删除PNG，不提交Git。
- 不改变内容投放、材料Key、奖励抽取、解锁条件、配装容量、调查完成和棋盘计算。
- 不新增独立资料台入口，不强制用完所有装饰，不重搭20页Canvas。

## Decisions

### 1. 语义目录与实际证据分离

新设计保存于 `Docs/GameDesign/11-美术规范/界面设计文档/资源接入与修订/`。`资源绑定规则.json`登记273张现存图和3张计划图，计划图没有GUID，登记不被认定为当前接入。状态/角色是显式语义，不再由Tab/Sub/按钮名字推断。

静态素材直接引用，动态变化通过序列化Sprite目录；材料用ID＋来源、对象用枚举/FormId、地点用placeId＋状态。弃用运行时目录扫描与中文显示名拼路径，避免语言和文件名变化影响绑定。

### 2. 通用行只扩展状态字段

沿用一个ListRowItem、64/96行高、容器隔离回收、详情/Action双回调。新增StatusIcon/StatusText/StatusColor及可选字段标志，独立于Icon/StateFrame/RightText。类型或对象48×48，状态24×24＋文字；收集状态框仍覆盖主图。Reset与Bind重置新字段，分类隐藏不清业务回调。

单主图＋状态文字方案改动较小，但用户选择有状态徽标的组合；不恢复旧业务行或多个Variant。Carry保持专用结构，目标144/172行高以满足48px对象图和形态按钮，承担可见条目密度下降的代价。

### 3. 状态与资格分开

持久选择、输入、业务状态分别绑定。地图锁定选择仍用known_locked建筑＋独立选择框；解锁选中才用selected建筑。事件/任务/案件按既有模型映射，图标不增加操作资格。

Archive异常纹样的来源行依据现有MaterialStack.Key显示，不修改存档与扣除逻辑；合计用generic图，避免用某来源图冒充全部。前五材料明确052～056；异常纹样057五来源图；图样058。

### 4. 短提示为项目全局表现组件

保留DialogView/GF操作弹窗边界。新增项目全局ToastHost，四种SHR-041、有限队列、去重、不挡射线；Loading仍阻挡操作并由原生命周期关闭。用户选择这种分离；全部弹窗和仅成功提示两种替代未采用。

### 5. 新增与淘汰

提出ICO-063增益、ICO-064机械臂次数、ICO-057-generic异常纹样三张128×128彩色单态图；待交付时有文字/分类回退。建议淘汰SHR-027-badge与SHR-047，两图先移除工具/目录/序列化引用，再全Assets依赖核对后删除。

ICO-009、两张缺已实现枚举的异常、SHR-032 warning/danger共5张预留；SHR-045可选；滚动条与真实计数角标6张按条件显示。59开发占位不作为正式覆盖目标。

### 6. 61张对象图保留原程序几何

零件/形态用于精确缩略图与实际装配盘面；障碍/异常/标记按原实体与区域绘制Image，不改变命中、物理或结算。预览与正式盘面共用解析与层次，未知图回退原EntityVisuals。

玩家/沈遥只用于精确人物身份，周衡缺图不借图。红舞鞋仅L-01已公开场景/档案。Reserved异常不按素材顺序猜配。

### 7. 增量几何与历史资料

本change `art/prefab-layout.md`定义新增/修改节点，`prefab-baseline.json`记录26个Prefab483节点的原四元组及hash。主壳既有Scaler与布局保留。旧文档不改写；新目录的冲突迁移清单明确优先级。

## Risks / Trade-offs

- [源图尺寸不齐、37张控件Border为零] → 先成族统一画布/轮廓，再校正切片；仅设Sliced不能通过验收。
- [24px徽标细节损失] → 状态文字必须同时存在；实测失败再按原编号简化重绘。
- [专用Carry行增高降低可见数] → 通用行保持64/96；候选通过ScrollRect/对象池承载，检验窄容器拖动。
- [新增字段造成池复用残留] → 丰富行→纯标题→另一业务行、分类隐藏/重开及回收单独验收。
- [新图尚未交付] →计划路径不登记GUID，按明确回退显示，不能声称已使用。
- [素材接入意外暴露未公开内容] →已知/已见/已装配条件取原业务，NotTriggered案件隐藏。
- [用户期间修改Prefab] →迁移先核对baseline hash，保留新布局，不覆盖其它工作。

## Migration Plan

语义目录/切片→通用行与五专用Item→地图/时间/准备→其余页面→Toast/Loading→对象/盘面/人物→引用/工具一致性→运行验收→淘汰资源零引用清理。逐阶段记录可审阅差异；失败回滚当前阶段，不清空业务数据、不改框架核心。

## Open Questions

本轮没有阻塞设计的产品选择。两张预留异常的业务映射、独立资料台入口、连续进度阈值等待后续实际业务设计；本轮明确不用，不将它们视为遗漏。新增/淘汰是可审阅建议，尚未制作/删除。
