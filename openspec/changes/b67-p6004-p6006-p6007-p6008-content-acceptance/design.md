# 首发内容验收与状态核对设计

## Context

P6-004/006/007/008，接续 b66。既有计划曾把G6标完成，但存档、视觉、人工试玩存在证据缺口，且用户明确暂缓音频、设备发布和纯度/生成一致性治理。任务工作簿是只读输入。

## Goals / Non-Goals

对本轮最终内容完成兼容、文案和清单验收，并准确同步开发文档。这里的内容冻结是本轮可验收范围基线，不是发布或整个G6通过。P6-005/009/010/012不自动纳入完成，十四案仍后置。

## Decisions

| 状态表达 | 优点 | 代价 | 选择 |
|---|---|---|---|
| 沿用工作簿“已完成” | 省维护 | 隐藏实际风险 | 不采用 |
| 任务来源＋批次证据＋暂缓项三方对照 | 反映实际可交付范围 | 需维护索引 | 推荐 |
| 重建/覆盖原工作簿 | 单表直观 | 违背只读约束和历史记录 | 不采用 |

### 最终存档/升级矩阵

对 b66最终配置和 b65资源运行：新档、旧世界档无尝试、有效尝试、主损备好、主备均坏、未知schema、配置指纹变化、三槽互切、删除/重建世代、选奖励中退出、事务写失败重试、Prepared日志中断、PlayerPrefs部分写入/已写但未清日志、全部结算恢复资料丢失。覆盖三教学零成本、红鞋和卷帘门真实结算，一天循环/补给刷新/跨日再加载。

期望沿D-324：有效日志优先完成确定结果且最多一次；坏尝试无罚重开保留世界；正常撤退按规则一次收费/扣时；彻底丢失日志不猜测补账。b60设施与异常恢复后必须与未中断路径状态等价。升级样本使用受控Editor测试副本，不覆盖用户真实档。无法无损迁移时明确提示重开轮/尝试范围，不宣称原地恢复。

### 文案与首发清单

抽取实际首发引用的教学、事件、人物对话、维修、失败/撤退/结算、恢复错误、Loading和空状态文本。核对术语、数值和行为匹配、中文标点、占位符、超长文本及重复提示；只改确证问题，不重写全部剧情。文本说明不得承诺当前不存在的玩法/语音/设备能力。

冻结条目含稳定键、入口、前置条件、配置版本、资源状态、验收证据、后置理由。覆盖首发切片、已投放普通事件、T-G试机与回访；P005～020及F4已完成能力按实际投放列入，不能重新开“补实现”任务。C002～015和十四案明确不可玩/后置；资源存在不等于已解锁。

### 状态核对和旧change处理

更新分批开发执行计划、路线总览、设计状态与待完善设计，补原任务→新批次→证据→未完成边界。工作簿不修改；提供状态差异建议表，让读者知道“已完成”缓存不能作为本轮验收证据。纠正总数统计不一致时仅说明口径，不擅自写回工作簿。

b57行为/装配子项通过后引用b60/b61证据；全量生成漂移仍未完成。旧 art-visual-refresh/design-board-environment-assets/design-ui-resource-binding-rules 的本轮子项只在证据匹配时关闭，其余14案/音频/设备子项保留。OpenSpec规范同步/归档仅针对真正完成且范围清楚的change，不为获得全绿删掉遗留。

## Risks / Trade-offs

- 旧状态被误当本轮全完成 → 报告开头明确“内容部分验收，G6未关闭”。
- 文案修补改变规则 → 规则以已批准设计/最终配置为准；发现新规则冲突列缺陷，不悄悄重定数值。
- 版本测试误动真实玩家数据 → 只使用隔离测试槽/路径和可恢复副本。

## Migration Plan

冻结候选版本后运行矩阵、修阻断缺陷、校对文案，再冻结清单并对照所有批次证据。文件变动后仅复测受影响路径。输出 verification.md、release-content-manifest.md 和 status-reconciliation.md；暂缓项列责任范围和恢复条件，不给未经验证的发布结论。文档可回退，运行配置回退遵守b58版本策略。
