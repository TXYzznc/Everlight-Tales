## Context

用户确认统一 16 类横向列表行，采用单预制体与通用显示脚本，使用 SHR-005 图片；单行高 64，双行高 96，隐藏节点释放布局空间。当前形态和材料条目存在重复结构，Journal/Guest 有独立操作按钮，Codex 有可选编号与状态框。

## Goals / Non-Goals

- 目标：一个资源承载全部纳入范围的横向列表行；修改该资源即可维护统一视觉结构。
- 目标：每次 Bind 都明确恢复全部显示和交互状态，保持页面业务行为。
- 目标：多个容器共享一模板后，清理/刷新互不影响。
- 非目标：将特殊卡片、六边形宿主、场景热点和携带槽位强行改为列表行。

## Decisions

### 1. 单预制体与通用显示组件

| 候选 | 优点 | 成本 | 结论 |
|---|---|---|---|
| 单预制体＋通用组件＋页面参数 | 统一资源、布局、状态与调用契约，真正删除重复资产 | 需要逐页面转换参数和改造回收 | 用户确认采用 |
| 单预制体＋专用适配脚本 | 调用迁移较小，各业务独立 | 保留更多显示类，契约仍容易分散 | 不采用 |
| 基础预制体＋多个 Variant | 单个业务可独立调整 | 仍需维护多份资源与覆盖关系，违背减少重复资产目标 | 不采用 |

正式资源拟定为 `Assets/Game/Prefabs/UI/Item/ListRowItem.prefab`。根对象只挂一个通用 `UIItemBase` 派生组件，不同时附加所有旧 Item 组件。页面不再通过旧业务 Item 类型取组件。

### 2. 显式数据参数与节点契约

拟定绑定参数 `ListRowData`，包含：

- `Title`：必选主文本。
- `Detail`：副文本。现有 Source/Description/Meta 由页面转为这个字段，不保留重复文本节点。
- `Id`：可选左侧编号。
- `Icon`、`StateFrame`：可选图标与覆盖状态框。可见性由显式字段和非空图片共同决定，缺失图片不显示白方块。
- `RightText`：可选右侧状态或数值，替代互不同时使用的 State/Value 节点。
- `ActionText`：可选独立操作按钮文字。
- 字段显隐集合、文字颜色、行禁用状态、持久选中状态、操作按钮独立禁用状态。
- `OnClick` 与 `OnAction`：详情与执行操作分别注入；通用组件不查询世界数据、不决定页面跳转或奖励。

全部内部引用通过预制体序列化字段绑定。Editor 可使用局部路径辅助绑定；运行时不靠名字找节点。通用行始终保留完整的可选结构，Bind 控制显隐，不再按业务删除子节点。

### 3. 两档布局

结构采用左侧可选编号、可选图标、弹性文本列、可选右侧文本和可选操作按钮。副文本启用且非空时高 96，否则高 64。标题始终可见；隐藏字段不占宽度，文本列获取剩余宽度。

主、副文本单行省略显示；详情交互继续提供完整文案。内容列的宽度随容器变化，不能沿用针对 1080 宽度的固定主文本宽度。操作按钮与行按钮独立接收点击；装饰图片和文字不抢占无用射线。

根按钮统一 `SpriteSwap`，normal/hover/selected 使用 SHR-005 对应图片；pressed 复用 selected，disabled 复用 normal，禁用文字通过参数颜色显示。持久选中是显示数据的一部分，不能与瞬时 hover/pressed 混淆。

### 4. 每次绑定和真正回收时重置

每次 Bind 更新全部文本、图片、显隐、布局、颜色、禁用状态、选中状态与回调；隐藏字段的旧数据也应清空。真正回收时释放回调及业务对象引用。

不能通过 `OnDisable` 清除有效回调：关闭分类视图也会触发 OnDisable，重新打开时可能不重新 Bind。回收清理应接入 ItemObject 的池生命周期，并验证新实例注册和复用均经过正确状态初始化。

### 5. 按容器隔离回收

现有池名由页面实例和模板实例构成，类型由泛型决定。Archive 的五个模板目前天然分池；合并为单模板单类型后，调用 `UnspawnAllChildItem` 将回收同页面全部行。

新增容器级行集合（拟定 `ListRowCollection`），每个显示容器记录自己生成的 `ListRowItemObject`，清理时仅逐实例回收自身持有的行。若现有公开 API 不足，在 UIFormBase 通用扩展中公开已有逐实例回收方法，不修改池名与旧业务池。

需专门处理页面关闭后框架已全量回收，而容器集合仍保存引用的情形：清理持有记录与池状态必须一致，禁止重复回收或回收已经归属其他容器的实例。以明确的持有代次/池状态/页面生命周期为实现依据，不只用 activeInHierarchy 判断池归属。

### 6. 逐页面迁移与工具同步

先迁移 Archive 的五个列表，验证同模板多容器，再逐个迁移 Codex、Workbench 三个列表行、Guest、Journal、Map、Board 对话选项、Settlement 奖励选项。

WorkbenchHostItem 保持六边形及原功能；其仍依赖的 WorkbenchItem/WorkbenchItemObject 不能因迁移三个列表行而删除。Guest/Journal 保留行详情和独立 Action。地图事件、对话和奖励行保留各自原回调。

生成器只生成新的通用列表行及仍保留的特殊 Item；显式重建页面的工具按新契约写入引用，当前页面迁移仅修改必要的模板与组件引用，保留用户维护的容器布局。

最后全量检索旧资源 GUID、资源路径、Item 类型、字段、注册表和绑定菜单。逐资源确认没有引用后通过 AssetDatabase 删除旧 Prefab 与 meta；无用途显示脚本同样在编译与扫描确认后删除。

## Risks / Trade-offs

- 多容器误回收是核心正确性风险，必须在批量删除旧资产前验证。
- 统一行高会改变屏幕可见条目数量，这是用户确认的布局调整；容器滚动与遮罩仍需核对。
- 通用组件参数过多可形成难维护的组合；以明确字段集合和两个点击语义约束，不支持任意节点名或随意层级配置。
- 从不同用途行复用时可能带入旧图标、Action 或监听；需要跨用途复用验收。
- 删除旧资源后恢复成本较高；按页面迁移保存可审阅差异，完成引用与日志验收后才清理，无 Git 历史重写或推送。

## Validation

- 静态扫描：16 类迁移全覆盖，5 个特殊 Item 未误改，旧 GUID/路径/类型零遗留（明确保留宿主类型除外）。
- 组件检查：单正式模板，序列化引用完整、SHR-005 状态图正确，副文本开关对应 64/96 高。
- 运行日志：逐页面数据行数、各容器活跃行数、切换分类、选中状态、根点击与 Action 回调。
- 复用验证：带 Id/Icon/Action 的行回收后，用纯标题参数绑定，不能留下旧节点、数据或监听。
- 回收验证：Archive 单分类重建不影响其他四类；页面关闭重开不发生重复回收或错容器归属。
- 不截图；不将静态检查结果写成已经完成运行时验收。
