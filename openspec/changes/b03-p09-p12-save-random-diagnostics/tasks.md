# 实现任务（b03 存档＋随机＋配置字段＋诊断）

覆盖原始任务：P0-009、P0-010、P0-011、P0-012。

依赖说明：P0-009、P0-010、P0-012 的前置均为 P0-002（b01 已完成），可随时开工；**P0-011 的前置是 P0-005（b02）**，若 b02 未落地，P0-011 只能登记字段草案而无法对照实际表列。

## 1. 存档服务骨架（P0-009）

- [ ] 1.1 定义存档三段信封结构（版本号、写入时间、载荷）与两个存档的逻辑名（世界／尝试）
- [ ] 1.2 落盘位置与序列化沿用框架约定：`Application.persistentDataPath` 下存档目录 + 框架既有 JSON 工具
- [ ] 1.3 实现世界存档读写接口：写入、读取、读取失败的可辨识结果
- [ ] 1.4 实现尝试存档读写接口，与世界存档**相互独立**（一方损坏不影响另一方）
- [ ] 1.5 版本号策略：独立版本号；版本高于支持范围时拒绝并报可辨识错误，不静默按当前格式解析
- [ ] 1.6 区分"损坏"与"从未存在过存档"两种失败结果
- [ ] 1.7 读写时机接口：由调用方在明确时机触发，不做隐式每帧写盘
- [ ] 1.8 确认运行时存档产物不进入版本库（受控路径之外或已忽略）

## 2. 可配置随机源（P0-010）

- [ ] 2.1 定义随机服务接口：整数、浮点、重置种子、消费计数
- [ ] 2.2 实现固定种子来源（默认）与"固定种子＋随机混合"来源，来源可插拔
- [ ] 2.3 消费计数在服务内部集中记账，只增不减，重置时归零
- [ ] 2.4 将随机服务放在 **`Board`**（零引擎依赖），公开接口不出现引擎类型
- [ ] 2.5 静态扫描护栏：业务代码不出现对引擎全局随机的直接调用
- [ ] 2.6 断言：同种子同序列、不同种子不同序列、计数等于请求次数、重置归零

## 3. 配置表字段草案登记（P0-011）

- [ ] 3.1 在既有设计参考文档体系内登记事件模板、关卡、零件、Buff 四类表的字段草案（不新建权威副本）
- [ ] 3.2 每类字段标注最终归属任务 ID，**关卡类明确标注归属 `P1-021` 关卡盘面配置表**
- [ ] 3.3 文档开头声明"草案，非冻结，最终以归属任务为准"
- [ ] 3.4 若 b02 已落地，对照实际表列核对草案与已建骨架的一致性

## 4. 诊断与盘面演算日志（P0-012）

- [ ] 4.1 新增业务诊断场景，接入框架既有诊断场景／报告模式，产出表加载状态与随机消费计数摘要
- [ ] 4.2 演算日志开关置于 `Board`（零引擎），关闭时零开销（不拼接字符串、不产生每步分配）
- [ ] 4.3 开启时记录种子、初始盘面、每步动作与该步随机消费数
- [ ] 4.4 提供按记录重放的入口，使"同一记录重放出同一结果"可被断言
- [ ] 4.5 断言：关闭时无记录、开启时记录完整、重放结果与记录一致
